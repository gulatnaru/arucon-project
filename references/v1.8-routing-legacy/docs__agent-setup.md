# 적용 안내 — 프로젝트 안에서만

## 제공 범위

이 ZIP은 **교체·병합용 문서와 Codex 설정**이다. 사용자 저장소/전역 설정을 이미 바꾼 것이 아니다. 기존 SRS·루트 AGENTS·숨김 `.codex`/`.agents` 폴더가 있다면 덮어쓰기 전에 diff를 검토한다. 회사 작업공간/홈 설정으로 복사하지 않는다.

권장 경로: 루트 `AGENTS.md`; 제품 자료 `docs/`; 역할 `.codex/agents/`; 스킬 `.agents/skills/`; 브리핑 `templates/`; 검사 `validation/`. 과거 `docs/AGENTS.md`의 “루트로 옮기라”는 안내는 제거하고 문서 작업용 보충 지침으로 바꿨다.

## 첫 적용

1. 현재 Git 상태와 사용자 변경을 확인하고 별도 변경 묶음으로 파일별 병합한다. 제공 diff는 검토용이며 자동 패치/초기화 스크립트가 아니다.
2. `.codex/config.toml`이 이미 있으면 더 엄격한 기존 sandbox/승인/조직 정책을 보존한다. 권한 프로필을 사용하는 환경에서 sandbox 키와 병용하지 않는다. 어떤 설정이 유효한지 호스트에서 먼저 확인한다.
3. Codex의 실제 버전과 프로젝트 신뢰/설정 로딩을 확인한다. `codex --version`은 CLI가 있는 경우만 사용한다. 앱/IDE는 그 환경에서 버전을 기록한다. 이 작업을 위해 전역 설정을 임의 변경하지 않는다.
4. 정적 검사를 실행한 뒤, 비밀·실데이터·외부 쓰기 없는 작은 작업으로 역할 세 개와 스킬 세 개의 인식을 확인한다. 설정 인식·권한 집행·발동률은 각각 실제 호스트에서 확인한다.
5. 작업 시작은 `templates/orchestrator-task.md` 또는 `docs/codex-handoff.md`의 지시문을 사용한다. 첫 작업에서 설치/권한 확인만 하고 멈추라는 뜻이 아니라, 승인된 로컬 결과물까지 진행한다.

## 제공 TOML의 의미

`.codex/config.toml`은 `approval_policy = "on-request"`, `sandbox_mode = "workspace-write"`, 샌드박스 outbound network OFF, 자식 스레드 최대2를 제안 기본값으로 담는다. 기존 보안 정책보다 낮추지 않는다. TOML 파일은 샌드박스 외부의 모든 MCP 쓰기를 자동 차단하는 정책이 아니다.

탐색/검토는 `read-only`, 구현은 `workspace-write`다. 검토자가 출력 파일을 쓸 수 없으면 총괄에게 증거 생성을 넘긴다. 모든 역할은 부모/호스트의 더 강한 제한을 따라야 한다.

**모델과 추론 강도를 고정하지 않았다.** 부모/기본 설정을 상속할 수 있으므로 자동으로 저비용 모델을 선택하는 패키지가 아니다. 원하는 모델은 계정에서 실제 지원되는 정확한 ID를 확인한 뒤 역할 파일의 `model`과 호환되는 `model_reasoning_effort`에 설정한다. 별칭만 보고 모델 ID를 추정하지 않는다. 역할별 배정값·실제 실행 모델·비용 측정은 팀이 기록한다.

`.codex/agents/` 탐색 방식은 공식 현재 문서 기준이다. 구형 환경에서 안 읽히면 설정 지원을 확인하고 단독 작업으로 진행한다. 미지원 키를 무시한 채 보호가 작동한다고 말하지 않는다. 기본 내장 역할을 덮어쓰지 않도록 `arucon_` 이름을 썼다.

## 스킬의 적용

`arucon-game-verification`과 `arucon-visual-verification`은 좁은 설명으로 자동 선택을 허용한다. Figma 외부 쓰기 스킬은 `policy.allow_implicit_invocation: false`다. 사용자가 Figma 반영을 명시한 작업에서 총괄이 `$arucon-figma-handoff`를 브리핑에 넣는다. 명시적 호출도 새로운 외부 권한을 만들어주지는 않는다.

역할별 `skills.config` 필터는 현재 스킬이 세 개뿐이므로 기본 파일에 넣지 않았다. 추후 실제 오발동이나 컨텍스트 과부하가 확인되면 공식 문법과 실제 설치 절대 경로로 해당 역할에만 비활성화 항목을 추가한다. 존재하지 않는 `/Users/me/...` 경로를 복사하지 않는다.

## 필요한 환경과 확인 한계

문서 정적 검사: Python 3.11 이상과 PyYAML 6.x. Codex 실제 로드/위임 검증은 이 검사와 별개다. 기존 v3의 테스트/영상 코드에는 환경 의존 경로가 있으므로 [검증 정책](validation-policy.md)을 따른다.

현재 사용자 전역 파일과 실제 Codex 설치는 이 작업에서 접근하지 않았다. 그 파일들이 이 문서와 충돌하지 않는다고 보증하지 않는다. 전역 파일 감사를 별도로 요청하면 접근 가능한 범위에서 검토한다. Figma 원격 편집·모델 호출 발동률 실험도 이번 납품에 포함되지 않는다.
