# 아루콘 — AI 개발 운영 v1.7

2026-09-17 · ENG-01 · 제품 요건 개정이 아닌 개발 방식 개정

## 1. 역할과 기준

공통 지침은 모델에 관계없이 필요한 사실·불변 조건·허용 범위·완료 기준이다. 역할별 수행 절차는 TOML에, 이번 결과물은 브리핑에 둔다. 모델의 능력을 이유로 제품 경계·권한을 약화하지 않는다. 공식 설정 문법과 이번 설계 판단은 [근거 문서](agent-tooling-sources.md)에서 구분한다.

| 역할 | 파일/위치 | 책임 | 범위 |
|---|---|---|---|
| 총괄 | 부모 세션 + `templates/orchestrator-task.md` | 승인 해석·분할·통합·최종 보고 | 부모 권한과 이번 승인 범위 안에서 진행 |
| 탐색 | `.codex/agents/arucon_explorer.toml` | 실제 호출 경로·관련 FR/테스트 찾기 | read-only, 근거와 위치를 반환 |
| 구현 | `.codex/agents/arucon_worker.toml` | 배정 파일 수정·관련 검증·범위 안 실패 수정 | workspace-write, 외부 쓰기 위임 없음 |
| 검토 | `.codex/agents/arucon_reviewer.toml` | 기능 회귀·증거·시각 기준 검토 | read-only, 제품 코드 수정 없음 |

총괄 역할을 전역 `~/.codex/AGENTS.md`에 넣지 않는다. 전역은 다른 저장소와 자식에게도 영향을 줄 수 있다. 프로젝트 규칙은 이 저장소에만 둔다. 다른 에이전트 도구에서 같은 설정 파일이 자동 적용된다고 가정하지 않는다.

## 2. 작업 배정

작은 변경은 단독 처리한다. 탐색량이 크거나 서로 독립된 검토가 이익을 낼 때 위임한다. 파일 수만으로 위임하지 않는다. 동일 파일 동시 작성자는 하나로 제한한다. 각 브리핑에 다음을 기록한다.

| 요소 | 필요한 내용 |
|---|---|
| 결과 | 산출물과 관찰 가능한 완료 조건 |
| 제약 | 관련 FR/DEC, 허용 파일, 보호 파일, 제품·권한 경계 |
| 검증 | 실제 존재하는 명령, cwd/환경, 증거, 필수 검사 |
| 멈출 지점 | 미정 제품 선택, 외부 승인 범위 변경, 범위 밖 실패 |

읽기 결과는 함수/파일/FR 위치와 짧은 근거를 반환한다. 긴 문서·로그를 모든 자식에게 다시 복사하지 않는다. 전체 기록·원본 증거는 필요할 때 열 수 있게 경로로 남긴다. 파일이 없거나 볼 수 없으면 없거나 미확인이라고 보고한다.

## 3. 진행·중단

허용된 로컬 수정→검증→관련 실패 수정은 중간 검토를 기다리지 않고 이어간다. 새 제품 정책이나 승인되지 않은 수치를 스스로 결정하지 않는다. 막힌 부분과 독립인 작업만 진행한다. 저장소 전체를 다시 설계하거나 다른 단계로 넘어가는 권한으로 확대하지 않는다.

검토 담당은 읽기만 한다. 브라우저 캡처·테스트가 쓰기 파일을 요구하면 총괄/허용된 실행자가 격리된 테스트 복사본에서 만들고 검토자가 증거를 읽는다. “테스트니까”라는 이유로 읽기 전용을 workspace-write로 바꾸지 않는다. 어떤 역할도 테스트 삭제·기준 완화로 성공을 만들지 않는다.

범위 밖 실패는 최초 실패·재현 조건·관련성을 기록한다. 필요한 추가 변경을 제안하되 승인되지 않은 파일을 조용히 고치지 않는다. 실패 수정은 이번 변경이 유발했고 허용 범위 안일 때 수행한다.

## 4. 권한은 모델과 무관하다

| 작업 | 정책 |
|---|---|
| 프로젝트 내부 읽기·관련 검색 | 가능. 비밀을 열람·출력하는 일반 권한이 아님 |
| 배정 코드 수정·합성 fixture·로컬 검사 | 기존 허용 범위 안에서 반복 승인 없이 수행 |
| 의존성 설치/다운로드 | 필요한 파일·네트워크·실행 영향과 실제 환경 정책을 확인. 작업과 무관한 설치 없음 |
| Figma/외부 파일 쓰기 | 이번 요청에 특정된 계정·파일·행위만 허용. 공유 확대·회사 계정 대체 없음 |
| 운영 배포·실결제·실건강정보 처리·파괴적 삭제 | 별도 명시적 승인과 해당 운영 검증 필요 |
| Git commit/push/merge | 각각 명시적 허용이 있을 때만. 사용자 미커밋 작업과 이력을 보존 |

샌드박스는 로컬 실행 경계이며, 연결된 MCP/플러그인의 외부 권한을 모두 제한하는 장치가 아니다. 실제 활성 도구와 자격 증명은 실행 호스트에서 점검한다. 읽기 역할에 외부 쓰기 도구를 노출하지 않는 구성을 우선하고 불가능하면 그 한계를 기록한다. 스킬 숨김이나 자동 호출 OFF만으로 보안이 보장된다고 말하지 않는다.

거부·한도·네트워크 실패를 다른 계정·비밀 토큰·비인가 API로 우회하지 않는다. 승인된 경로의 재시도도 부분 성공 여부를 먼저 확인하고 동일 외부 객체를 중복 생성하지 않는다.

## 5. Figma의 완료 단계

`접근 확인 → 대상 확인 → 편집 요청 → 생성/변경 ID 확보 → 하위 노드 재조회 → 렌더 검증`을 구분한다. 사용자 승인 범위와 실제 확인한 계정이 다르면 편집 전 멈춘다. 기존 파일은 새로 만들기보다 지정 파일 안에서 편집한다.

파일 URL 생성·업로드 URL 발급·로컬 시안 생성은 원격 반영 완료가 아니다. 쓰기는 성공했지만 재조회/렌더가 실패했다면 **반영됨·검증 미완료**로 보고하고 무작정 반복 쓰지 않는다. 하위 노드를 보지 못했으면 파일이 비었다고 단정하지 않는다. Figma의 래스터 캡처·편집 가능한 UI·게임 실행 코드·최종 리깅 파일은 별개다.

## 6. 성격과 아트의 검증

기능 테스트와 별개로 같은 화면 크기에서 변경 전후를 비교한다. 작은 캐릭터, 넓은 이동 영역, 조용한 아이의 반쯤 감긴 눈·작은 일자 입, 접촉 후 안정되는 말캉한 반응을 확인한다. 모션 변경에는 전·중·후 영상이 필요하다. 정지 화면만으로 보행이나 탄성이 자연스럽다고 승인하지 않는다.

시각 검토의 결론은 구체적인 관찰과 재현 정보다. AI 검토 결과는 사용자 아트 승인이나 실제 기기 성능 검증을 대신하지 않는다. [검증 정책](validation-policy.md)의 증거 범위를 적용한다.

## 7. 모델·비용 운영

역할 파일에는 특정 모델 ID를 넣지 않았다. 실행 호스트의 상속/기본값에 따라 선택되므로 자동 저비용 모델 배치가 아니다. 실제 계정에서 사용 가능한 모델과 추론 강도를 확인한 뒤 역할별로 기록한다. 검증 전 모델별 가격·문제 발생률·성능 보장을 복사하지 않는다.

초기 설정은 동시에 열린 자식 스레드 최대 2개다. 이것은 항상 두 명을 띄우라는 뜻이 아니다. 비용·정확도·지연을 작은 대표 작업으로 비교하고 필요할 때만 조정한다. 서브에이전트가 없으면 동일 완료 기준으로 단독 처리한다.

## 8. 결과 보고

`templates/completion-report.md`를 사용한다. 기능 검증, 시각 검증, 사용자 승인, 환경 제약을 분리한다. 원문 전체 로그 대신 명령/exit code/실패 요약/로그 경로를 보고한다. 실제 본 증거만 근거로 쓴다. 자식의 “완료” 문구만으로 총괄 완료를 선언하지 않는다.

현재 묶음은 실행 설정·지침의 파일 납품이다. 실제 사용자 Codex 환경에 적용·위임·스킬 발동률 검증이 이루어진 상태는 아니다.
