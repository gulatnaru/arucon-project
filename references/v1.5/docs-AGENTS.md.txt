# AGENTS.md — Arucon repository instructions

이 파일은 아루콘 개발 저장소 루트에 둔다. 아래 지침은 코딩 에이전트의 작업 방식이며, 제품 요구사항 자체는 `arucon-SRS.md`를 따른다.

## 1. 시작 전에 읽을 것

1. `arucon-SRS.md` 전체, 특히 0장·13장·현재 단계 FR.
2. `decisions.md`의 현재 승인 상태. v1.4 DEC-19~23 및 v1.5 DEC-27~29는 명시한 방향만 승인되었다. DEC-30은 PROPOSED, DEC-31은 OPEN이다. 이전 미정 결정·신규 수치까지 승인된 것은 아니다. 최초 PROTO 범위는 역사 문서 prototype-spec.md를 참고하고, 최신 표시 방향은 SRS FR-10.1과 cross-device-design.md를 따른다. 실제 시제품별 실행 계약·QA는 별도다.
3. `arucon-agent-prompts.md`의 맡은 단계와 `acceptance-tests.md`의 관련 테스트.
4. 존재하면 승인된 `architecture.md`, 실제 코드·패키지·실행 명령·현재 Git 변경 사항.

문서나 코드가 보이지 않으면 없는 사실을 추정하지 말고 누락을 보고한다. 서로 충돌하면 FR/DEC와 상충 문구를 기록하고 해당 부분을 결정 대기로 둔다. 단계 프롬프트로 SRS를 덮어쓰지 않는다.

## 2. 변경할 수 없는 핵심 경계

- MVP의 EXP 원천은 직접 급식 또는 사용자가 동의한 식탁 자동급식의 실제 섭취뿐이다. 부재 중에는 승인된 조건과 동면 경계 내 자동급식만 허용한다. 걸음·수면·위젯·자동 동기화로 EXP를 직접 지급하지 않는다.
- 실제 걷기·달리기는 펫 체력을 줄이지 않는다. 감소 원인은 시간·승인된 적극적 놀이·소화뿐이다. 가벼운 쓰다듬기·인사·관찰에는 자원 비용이 없다.
- 청결은 기분과 기운 없음에 영향을 주며 체력을 직접 줄이지 않는다.
- 기운 없음의 발생 원인은 청결 장기 방치 하나다. 약 없이 자연 회복할 수 있어야 한다.
- 체력 0 자체는 차단 사유가 아니다. 깨어 있고 공통 배고픔/재고 조건을 충족하면 두 급식 모드 모두 섭취할 수 있다. 저체력을 행동 차단으로 바꾸지 않는다.
- 수면 0점은 원문 커브 0.7, 수면 데이터 없음은 중립 1.0이다. 미구현 scorer·API 오류를 0점으로 변환하지 않는다.
- 상한 때문에 기존 먹이를 빼앗지 않는다. 사망·영구 능력치 손실·비난 문구를 만들지 않는다.
- 효율·약은 활동으로 번 코인 전용이다. 현금→코인·효율 번들 등 우회 경로도 만들지 않는다.
- 원본 수면·오디오·원시 헬스·GPS 데이터를 서버, outbox, 분석 SDK, 크래시 첨부, 디버그 로그로 보내지 않는다.
- P2/P3 기능·테이블·API를 선행 구현하지 않는다. EXT-PC/HOME/WALLPAPER/SHARED는 독립 작업으로 배정될 때만 해당 승인 범위를 구현한다. 모바일 MVP에 확장 구현을 몰래 끼워 넣지 않는다.
- 캐릭터 아트는 승인된 별도 자료가 없으면 플레이스홀더다. 논리 외형 분기가 미정이면 가짜 규칙을 실제 펫에 확정하지 않는다.

## 3. 미정과 제안의 처리

`PROPOSED`는 승인된 기본값이 아니다. `OPEN`, `PROPOSED`, 또는 미승인 세부 값이 필요한 기능을 임의로 완성하지 않는다. 다음을 보고한다.

```text
결정 ID / 관련 FR:
막히는 동작:
확정된 부분에서 가능한 작업:
필요한 선택·값·검증 예시:
```

합성 fixture·타입·인터페이스·명시적 not_configured 반환은 허용한다. 운영 데이터와 섞지 말고 테스트용임을 표시한다. 미구현 adapter를 정상 데이터 없음으로 위장하지 않는다. 승인되지 않은 규칙이 없는 것처럼 기본값을 채워 프로덕션 빌드를 통과시키지 않는다. 미정 기능을 숨기거나 요구사항을 삭제해 완료로 만들지 않는다.

에이전트는 제품 결정을 스스로 APPROVED로 바꾸지 않는다. 사용자의 명시적 승인이 있는 범위만 SRS·결정기록·테스트·config에 함께 반영한다.

## 4. 설계·구현·테스트 규칙

도메인은 시계·난수·IO와 분리한다. `now`, config 버전, 이미 선택된 랜덤 결과를 입력받는다. 순수 엔진의 결과 저장·중복 명령 처리·원자적 트랜잭션은 애플리케이션 서비스와 저장소의 책임이다. UI/위젯은 도메인 값을 직접 변경하지 않는다.

모든 게임 밸런스 값은 승인된 단일 config 소스에서 읽는다. P2/P3 참고 값은 MVP 실행 경로와 분리한다. 라이브러리 버전·명령어는 실제 저장소와 공식 문서를 확인한다. 설치·빌드하지 않은 환경에서 ‘빌드 성공’이라고 쓰지 않는다.

행동 명령과 활동 데이터는 각각 중복 방지가 필요하다. 저장 실패·앱 종료·재전송·시간 경계·권한 철회·마이그레이션 실패를 정상 경로와 함께 테스트한다. 재고·EXP·원장·outbox의 부분 저장은 금지한다. 시간을 나누어 계산해도 같은 결과가 나오도록 잔여 정밀도를 보존한다.

PC·위젯·배경화면의 갱신/시계/교감은 경제 명령이 아니다. 게임 숫자를 로컬 렌더에서 진척시켜 중복 성장시키지 않는다. 개인정보·구매 정보·토큰은 합성 fixture로 대체한다. 실제 보호자 동의·현금 결제·배포·클라우드 변경은 명시적 승인과 필요한 검증 없이 실행하지 않는다. 개발 환경 mock을 출시 경로로 연결하지 않는다.

## 5. 작업 범위와 Git

기본은 한 세션에 배정된 한 단계다. 사용자가 묶음으로 요청한 이번 문서 개정+PROTO 제작은 승인된 한 작업 묶음이다. 이를 운영 MVP 전체 구현 허용으로 확대하지 않는다. 단계가 끝나면 별도 QA를 거친다. QA는 검증 보완 수단이며 별도 세션 자체가 정확성을 보장하지 않는다.

작업 시작 시 `git status`와 현재 브랜치를 확인한다. 사용자 작업을 덮어쓰거나 관련 없는 파일을 정리하지 않는다. 작업 브랜치는 `feature/<단계>-<설명>`을 사용하며, 브랜치 변경이 기존 변경을 훼손할 수 있으면 먼저 그 상황을 보고한다.

**기본: 에이전트가 변경·검증 보고, 사람이 검토 후 커밋·머지.** 원문의 ‘사람 커밋’ 규칙을 기준으로 통일했다. 사용자가 해당 세션에 명시적으로 커밋을 허용한 경우에만 기능별 커밋과 해시를 남긴다. 자동 push, main 직접 커밋·머지, 강제 push, 이력 삭제, 파괴적 초기화는 하지 않는다. 밸런스 변경은 분리하여 추적한다.

## 6. 완료 보고

아래 순서로 보고한다.

1. 맡은 단계·FR·적용한 승인 DEC·실제 변경 파일과 요약.
2. 실행한 명령·환경·실제 결과. 실패와 미실행은 구분한다.
3. 수용 기준 판정: **충족 / 미충족 / 결정 대기 / 해당 단계 범위 밖 / 확인 불가** 및 근거.
4. 남은 결함·제품 결정·외부 계정/기기/정책 의존·다음 단계 차단 항목.
5. Git 상태. 커밋하지 않았으면 그대로 명시하고 해시를 만들지 않는다.

테스트 파일을 작성했지만 실행하지 않았다면 ‘작성 완료·실행 확인 불가’다. fixture 통과는 실기기·실결제·운영 동의 완료가 아니다. 실제 코드를 확인하지 않고 요구사항이 충족됐다고 말하지 않는다.

## 7. QA 모드

QA 요청에서는 코드를 고치지 않는다. SRS·승인 DEC·코드·실행 결과를 근거로 문제를 보고한다. 배정 단계 밖의 미래 기능은 범위 밖으로 표시하되 최종 MVP 완료로 누락시키지 않는다. 요구사항과 기대값이 충돌하면 테스트를 요구사항보다 우선하지 말고 불일치를 보고한다.

보고서에는 재현 단계, 기대값·실제값, 파일/위치, 영향 FR/AT ID, 실행 환경과 증거를 넣는다. 에이전트가 자신의 구현을 통과시키기 위해 테스트를 삭제·완화하거나 명세를 바꾸지 않는다.

## 8. v1.4 생활 중심 금지·구현 경계

- 기본 화장실에 고장/소모품/청소 숙제를 추가하지 않는다. 설치 후 청결 원인 발병이 사라지는 것은 의도된 효과다.
- 식탁은 별도 opt-in 후 허용한 보관함 먹이를 사용한다. 식탁으로 매번 옮기기·몰래 구매·수동급식 효율 우대 금지.
- 성격은 시각 행동을 바꾸되 경제 효과를 바꾸지 않는다. 사용자 건강·MBTI·자동화 사용으로 성격을 판정하지 않는다.
- 16성향과 1차4종은 확장/아트 방향이다. 이번 PROTO는 같은 외형의 성격2종이며 진화 게임 완성으로 보고하지 않는다.
- prototype/src/config.js의 값은 합성 데모 전용이다. 운영 config로 가져오지 않는다.
- 프로토타입 테스트 결과는 prototype/QA-REPORT.md에, 운영 미실행 수용 기준은 docs/acceptance-tests.md에 분리한다.


## 9. v1.5 다중 접점·아트 검증

- 모바일 메인은 전체 화면 방, 넓은 이동 범위, 작지만 표정이 읽히는 펫, 최소 UI다. 디버그 버튼을 메인으로 되돌리지 않는다.
- reserved의 반쯤 감긴 눈·작은 일자 입을 유지한다. 교감/기쁨이라고 모든 프로필을 같은 웃는 얼굴로 바꾸지 않는다. 말캉함은 접촉/착지 반응이지 상시 전체 그림 늘리기가 아니다.
- 초기 PC는 같은 펫 조회·무료 교감·표시 위치/모드 변경만 한다. 먹이·구매·수면 전이·진화·EXP·성격 점수 쓰기 권한을 만들지 않는다.
- 위젯은 스냅샷이다. 앱 렌더러를 계속 실행하거나 푸시/재조회로 경제를 진척시키는 우회를 만들지 않는다. Android 배경화면은 별도 타당성 검증 범위다.
- 실제 건강 원본과 필요 없는 집계를 PC/공용 화면으로 전송하지 않는다. 지원하지 않는 시크 표정/아트/스키마를 새 진화형으로 임의 대체하지 않는다.
- 연결 계정과 대상 파일을 실제 조회 후 확인한다. 다른 회사/개인 계정·공유 권한을 임의 변경하지 않는다. Figma 조회·업로드 URL 발급·편집 성공·실제 렌더 검증을 구분한다.
- 도구 한도/권한/네트워크로 Figma 쓰기가 실패하면 원격 반영을 완료로 보고하지 않는다. 기존 파일이 비었다는 결론도 하위 노드를 실제 확인한 경우만 내린다.
- 문서/시안의 제작, 테스트 명세 작성, 네이티브 코드 구현, 실제 설치/실기기 검증을 각각 보고한다. 과거 v3 테스트 결과를 이번 신규 기능의 실행 결과로 재사용하지 않는다.
