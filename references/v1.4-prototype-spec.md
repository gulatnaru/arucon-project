# 아루콘 — 생활 프로토타입 범위와 실행 계약

버전 life-proto-0.1 / 대응 SRS v1.4 / 작성일 2026-09-17  
이 문서는 실제로 제공한 HTML 시제품의 범위다. 운영 SRS 전체를 구현했다는 뜻이 아니다.

## 1. 실행 파일

`../prototype/arucon-prototype.html`은 CSS·SVG·JavaScript를 내장한 단일 파일이다. 외부 폰트·이미지·라이브러리·API를 가져오지 않는다. 패키지 설치 없이 일반 데스크톱 브라우저에서 여는 용도다. 파일 미리보기 앱은 스크립트를 실행하지 않을 수 있으므로 실행 브라우저에서 확인한다. file:// 저장 동작은 환경별 확인이 필요하다.

로컬 웹 방식으로 열려면 `prototype` 폴더에서 다음 명령을 실행하고 표시한 로컬 주소로 접속한다.

```sh
python -m http.server 8000 --bind 127.0.0.1
# 브라우저: http://127.0.0.1:8000/arucon-prototype.html
```

이 명령은 현재 컴퓨터에서만 보이는 개발 서버다. 모바일 공유 URL이나 공개 배포가 아니다. 공개 배포·호스팅 계정 변경은 이번 작업에서 하지 않았다.

## 4. 시간과 부재의 단순화

화면을 보는 동안에는 시간 버튼으로 수치 시간을 진행한다. 11초 간격의 idle 연출은 보상을 주거나 배고픔을 올리지 않는다. 따라서 UI를 오래 구경해도 그 자체로 시간성 자원이 계속 줄지 않는다.

창을 숨기거나 닫은 뒤 돌아오면 저장 시각/숨긴 시각과 현재 기기 시각의 차이를 부재 입력으로 사용한다. 실제 1분은 게임1분이며 연출 속도로 과장하지 않는다. 입력을 최대7일로 제한하지만 상태는 마지막 활성 기준24시간 이내에서만 진행한다. 그 이후는 동면으로 정지하고 복귀 버튼으로 이어간다. 잠든 상태로 동면했으면 복귀 후에도 잠든 상태다.

모든 수치 변화는 전역 게임 분 경계에서 계산한다. 59초는 다음 경계 전까지 수치 변화가 없을 수 있다. 부재 입력을 분할해도 같은 결과를 내도록 테스트했다. 기기 시계 조작/시간대/DST/서버 검증을 구현한 것은 아니다.

프로토타입은 실제 건강 데이터의 지연·버전 변경을 다루지 않는다. 부재 정산 이후 +걸음 버튼을 누르면 현재 시점의 먹이가 생긴다. 새 먹이를 과거에 보유했다고 소급해 먹이지 않는다. 자동식사 자체가 접속 시각을 갱신하지 않는다.

## 5. 코드 구조

```text
prototype/
  arucon-prototype.html       배포되지 않은 독립 실행 파일
  build.py                   src를 단일 HTML로 묶음
  src/config.js              합성값/카탈로그
  src/engine.js              순수 상태/명령/시간 정산/식사/검증
  src/behaviors.js            성격별 포즈·거리·시간·완료 문구
  src/app.js                  DOM·저장·시계 입력·연출·버튼
  src/styles.css             반응형 레이아웃/애니메이션
  src/index.template.html    임시 SVG·화면 구조
  tests/                     Node/브라우저 검사와 실제 결과
  screenshots/               실제 브라우저 렌더
  QA-REPORT.md               실행 근거 및 확인 불가 항목
```

`engine.dispatch(state, command, config)`는 새 상태·새 이벤트·결과를 돌려준다. 입력을 변경하지 않는다. engine은 파일/네트워크/브라우저/난수를 읽지 않는다. app이 commandId와 부재 시간 입력을 제공하고 저장한다.

두 급식은 같은 `meal` 경로를 사용한다. 식사 명령은 엔진에서 즉시 확정되며 그 결과를 연출한다. 애니메이션만 보다가 창을 닫아도 이미 확정된 식사의 결과가 추가 지급되지 않는다. 일지의 `다시 보기`는 시각 스크립트만 실행한다.

터치/놀이 관찰은 시퀀스가 끝난 뒤에만 `observe`로 남긴다. 중간에 다른 행동·성격 전환·수면·창 숨김·안내창 등으로 중단하면 완료로 기록하지 않는다. 연출에는 자동 플레이 선택 및 이벤트 큐의 운영 수준 스케줄러가 없다. 하나의 새 연출이 이전 연출을 대체한다.

## 6. 저장과 신뢰성 한계

localStorage 저장은 같은 브라우저/출처에서만 사용할 수 있다. 코드 내 보호 로직은 백업·클라우드·로그인·DB 트랜잭션이 아니다. 브라우저 데이터 삭제, 파일 이동으로 출처가 달라진 경우, 다른 기기, 오래된 스키마 마이그레이션은 복구하지 않는다.

저장 실패 때는 현재 메모리에서 계속 실행하고 한계를 알린다. 손상되거나 버전이 다른 저장은 자동으로 덮어쓰지 않는다. 명시적인 ‘데모 초기화’가 삭제를 허용한다. 복구 파일 내보내기·사용자별 데이터 분리·충돌 해결·암호화는 운영 단계 과제다.

다른 탭의 변경 신호로 쓰기를 멈추는 장치는 동시 사용 경고일 뿐, 완전한 다중 탭 경쟁 방지가 아니다. 마지막512개 밖의 오래된 명령 재전송을 완전히 막는 운영 원장도 없다. 이 약점들을 SQLite/서버 계약으로 이행하는 것이 D1/D2d/D6a 작업이다.

## 7. 포함하지 않은 것

실제 HealthKit/Health Connect/페도미터/GPS, 실제 수면 채점, 계정·법정 동의·결제·네트워크·서버 동기화·위젯·푸시·출시 심사, 레벨/성별/진화 전 과정, 공통 아기형 및 1차4종 완성 아트, 16성향 형성, 취향 학습, 자유 가구 배치, 운영 경제 밸런스를 구현하지 않았다.

누적 EXP 숫자는 실제로 계산하지만 단계별 진화 판정을 구현하지 않는다. 1개 방과 두 성격의 감각을 먼저 확인하는 시제품이다. 현재 펫의 SVG는 기존 시트에 대한 임시 구현이며 원화/리깅 납품이 아니다.

## 8. 검증 범위

자동 검사 실행 결과는 `../prototype/QA-REPORT.md`와 테스트 결과 파일에만 기록한다. 브라우저는 HTML을 DOM으로 주입해 시험했으며 저장소는 명시적인 메모리 fixture로 대체했다. 테스트 환경 정책상 파일/로컬 주소 직접 탐색이 차단되어 실제 file:// 실행, 실제 출처 localStorage 지속성, 사용자 기기의 Safari 실행은 검증하지 못했다. 구현 자체가 차단된 기능을 필요로 하는 것은 아니지만 그 환경별 동작을 확인했다고 주장하지 않는다.
