# FUN-00 — 아루콘 재미·상호작용·캐릭터 개편 통합 지시서

> **2026-09-28 운영 변경:** 이번 품질 복구·FUN 개편은 ASTRA_DIRECT다. 아래의 모델별 위임·별도 reviewer 필수 절차 대신 Astra가 직접 설계/구현/디버깅/실제 앱 검증과 SELF_REVIEW를 수행하며 새 서브에이전트는 생성하지 않는다. 제품 요구·테스트 기대값·권한은 유지한다. 정상 사용자 입력으로 검증하며 개발 메뉴 강제 재생만으로 통과하지 않는다. 현재 종료 상태는 READY_FOR_PRODUCT_REVIEW / REWORK_REQUIRED / BLOCKED를 사용하고 재미·최종 아트는 USER_REVIEW_PENDING이다. 과거 분업과 종료 명칭은 이력으로 보존한다.

이 파일 전체를 이번 Codex 작업 지시로 사용한다. 기존 프로젝트에서 이어서 구현하며, 새 앱을 처음부터 다시 만들거나 과거 인계 ZIP으로 현재 소스를 덮어쓰지 않는다.

이 문서의 사용자 피드백은 이번 대화에서 전달된 내용이다. 상세 시스템 구성과 검증 방법은 그 피드백을 실행 가능한 작업으로 구체화한 지시다. 새로운 경제·건강 평가·진화 산식이나 출시 정책을 일괄 승인하는 문서가 아니다.

## 1. 최상위 목표와 현재 문제

아루콘의 당면 목표를 ‘출시 직전 검증을 끝내기’에서 **사용자가 직접 만지고 키우고 싶어지는 펫 게임의 플레이 가능한 개편판을 만들기**로 전환한다.

사용자가 직접 플레이하며 보고한 문제:
- 성장과 달라짐이 잘 보이지 않아 키우는 재미가 부족하다.
- 상호작용 종류, 대사, 표정과 후속 반응이 적고 반복된다.
- 성격을 설명 없이 알아보기 어렵다.
- 움직임이 매우 끊기고 느리다. 기존 보고의 ‘3Hz’가 무엇을 뜻하는지는 다시 확인해야 한다.
- 기록 화면이 열린 뒤 닫히지 않는다.
- 청소와 쓰다듬기가 동작하지 않는 것처럼 느껴진다.
- 캐릭터가 귀엽기는 하지만 고유한 매력이 부족하다. 뿔 위치·형태와 얼굴·몸 비율을 다시 보고 싶다.
- 몸은 단순히 화면에서 커지는 것이 아니라 **앞·옆·뒤 모두 더 둥글고 도톰한, 통통한 모찌 체형**이었으면 한다.

목표 경험:
> 얼굴은 시크하지만 행동은 다정한 아이. 익숙한 버릇은 남고, 상황과 함께한 경험에 따라 새로운 모습을 발견한다. 키우면서 무엇이 달라졌는지 실제 행동과 화면에서 느낀다.

과거 자동 테스트·네이티브 빌드·시뮬레이터 PASS 기록으로 이번 사용자 관찰을 반박하지 않는다. 해당 빌드·상태·입력에서 다시 재현해 원인을 확인한다. 사용자 피드백도 아직 모든 원인이 확정된 버그 분석으로 취급하지 않는다.

## 2. 이번 변경 허용 범위와 보존할 것

### 이번에 구현할 범위
- 기록창·청소·쓰다듬기 등 기본 조작 복구와 성능 문제 진단·수정.
- 상황 기반 반응 선택, 순간 감정 표현, 짧은 선택형 대화, 연출 제어, 제한된 교감 기억, 콘텐츠 작성·검증 도구.
- 승인된 성장 결과의 가시화와 성장에 따른 행동·표현의 확장.
- 캐릭터의 앞뒤 볼륨·얼굴 배치·귀·뿔을 다듬는 **비파괴 후보 제작과 실제 앱 비교 모드**.
- 위 변경에 필요한 코드·콘텐츠·스키마·테스트·관련 문서 수정.

기존 ‘승인 아트 변경 금지’는 이번에 명시적으로 요청한 체형·뿔·얼굴 후보 제작을 막는 근거로 사용하지 않는다. 다만 원본은 보존하며, 후보를 최종 승인 아트나 운영 기본값으로 자동 확정하지 않는다.

### 계속 유지할 제품 경계
- 화면 전체가 방이고, 펫은 작게 보이며, 실제 이동 가능한 빈 공간이 넓다.
- 모찌 같은 말캉함, 작은 생명체의 인상, 시크한 얼굴과 다정한 행동의 대비를 유지한다.
- 공통 아기형 표시명은 **아루콘**, 1차 형태 이름은 **말루·모노·피코·몽글**이다.
- 개체명(예: 구름콘), 형태 이름, 성격은 독립이다. 모노를 츤데레로 강제하지 않는다.
- EXP는 승인된 섭취 확정에서만 생긴다. 대화·쓰다듬기·관찰 자체로 EXP나 재화를 만들지 않는다.
- 직접 급식과 동의한 식탁 자동급식의 조건·성장 효율을 동등하게 유지한다.
- 실제 걷기·가벼운 교감 때문에 체력을 깎지 않는다. 청결 외 원인으로 기운 없음을 만들지 않는다.
- 기본 화장실과 자동화의 편의를 약화하지 않는다. 새로운 청소 숙제·유지비·수동 돌봄 보너스를 붙이지 않는다.
- 사망·영구 손실·재화 회수·접속 압박·운동/수면/건강 상태에 대한 비난을 만들지 않는다.
- 이미 승인·구현된 정책과 정확한 수치는 현재 SRS/DEC/config에서 확인해 유지한다. 오래된 문서의 OPEN 상태나 과거 제안으로 되돌리지 않는다.
- 이번 개편을 이유로 성장 기간, 수면 점수 산식, 진화 분기, 상품 가격·효과, 성격 형성 산식을 새로 승인하지 않는다.
- 실제 HealthKit/Health Connect/센서 건강정보 읽기는 OFF, 실제 사용자 계정·실결제·운영 서비스 연결은 기존 승인 경계대로 유지한다.

## 3. 착수와 자율 진행 방식

현재 Git branch/HEAD/변경 사항과 사용 가능한 도구부터 확인한다. 특정 과거 커밋으로 reset하지 않고 사용자 변경을 보존한다.

루트와 해당 하위 경로의 `AGENTS.md`, 이 지시서, 다음 자료의 관련 부분으로 현재 상태를 복원한다:
- `NEXT-RESUME.md`, `AUTONOMOUS-STATUS.json`, `AUTONOMOUS-RUN-REPORT.md`
- `MVP-GAP-MATRIX.md`, `DECISION-SUMMARY.md`, `DECISION-QUEUE.md`
- `docs/model-routing.md`, `docs/hard-stops.md`
- SRS/DEC의 성장·성격·생활·시각·입력 관련 항목
- 현재 앱 코드, 자산, 렌더러/모션 설정, 해당 테스트와 최근 실제 실행 증거

파일이 없으면 없다고 기록하고 현재 근거로 진행한다. 관련 없는 문서·이력·대용량 자산을 모든 에이전트가 전부 읽게 하지 않는다.

현재 구조에서 재사용할 것과 바꿀 것, 의존 관계, 완료 증거를 짧게 계획하고 곧바로 구현한다. 계획 문서 작성만 하고 사용자 승인을 기다리지 않는다. 아래의 시스템 책임을 꼭 별도 패키지나 클래스로 만들 필요는 없지만, 책임·데이터·검증 경계는 분리한다.

### 모델별 역할
`docs/model-routing.md`와 실제 사용 가능한 역할 설정을 유지한다.
- 루트 Astra: 작업 분해, 경험 설계의 통합, 교차 모듈 판단, 결과 판정.
- `arucon_explorer`: 탐색·실패 경로·콘텐츠/자산/기존 검사 파악.
- `arucon_builder`: 비사소한 앱·상태·렌더러·저장·시스템 구현.
- `arucon_luna_worker`: 범위가 정해진 콘텐츠 데이터·fixture·반복 수정.
- `arucon_reviewer`: 구현 담당과 분리된 회귀·상태·콘텐츠·증거 검토.
- Spark 역할은 실제 지원되고 좁은 작업에 적합할 때만 사용한다.

APP/FUN 단계명과 에이전트 역할·실제 모델을 혼동하지 않는다. 요청한 역할/모델과 런타임에서 확인된 모델을 구분한다. 자기소개만으로 모델을 확인했다고 하지 않는다. 설정 미지원이나 모델 정보 미노출은 정확히 기록하며, 모든 하위 작업을 몰래 Astra로 올리지 않는다.

같은 파일의 동시 작성자는 하나다. 독립적인 작업만 병렬화하며 작은 작업마다 모든 역할을 호출하지 않는다. 위임에는 결과·허용 파일/제약·검증·반환할 지점을 포함한다. 콘텐츠 생산과 콘텐츠 품질 검토도 구분한다.

## 4. 먼저 플레이를 막는 문제부터 해결한다

### 기록 화면
- 실제 앱에서 열기·닫기·다시 열기와 기존의 닫기 제스처를 재현한다.
- 명확한 닫기 수단을 제공한다. Android 뒤로가기는 열린 패널을 먼저 닫고, 플랫폼에 맞는 기존 조작을 유지한다.
- 닫힌 뒤 투명 overlay, pointer capture, gesture handler, 포커스 또는 입력 잠금이 남지 않는다.
- 패널을 닫는 입력이 그대로 바닥 이동이나 급식으로 전달되는 click-through도 막는다.
- 성공 후 이전 거절 안내가 남는 회귀와 패널 전환 중 연출·입력 복구를 확인한다.

### 쓰다듬기
- 작은 펫의 시각 크기와 조작 영역을 분리하되 가구·버튼·말풍선 선택과 충돌하지 않게 한다.
- 누르기·유지·놓기·취소·두 손가락·이동 중 입력을 확인한다.
- 유효한 입력에는 즉시 작은 시선/표정/몸 피드백을 준다. 츤데레의 딴청 때문에 입력 자체가 무시되는 것처럼 보이지 않는다.
- 손을 떼거나 화면이 바뀌면 누름 상태가 정리되고 자연스럽게 복원된다.

### 청소
- ‘입력 오류’, ‘배설물 없음’, ‘화장실이 이미 자동 처리함’, ‘실제 청소 성공’을 구분한다.
- 자동 화장실이 있는 정상 상태를 고장으로 바꾸거나 테스트하려고 일부러 청소 거리를 만들지 않는다.
- 대상이 없으면 짧고 명확한 안내를 주고, 대상이 있으면 승인된 청소 처리와 시각 반응을 연결한다.
- 더러운 상태 재현이 필요하면 실제 저장과 분리한 개발용 fixture를 사용한다.

### 생활 행동과 입력 우선순위
식사·수면·패널·대화·쓰다듬기·이동·자율 행동의 우선순위와 취소 규칙을 명시한다. 모든 연출을 끝까지 강제 대기시키지 말고, 기존 도메인 계약에 따라 중단 불가 행동과 취소 가능한 표현을 구분한다. 연속 입력·앱 전환 후 영구 busy 상태가 남지 않게 한다.

## 5. 끊김과 느림을 성능 측정으로 분리한다

‘시뮬레이터라서 그렇다’거나 ‘실기기를 연결해야만 할 수 있다’고 단정하지 않는다. 현재 환경에서 확인 가능한 원인을 먼저 조사한다.

- 기존 3Hz가 렌더 요청 제한, 실제 화면 갱신, 모션 샘플링, 진단 캡처 주기 중 무엇인지 확인한다.
- 일반 모드에 임시 진단용 저주기 설정이 남아 있다면 경로와 적용 조건을 수정한다. 위젯 갱신 주기나 움직임 줄이기를 본앱 모션 품질과 혼동하지 않는다.
- Debug/Release, 시뮬레이터/에뮬레이터/실기기, 하드웨어/소프트웨어 렌더링을 구분해 기록한다.
- JS 작업, native/GL 작업, draw call·재질·그림자·해상도, morph 계산·할당, 프레임 예약·중복 루프, DB/UI 갱신 비용을 증거에 따라 좁힌다.
- 모션 속도와 렌더 프레임 수를 분리한다. 저프레임을 모든 동작 배속으로 감추거나 게임 시간을 변경하지 않는다.
- 같은 조건의 전후 측정을 남긴다. 가능한 프레임 간격 분포·긴 멈춤·입력 이벤트 후 첫 피드백 지연과 측정 한계를 보고한다.
- 이번 검증 환경의 프레임/입력 예산과 측정 방법을 먼저 정해 기록한다. 실패 후 통과시키려고 기준을 완화하지 않는다. 임의 수치를 이미 사용자가 승인한 출시 사양으로 적지 않는다.
- 새 반응 시스템은 사건 중심으로 동작한다. 매 프레임 전체 카탈로그 탐색·대사 선택·DB 쓰기를 하지 않는다.
- UI 닫기와 기본 입력이 고비용 렌더 때문에 장시간 잠기지 않게 한다.

시각적으로 중요한 몸·얼굴·말캉함을 삭제하거나 GLB를 단색 도형으로 바꿔 완료하지 않는다. 저비용 렌더 경로가 필요하면 비교 가능한 설정으로 두고 외형·입력·모션 차이를 공개한다.

실제 기기가 없으면 기기 터치 지연·발열·배터리는 NOT_RUN이다. PC에서 가능한 재미 검증을 먼저 진행하되, 성능 원인 구분에 실제 기기가 필요하면 별도 차단 항목으로 남긴다. 실기기 검증을 앞으로 영구 생략하는 것은 아니다.

## 6. 키우는 재미와 성장 체감을 실제 플레이에 연결한다

대사만 늘리지 말고 다음 연결을 만들어라:

**상호작용 → 즉시 반응 → 후속 행동/짧은 대화 → 함께한 경험의 변화**

**승인된 활동 입력 → 먹이·코인 → 섭취 확정 → 성장 결과 → 새로운 행동·표현/생활환경의 발견**

- 현재 성장 계산이 있어도 사용자가 체감하지 못하는 원인을 찾는다. 값이 없거나 연출이 연결되지 않은 것을 구분한다.
- 식사 완료와 실제로 확정된 성장 변화, 다음 성장까지의 진행, 새로 열린 표현을 단순하고 읽기 쉽게 보여준다.
- 레벨업/형태 변화/행동 해금 알림은 확정 이벤트에 연결한다. 재생·재실행으로 성장이나 재화를 다시 지급하지 않는다.
- 승인된 성장 단계에 맞춰 새로운 놀이 방식·자세·대화 장면을 발견하게 한다. 상호작용을 많이 클릭해야 더 빨리 성장하는 구조로 바꾸지 않는다.
- 같은 외형·성격의 고유한 버릇은 성장 후에도 남긴다. 발전이 완전히 다른 성격으로 교체되는 것처럼 보이지 않는다.
- 반응 기억을 애정 점수의 관리 숙제, 연속 출석, 비접속 감점, 유료 가구의 애정 우위로 만들지 않는다.
- 가구가 있으면 그 가구와의 행동이 늘어나지만, 빈 방에서도 기본 교감과 애정 표현은 가능해야 한다.

오래 기다리지 않고 성장 차이를 비교하도록 개발용 ‘성장 전/후 시나리오’를 제공한다. 별도 fixture 저장소/프로필로 격리하고 합성 시연임을 표시한다. 일반 저장·원장·시간·실제 건강기록에 섞거나 실제 성장 속도를 바꾸지 않는다.

진화 형태 ID와 대명사는 있으나 런타임 아트가 없는 경우 이를 명확하게 표시한다. 같은 공통 GLB를 보여주면서 ‘진화 외형 구현 완료’라고 하지 않는다. 이번에는 공통 아기형 개편을 우선하고, 없는 4종 자산은 별도 미완료로 유지한다. 이름·분기·완성 모델을 서로 다른 결과물로 다룬다.

## 7. 확장 가능한 펫 반응·감정·대화 시스템 v1

### 7.1 상황과 반응 선택
- 입력 사건, 현재 도메인 상태, 하던 행동, 접촉 위치, 성격, 최근 반응 이력, 가구, 승인된 성장 단계로 상황을 구성한다.
- 유효한 후보를 먼저 좁히고 우선순위·최근 사용·반복 억제·변형을 적용한다. 랜덤이 상황과 성격보다 우선하지 않는다.
- 최근 대사 ID뿐 아니라 의미상 같은 행동 장면의 연속 반복도 관리한다.
- 다른 적절한 후보가 없으면 안전한 기본 반응을 사용한다. 반복 억제가 입력 거절이나 무반응을 만들면 안 된다.
- 테스트용 시간과 난수를 주입할 수 있게 하며, 왜 선택/제외되었는지 개발 모드에서 설명 가능하게 한다.

### 7.2 성격·게임 상태·순간 감정의 분리
- 성격: 비교적 안정적인 표현 스타일.
- 게임 상태: 기존 엔진이 결정하는 배고픔·수면·청결 등에 관한 상태.
- 순간 감정: 관심·만족·놀람·쑥스러움 등 표현을 위한 짧은 전환.
- 순간 감정의 시작·전환·안정·중단을 정의한다. 잠깐 시무룩한 것을 영구 성격으로 저장하지 않는다.
- 새로운 표현 상태가 기존 Mood·체력·EXP 계산의 다른 진실 원천이 되지 않게 한다.
- 사용자 운동량·수면으로 사람의 MBTI·의료 상태를 추정하지 않는다. 이번에 16성격 전체를 확정·구현할 필요는 없다.

### 7.3 대사와 짧은 선택형 대화
- 일방적인 말풍선과 선택 후 후속 행동이 이어지는 짧은 대화를 구분한다.
- 시작 → 표현/선택 대기 → 후속 반응 → 종료 또는 취소의 상태를 관리한다.
- 선택지는 적고 맥락에 맞게 제공한다. 대답하지 않거나 다른 화면을 열어도 벌점·독촉·입력 잠금이 생기지 않는다.
- 대사를 읽기 전에 자동으로 넘어가지 않도록 가독성을 확보하고, 즉시 닫거나 대화 표시를 줄일 수 있게 한다.
- 로컬 콘텐츠로 오프라인 동작한다. 이번에 자유 입력형 외부 LLM, 유료 대화 API, 마이크, 서버 대화 전송, 사용자 간 채팅을 추가하지 않는다.
- 대사 개수나 무작위 조합 수만 늘리는 것을 대화 시스템 완료로 보지 않는다.

### 7.4 행동·표정·시선 연출
- 눈·입·시선·귀·몸·대사를 감정적으로 일관된 하나의 장면으로 묶는다.
- 기분에 안 맞는 표정·동작·문장을 독립 랜덤으로 조합하지 않는다.
- 같은 장면 안에서는 시선 방향, 기대는 위치, 머뭇거림, 귀의 후행 반응 등을 안전하게 변화시킬 수 있다.
- 대사 없이 몸과 시선만으로 표현하는 반응도 제공한다. 대사는 행동을 보조하며 매번 길게 말하지 않는다.
- 입력에는 빠른 확인 반응을 주고, 성격 연기는 그 뒤에 이어간다.
- 취소·화면 전환·앱 정지·컴포넌트 해제에서 listener, timer, 입력 잠금, 임시 표정, 예약 연출을 정리한다.
- 화면 연출 종료 콜백이 새로운 경제 정산이나 중복 보상의 우회 경로가 되지 않게 한다.

### 7.5 교감 기억과 성장 연결
- 실제 발생한 게임 사건과 화면에서 보여준 반응을 구분한다.
- 시작·표시·완료·중단 중 어떤 시점에 최근 사용/기억이 기록되는지 명세한다. 중단 장면을 완료 관찰로 기록하지 않는다.
- 재접속 때 최근 반복 억제와 필요한 습관 표현을 이어갈 수 있도록 제한된 이력을 저장한다. 펫별 범위, 최대 크기, 버전, 마이그레이션·손상 복구를 둔다.
- 원시 건강정보나 불필요한 개인 데이터를 수집하지 않고, 이벤트마다 전체 원장을 읽거나 매 프레임 저장하지 않는다.
- 부재 중 관찰하지 않은 놀이·대화를 실제 기억처럼 꾸미지 않는다. 도메인이 실제 확정한 부재 정산 사건과 구분한다.
- 기록은 반응 선택을 돕는 수단이다. 관계 수치 감소·클릭 보상·성장 배율의 숨은 변경으로 연결하지 않는다.

### 7.6 자기 생활을 하는 행동
- 적절한 휴식 간격을 두고 살피기·자세 바꾸기·자리 이동·가구 탐색 등의 자율 행동을 선택한다.
- 사용자의 입력이 들어오면 낮은 우선순위의 자율 행동을 자연스럽게 양보한다.
- 계속 말하거나 뛰어다니며 주의를 요구하지 않는다. 조용함과 가끔 나오는 새로운 행동의 대비를 유지한다.
- 움직임 줄이기에서는 필요한 입력과 상태 전달을 남기고 장식 배회·과한 탄성을 줄인다. 경제 결과는 동일하다.

### 7.7 콘텐츠 데이터와 제작 도구
- 이미 지원하는 동작을 쓰는 새 반응은 핵심 선택 엔진 수정 없이 데이터 추가로 확장할 수 있어야 한다.
- 콘텐츠 ID, 장면 계열, 성격/상황 조건, 우선순위·반복 규칙, 대사/선택지, 연출 참조, 후속 전환과 종료를 검증 가능한 형식으로 둔다.
- 새 움직임이 필요한 콘텐츠는 별도 애니메이션 제작이 필요하다고 표시한다. 없는 리소스를 재생했다고 하지 않는다.
- 중복 ID, 누락 참조, 모순된 조건, 유효하지 않은 전환, 도달 불가 후보를 검사한다.
- 개발용 미리보기에서 상황·성격·단계·최근 이력을 지정하고 후보/선택 이유/실제 재생 장면을 확인한다. 일반 방 화면에는 디버그 도구를 노출하지 않는다.
- 이름 삽입·줄바꿈·긴 문장·문자 수 처리와 기존 Hermes/네이티브 호환 수정을 보존한다.

## 8. 실제 콘텐츠 범위와 성격 연기

시스템과 콘텐츠를 함께 납품한다. 구조만 만들고 대사 몇 줄만 넣거나, 반대로 많은 문장만 넣고 시스템이 있다고 하지 않는다.

첫 연결 검증은 **쓰다듬기·공놀이·휴식**으로 한다. 같은 외형에서 츤데레와 솔직한 아이를 비교하고, 그 연결을 확인한 뒤 인사·식사·잠들기/깨우기·가구 탐색·성장 발견·청소 상황 안내까지 확장한다.

상황별 콘텐츠 표에 트리거, 실제 전제 조건, 성격 차이, 행동 장면, 후속 반응, 가능한 자산, 반복 규칙을 기록한다. 같은 대사의 동의어 교체는 새로운 행동 장면으로 세지 않는다. 동작이 같은 모든 순열을 ‘수천 개 반응’으로 계산하지 않는다.

다양성과 일관성을 함께 유지한다. 반복을 영원히 없앨 수 있다고 약속하지 않고, 짧은 플레이에서 특정 몇 장면만 몰리는 원인을 줄인다. 고유한 버릇은 남기되 상황이 달라지면 반응의 의미도 달라져야 한다.

### 츤데레의 핵심
‘싫은 척하지만 결국 다정하게 반응하는 아이’다. 실제 거부·지연·낮은 보상을 성격으로 만들지 않는다. 늘 졸리거나 화난 표정으로 고정하지 않는다.

연기/대사 예시 — 문구 그대로 강제할 필요는 없음:
- 평소 쓰다듬기: 얼굴은 옆으로, 몸은 손에 기대기. “……거긴 괜찮네.”
- 손을 뗀 후: 손이 있던 곳을 보고 살짝 다가오기. “……끝이야?”
- 공을 가져오기: 공을 놓고 딴청. “그냥 여기 둔 거야.”
- “같이 놀까?” 선택: 공을 앞으로 밀기. “한 번만이야.”
- “옆에서 쉬자” 선택: 공을 옆으로 두고 가까이 앉기. “……그것도 나쁘진 않네.”
- 쉬는 중 접촉: 눈만 짧게 감고 몸을 맡기기. 대사 없이 표현 가능.

솔직한 아이는 같은 애정의 크기를 빠른 눈 맞춤·먼저 다가오기·분명한 기대기로 표현한다. 두 성격의 차이는 애정의 가치나 기능 효율이 아니라 표현 방식이다.

‘늦었잖아’, ‘왜 안 왔어’, ‘네가 안 돌봐서’처럼 접속·건강·돌봄을 탓하는 문구는 넣지 않는다. 새로운 마음속 기억을 이유로 수동 급식을 유리하게 만들지 않는다.

## 9. 캐릭터 v2 — 통통한 입체감과 시크한 얼굴

현재 원본·자산 식별자·편집 소스·모션 설정을 먼저 확인하고 보존한다. 단순 콘셉트 이미지, 실제 3D 자산, 실제 재생 동작을 구분한다.

이번 아트 집중 범위는 공통 아기형이다. 기존 1차 형태명/방향은 유지하고, 새 아기형 승인 전 4종의 대규모 재제작으로 범위를 넓히지 않는다.

제작 방향:
- 정면 폭만 키우지 않고 이마/얼굴 아래·배·등·엉덩이의 앞뒤 두께와 곡률을 늘린다.
- 머리와 몸이 강하게 나뉘지 않는 도톰한 찹쌀떡 실루엣을 만든다. 배만 별도 공처럼 붙이지 않는다.
- 방 안에서 차지하는 전체 화면 크기는 크게 늘리지 않는다. 작은 펫과 넓은 공간을 유지한다.
- 짧고 둥근 뿔이 둥근 이마에 자연스럽게 연결되도록 위치·각도·길이·형태를 검토한다.
- 눈매·입이 몸의 볼륨에 묻히지 않게 하며 반쯤 감긴 시크한 인상은 읽혀야 한다.
- 작은 발은 바닥을 딛고, 귀는 부드럽게 따라온다. 눌림·복원에서 얼굴이 찌그러지거나 가구와 겹치지 않게 한다.
- 광택 강한 젤리나 플라스틱으로 바꾸지 않고 따뜻한 크림색 모찌 느낌을 유지한다.

비교 범위는 **기존형 + 볼륨을 조금 늘린 후보 + 더 과감하게 늘린 후보**로 제한한다. 같은 카메라·조명·게임 화면 크기에서 정면·측면·뒷면·3/4, 대기·보행·눌림/복원을 비교한다.

가능한 도구로 편집 가능한 소스와 실제 앱용 후보 자산을 제작하고, 개발용 비교 선택기에 연결한다. 도구가 부족하면 확인된 자산 계약과 부족한 제작 항목을 남긴다. 정지 시안만으로 런타임 아트 완료라고 하지 않는다. 아트 후보가 막혀도 입력·성능·대화 작업은 계속한다.

후보는 기존형으로 쉽게 돌아갈 수 있게 한다. 비교 토글은 `formId`, 진화 결과, 경제 상태를 변경하지 않는다. 후보 제작 완료와 사용자 최종 아트 승인 상태는 분리한다.

## 10. 화면은 복잡하게 만들지 않는다

- 전체 화면 방과 기존 최소 조작 구성을 유지한다. 새 감정 수치판·관리 대시보드로 방을 덮지 않는다.
- 짧은 말풍선과 소수의 맥락형 선택지를 사용하고, 가구·펫·이동 입력을 과도하게 가리지 않는다.
- 성장 피드백과 새 행동 발견은 필요한 순간에만 보여준다. 큰 팝업을 매번 반복하지 않는다.
- 기록 화면은 보조이며, 재미의 대부분은 방 안의 실제 행동에서 느껴져야 한다.
- 작은 화면·큰 글자 설정·안전 영역·화면 전환에서도 닫기와 선택 입력이 도달 가능해야 한다.
- 대사 표시·선택 입력은 움직임 줄이기에서도 정상 작동한다. 소리를 추가한다면 무음에서도 의미가 전달되어야 한다.

## 11. 검증 계약

각 변경에 맞는 검사와 저장소 필수 검사를 실행한다. 매번 전체 스위트를 반복할 필요는 없으나 통합 게이트에서는 필요한 회귀를 수행한다. 실패를 숨기기 위한 테스트 삭제·Windows skip·기대값 완화는 금지한다.

필수 확인:
1. 기록창을 여러 번 열고 닫아도 overlay/입력 잠금이 남지 않고 배경 오조작이 없다.
2. 쓰다듬기 시작·유지·해제·취소·다중 입력 후 복원과 다음 동작이 정상이다.
3. 청소 대상 없음/자동 처리/실제 대상 있음이 구분되고 성공 피드백이 실제 상태와 일치한다.
4. 같은 입력에서 상황·성격 차이가 선택과 실제 연기로 드러난다.
5. 적절한 대안이 있을 때 최근 장면의 반복을 줄이고, 후보 부족·손상 콘텐츠에서도 안전한 반응을 제공한다.
6. 대화 선택·무응답·닫기·화면 전환·앱 전환에서 영구 대기나 잘못된 후속 행동이 생기지 않는다.
7. 시작/완료/중단의 기억 기록과 재실행 후 최근 이력 유지가 명세대로 동작한다.
8. 교감·대사·표시 재생은 자원 중립이며, 직접/자동급식 동등성과 기존 원자적 정산을 보존한다.
9. 성장·해금 피드백은 확정 이벤트에 연결되고 중복 재생이 보상/진화 재실행을 만들지 않는다.
10. 개발 성장/감정 시나리오는 실제 저장과 격리된다. 기존 저장본을 삭제하지 않고 마이그레이션·실패 복구를 검사한다.
11. 지원되는 연출의 새 반응 데이터를 추가해 핵심 선택 코드 변경 없이 실제 재생할 수 있다.
12. 최소 대표 장면은 실제 앱에서 입력부터 후속 반응까지 이어진다. 콘솔 출력·Node 검사만으로 완료하지 않는다.
13. 새로운 체형의 눈매·바닥 접촉·가구 접근·눌림·복원과 크기를 동일 조건에서 비교한다.
14. 성능은 실제 측정 경로와 환경을 명시한다. 영상 인코딩 FPS·자동 시계 진행·렌더 생략 테스트를 앱의 실제 성능이라고 하지 않는다.
15. iOS Simulator, Android Emulator, 실기기의 실행 결과를 서로 대신하지 않는다. 실행하지 못한 플랫폼은 미실행/환경 차단으로 남긴다.

재현에 필요한 최소 증거를 남기며 긴 영상이나 로그를 무작정 늘리지 않는다. 독립 reviewer는 코드·도메인 경계뿐 아니라 장면의 맥락·반복·도달성·보고 정확성도 검토한다. reviewer의 의견은 사용자의 재미·아트 승인을 대신하지 않는다.

## 12. 실행 순서와 중간 정지 방지

작업명은 관리용이며 에이전트 모델명이 아니다.
- FUN-01: 사용자 버그 재현, 기본 조작 복구, 성능 기준선과 주요 차단 원인 해결.
- FUN-02: 쓰다듬기·공놀이·휴식의 ‘입력→상황→감정→대사/행동→후속 반응→기억’ 연결을 실제 앱에서 검증.
- FUN-03: 나머지 생활 콘텐츠, 성장 체감, 콘텐츠 검증/미리보기로 확장.
- ART-02: 원본을 보존한 통통한 체형·뿔·얼굴 두 후보 제작 및 비교. 인터페이스가 안정되면 독립적으로 병행 가능.
- FUN-04: 통합 회귀·실제 플레이 경로·성능 비교·사용자 평가용 빌드/실행 안내.

문서만 쓰거나 첫 구현을 끝냈다는 이유로 매번 검토를 요청하지 않는다. 목표·제약 안의 기술 선택과 되돌릴 수 있는 표현 튜닝은 자율 수행한다. 다만 기존 도메인 규칙의 변경이 필요한 경우는 별도 결정 항목으로 분리한다.

같은 실패에 변화 없는 재시도를 계속하지 않는다. 저장소의 재시도 예산을 따르고, 정해진 예산이 없으면 원인 가설/측정/변경이 없는 반복을 중단해 차단 근거와 다음 필요 행동을 기록한다. 접근 거부·사용 한도·호스트 잠금을 우회하지 않는다.

하나의 플랫폼·자산·승인 문제가 막혀도 그에 의존하지 않는 작업은 계속한다. 사용자가 답하지 않았다는 이유로 가능한 구현을 남겨두고 종료하지 않는다. 반대로 사용자 만족을 스스로 추측하면서 무기한 수정 루프를 돌리지 않는다.

## 13. Git·외부 권한·데이터 경계

기존에 승인된 개인 `origin` 대상과 `feature/arucon-mobile-autonomous` 브랜치를 실제로 확인한다. 이번 개편에서도 해당 feature 브랜치의 논리적 checkpoint commit과 일반 push를 허용한다. 다른 원격/브랜치로 임의 대체하지 않는다.

- 원본 GLB/편집 소스와 현재 미커밋 변경을 보존하고, 필요한 변경만 선별 stage한다.
- `mobile/.git` 같은 중첩 Git 저장소를 만들지 않는다. 런타임 소스·필요한 자산·lockfile이 실제 일반 파일로 추적되는지 확인한다.
- 비밀키·계정 캐시·실제 DB·node_modules·개인 로그·불필요한 영상/ZIP/빌드 결과는 업로드하지 않는다. 이미 추적된 제외 대상도 검사한다.
- CNG를 사용하는 경우 생성 폴더의 임시 수정보다 재생성 가능한 plugin/template 소스를 수정한다. 재생성 전 직접 수정된 내용의 유무를 확인한다.
- 저장 손상·빌드 실패 해결을 위해 사용자 DB나 다른 파일을 조용히 삭제하지 않는다.
- main push/merge, force push, tag/release, 배포·공개 범위 변경, 신규 유료 API/외부 계정 생성, Figma 원격 편집, 실결제, 실제 건강정보 읽기, 관리자/OS 보안 변경은 이번 범위에서 허용하지 않는다.
- push 실패 시 로컬 체크포인트와 정확한 원인을 남긴다. 원격 반영 완료를 주장하지 않는다.

## 14. 산출물과 종료 조건

소스 구현과 실제 콘텐츠가 주 결과물이다. 상세 문서는 기존 위치를 재사용하거나 아래처럼 소수로 정리한다:
- 개편 계획/승인 범위/의존 관계: `docs/fun-first-plan.md`
- 시스템 계약·데이터 작성법·반복/기억/대화 규칙: `docs/pet-reaction-system.md`
- 캐릭터 후보·편집 소스·비교·리소스 계약: `docs/character-v2.md`
- 실제 검증과 미실행 구분, 사용자 플레이 안내: `FUN-FIRST-REPORT.md`

기존 SRS/DEC에는 이번에 바뀐 요구의 범위와 연결만 일관되게 반영한다. 관련 없는 OPEN을 APPROVED로 바꾸지 않는다. `AGENTS.md`는 짧은 공통 원칙과 해당 문서 참조만 유지한다.

`AUTONOMOUS-STATUS.json`, `AUTONOMOUS-RUN-REPORT.md`, `MVP-GAP-MATRIX.md`, `DECISION-QUEUE.md`, `NEXT-RESUME.md`의 관련 상태를 실제 결과로 갱신한다. 최신 사용자 피드백에서 다시 실패한 항목은 재오픈하고 과거 증거의 빌드/환경을 보존한다.

사용자가 약 10분 동안 비교할 수 있는 실행 경로를 제공한다:
- 기본 이동과 기록창 닫힘, 쓰다듬기/청소 안내.
- 동일 외형의 두 성격 비교와 상황을 바꾼 후속 반응.
- 짧은 선택형 대화와 취소·재개.
- 일반 저장과 분리된 성장 전후 시연.
- 기존 체형과 두 후보의 게임 화면/동작 비교.
- 앱 전환·종료·재실행 후 상태 복구.

최종 상태는 다음을 구분한다:
- **READY_FOR_PRODUCT_REVIEW**: 핵심 조작과 대표 반응·대화·성장 시연이 실제 앱에서 이어지고, 선언한 해당 환경의 성능 기준과 콘텐츠 확장·회귀 검사 및 필요한 비교 결과가 준비됨. 프레임 정지나 조작 불능이 남았는데 이 상태를 부여하지 않는다. 이는 출시/최종 재미 승인 아님.
- **BLOCKED_WITH_CHECKPOINT**: 환경·도구·필요 자산·권한 등으로 필수 증거를 확보하지 못함. 가능한 독립 작업을 끝내고 남은 차단과 재개 방법을 명시함.
- 재미 만족도와 최종 캐릭터 선택은 두 경우 모두 **USER_REVIEW_PENDING**으로 별도 표시한다. 사용자 평가가 들어오면 다음 반복 작업으로 이어간다.

최종 보고에는 실제 수정·구현 범위, 콘텐츠 범위, 실제 앱 증거, 성능 전후와 측정 한계, 저장/경제 보존, 후보 아트 상태, 모델 위임 확인 범위, 미완료 플랫폼/자산, branch/commit/push 상태를 포함한다.

‘테스트 N개 PASS’, ‘대사 수백 개’, ‘가짓수 수천 개’만으로 게임 개편 완료를 선언하지 않는다. 사용자가 실제로 플레이할 수 있는 장면과 비교 자료를 남긴 뒤, 재미와 외형에 대한 최종 선택은 사용자에게 돌려준다.
