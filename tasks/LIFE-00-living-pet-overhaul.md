# LIFE-00 — ‘돌아다니는 캐릭터’에서 ‘함께 사는 펫’으로

작성일: 2026-09-29  
작업 유형: 기존 아루콘의 플레이 경험 전면 개편  
실행 방식: **ASTRA_DIRECT — Astra가 설계·구현·디버깅·실행 확인을 직접 담당**  
목표 결과: **실제로 플레이 가능한 개편판 + 같은 빌드의 검증 증거**  
최종 재미·아트 승인: **USER_REVIEW_PENDING**

이 파일 전체가 이번 실행 지시다. ‘새 아이디어를 제안하고 끝내라’는 요청이 아니다. 현재 앱에서 구현하고 직접 실행해라. 기존 검증된 경제·저장·네이티브 기반을 보존하되, 재미를 가로막는 화면·행동·대사·연출 구조는 필요한 만큼 교체한다. 앱 전체를 지우고 새로 만들거나 이전 인계 ZIP으로 덮어쓰지 않는다.

## 0. 요청의 근거와 이번 변경의 효력

### 사용자가 직접 요청한 것
- 진짜 펫처럼 먼저 다가오고, 혼자 말도 걸고, 장난치고, 쉬고, 먹고, 배변하는 생활.
- 문장 두 개와 배회만 반복하지 않는 다양한 행동·표정·대사.
- 그때그때 다른 성격으로 바뀌는 것이 아니라, 함께 지내며 **하나의 개성이 완성되는 경험**.
- 키우는 재미, 상호작용하는 재미, 성장과 발견의 재미.
- 앞뒤로 도톰하고 둥근 모찌 체형, 자연스러운 뿔, 시크하지만 다정한 매력.
- 화면 전체를 방으로 쓰는 단순한 화면. 펫 가까이의 자연스러운 말풍선.
- 개발용 정보·이상한 말투·저장 안내 깜빡임·화면 깨짐·입력 정지의 해소.
- 강제 멀티모델 공정을 거치지 않고 Astra가 직접 품질을 책임지는 진행.

이하의 행동 목록, 수치, 콘텐츠 범위와 시험 방법은 위 요청을 구현하기 위해 이번에 제안하는 **개편판의 작업 기준**이다. 이미 구현된 사실이나 과거에 사용자가 승인한 숫자로 기록하지 않는다. 표현·타이밍의 되돌릴 수 있는 세부는 직접 선택하고 튜닝하되, 경제·개인정보·법률 정책의 변경 권한으로 확대하지 않는다.

### 문서 간 충돌 처리
- 이번 작업의 UX·행동·대사·체형·개발 방식은 이 문서가 FUN-00/FUN-01의 관련 지시를 갱신한다. 과거 결함과 유효한 회귀 검사는 계승한다.
- 이전의 ‘루트는 코딩 금지’, ‘Sol/Terra/Luna 위임 필수’, ‘독립 reviewer 필수’는 이번 작업에 적용하지 않는다. 자동 테스트와 실제 플레이 검증은 유지한다.
- 기존 ‘아트 변경 금지’는 이번에 요청한 체형·뿔·얼굴과 승인된 1차 방향의 검토용 자산 제작을 막지 않는다. 원본은 보존하고 최종 사용자 아트 승인은 별도로 둔다.
- ‘기본 화장실 제공·자동 청결’은 유지한다. 배변을 보여달라는 요청을 청소 숙제·유지비·자동화 철회로 해석하지 않는다.
- 현재 저장소의 최신 승인 SRS/DEC/config를 확인한다. 오래된 문서의 OPEN이나 예전 숫자로 되돌리지 않는다. 이번 개편과 무관한 결정은 바꾸지 않는다.
- TR55 등 트레이딩 프로젝트 문서는 이번 아루콘 작업의 근거가 아니다.

## 1. 최종 목표 — 숫자가 아니라 실제 장면

> 손대지 않아도 자기 생활을 하고, 함께 놀면 그 아이답게 반응하며,
> 다시 만났을 때 익숙한 버릇과 조금 달라진 모습을 발견하는 작은 친구.

‘살아 있다’는 것은 사용자가 느끼는 일관된 가상 펫의 표현이다. 실제 의식·감정·의존성을 가진 존재라고 주장하거나 사용자를 압박하지 않는다.

다음 다섯 경험을 하나의 앱에서 연결한다.

| 경험 | 실제로 보여야 할 결과 |
|---|---|
| 관찰하는 재미 | 아무것도 누르지 않아도 목적 있는 비이동 행동과 작은 생활 장면이 나온다. |
| 교감하는 재미 | 손에 기대기, 장난 응답, 선택 후 후속 행동이 즉시 화면에 나타난다. |
| 개성을 알아가는 재미 | 같은 사건에도 그 아이 특유의 거리감·말투·버릇이 반복해서 읽힌다. |
| 키우는 재미 | 확정된 성장에 따라 표현·행동·외형이 어떻게 달라지는지 보인다. |
| 내 방을 만드는 재미 | 가구와 장난감이 실제 생활 행동을 열고, 펫이 좋아하는 자리를 만든다. |

현재 문제를 덮는 토스트, 시스템 이름, 테스트 개수, 랜덤 문장 개수는 위 경험을 대신하지 못한다.

## 2. 착수와 직접 개발 권한

Astra가 현재 코드·자산·실행 화면을 직접 확인하고 필요한 설계·구현·시험을 수행한다. 이번 작업에서 새 서브에이전트를 생성하지 않는다. 이미 작업 중인 에이전트가 있으면 안전한 작은 단위에서 변경을 인계받고 병렬 쓰기를 정리한다. 자체 검토는 SELF_REVIEW로 기록하며 독립 검토라고 부르지 않는다.

현재 Git HEAD/branch/dirty 상태, 실제 설치 앱의 build identifier, Debug/Release, 연결된 Metro, OS/runtime, 화면 크기와 글자 배율을 확인한다. 과거 보고의 SHA를 현재 상태로 가정하거나 reset하지 않는다.

루트·관련 하위 AGENTS.md, 최신 실행 보고/재개 안내, SRS/DEC의 필요한 부분, 기존 FUN 구현과 실제 자산을 읽는다. 전체 문서·과거 패키지를 매번 전부 읽지 않는다. 운영 규칙과 충돌하는 위임 지시만 최소 수정하고, 상세 요구는 이 작업 문서에 둔다. 사용자 전역 설정·권한은 바꾸지 않는다.

**첫 구현 목표는 아래 §3의 한 번의 연결된 플레이다.** 여러 시스템 문서와 클래스부터 모두 만든 뒤 마지막에 화면을 연결하는 방식은 피한다. 짧은 실행 계획을 세우고 곧바로 현재 앱에서 시작한다. 단계별 승인 대기로 멈추지 않되, 실패한 핵심 흐름 위에 콘텐츠만 쌓지 않는다.

## 3. 먼저 완성할 대표 플레이 — ‘공은 그냥 여기 둔 거야’

아래 장면을 정상 사용자 입력과 실제 화면에서 연결해라. 신규 격리 체험 프로필에는 공·쿠션·기본 화장실·시연용 먹이가 준비되어 있어야 한다. 기존 일반 저장에 재화나 가구를 몰래 지급하지 않는다.

1. 깨끗한 방에 들어가면 펫이 시선을 주고 귀·몸을 작게 반응시킨다. 화면에는 큰 상태 카드나 개발 용어가 없다.
2. 잠시 관찰하면 펫이 몸을 풀거나 공을 살펴본다. 이어 공을 사용자 쪽으로 굴리고 기다린다. 일정 간격으로 좌표만 바꾸는 배회로 대체하지 않는다.
3. 츤데레 아이가 짧게 ‘이거, 굴러왔네.’라고 말한다. 기본 표정은 무심해도 공을 기다리는 시선과 앞발은 목적을 보여준다.
4. 사용자가 공을 굴리면 펫이 시선→방향 전환→접근→앞발로 다루기→다시 가져오기/굴리기 순서로 반응한다. 다시 시작하면 속도·방향·짧은 장난이 달라진다.
5. 사용자가 펫을 누르고 쓰다듬으면 몸이 말캉하게 눌리고 손 쪽으로 기댄다. 손을 떼면 복원 후 추가 반응이 나온다. 저장 알림이 주 반응이 되어서는 안 된다.
6. 쉬자는 선택을 하면 공을 옆으로 두고 쿠션에 간다. ‘그럼 잠깐만.’ 같은 짧은 말과 몸을 묻는 행동이 이어진다. 대화 중에도 호흡·눈·귀와 취소 가능한 입력은 살아 있다.
7. 다음 교감에서는 방금 공놀이했다는 실제 경험이 반응에 반영된다. 영구적으로 공만 고르는 상태는 만들지 않는다.
8. 기록을 열었다 닫아도 방과 입력이 복구된다. 앱을 다시 실행해도 개체명·실제 상태·필요한 최근 기억은 유지된다.

이 장면을 먼저 완성하되 이것 하나를 전체 개편 완료로 보고하지 않는다. 그다음 다음 절의 생활·놀이·성장으로 확장한다.

## 4. 방 화면을 제품 화면으로 교체

### 4.1 방과 최소 UI
- 화면 전체가 방이다. 위·아래 큰 흰 카드와 촘촘한 갈색 버튼 줄을 기본 화면에서 걷어낸다.
- 상단은 사용자가 지은 이름 한 번과 작은 메뉴 정도로 시작한다. 재화·성장 요약은 필요한 곳에 작게, 상세 수치는 별도 패널에 둔다.
- 하단 상시 동작은 ‘놀기 / 먹이 / 꾸미기’ 등 최대 세 묶음을 기본 후보로 삼는다. 실제 사용성을 보고 동등하게 단순한 구성으로 조정할 수 있다. 청소는 배설물, 쉬기는 쿠션, 교감은 펫과 직접 연결하고 접근성용 대체 조작은 메뉴에 둔다.
- 기록·성격 카드·성장 상세·설정·체험 도구는 필요할 때 열고 닫는다. 투명 overlay가 방 전체 입력을 먹거나 닫기 입력이 바닥으로 관통하지 않는다.
- 펫은 작은 크기와 넓은 이동 공간을 유지하되 표정이 읽혀야 한다. 교감 때 선택적인 짧은 카메라 접근은 가능하나 갑자기 확대하거나 원래 위치를 잃지 않는다. 동작 줄이기에서는 카메라 움직임도 줄인다.

### 4.2 이름·개발 표시·체험 모드
- ‘Sim콘 · 아루콘 · 함께 있는 중’, SOURCE_SYNTHETIC, 내부 상태 enum, ‘수치 닫기’, ‘합성 도구’는 주 화면의 기본 표현으로 사용하지 않는다.
- 개체명·형태·성격은 별도 데이터다. 공통형은 아루콘, 1차 이름은 말루·모노·피코·몽글이다. 형태·성격·이름을 한 줄로 상시 이어붙이지 않는다.
- Sim이 자동 생성한 fixture 이름인지 사용자가 실제 입력한 이름인지 확인한다. 사용자 이름을 일괄 치환하거나 DB를 초기화하지 않는다. 새 체험에서는 이름을 지을 수 있게 하고 미입력은 ‘아루콘’으로 소개한다.
- 건강 연결 OFF와 합성 데이터라는 사실을 숨기지 않는다. 시작 안내와 설정에 ‘체험 모드 — 실제 걸음·수면은 연결하지 않았어요’를 명확히 표시하고 주 화면에는 작은 ‘체험’ 표시만 둔다. 체험 도구는 메뉴 안으로 이동한다.
- 새 체험 프로필은 첫 10분에 굶은 펫과 빈 상점 버튼만 보지 않도록 충분한 **체험용** 먹이와 필요한 놀이 사물을 제공한다. 실제 건강 보상으로 표시하지 않고 일반 저장·계정과 분리한다.
- 체험 자원을 쓰는 먹이·식사·구매는 동일한 게임 서비스 경로로 처리한다. 디버그에서만 성공하는 별도 가짜 플레이를 만들지 않는다.

### 4.3 화면 깨짐
제공된 스크린샷은 UI 카드가 방을 덮고 펫보다 설명이 강조되는 문제의 참고다. 렌더가 ‘깨져 보이는’ 정확한 원인은 미확정이다. 잘림·레이아웃·낮은 렌더 해상도·aliasing·재질·조명·카메라·좌표 오류를 실제 화면에서 구분한다. 단순 배경색 변경이나 펫 확대를 해결로 간주하지 않는다.

UI overlay가 바뀌어도 방/GLView 크기·컨텍스트·컨트롤러가 불필요하게 재생성되지 않게 한다. 작은 화면·큰 글자·키보드·모달·대화에서 읽기/닫기/펫 조작이 유지되어야 한다.

## 5. 하나의 개성 — 안정된 성격 + 취향 + 실제 기억

상태값과 인터페이스 이름은 현재 구조에 맞게 선택한다. 아래 책임 때문에 서버·패키지·DB를 여러 개 새로 만들 필요는 없다.

| 층 | 책임 | 제한 |
|---|---|---|
| 기본 성격 | 접근 방식, 장난 스타일, 시선·말투·애정 표현의 일관성 | 현재 personality를 보존한다. 기분에 따라 성격 ID가 바뀌지 않는다. |
| 순간 표현 | 관심, 기대, 만족, 놀람, 쑥스러움, 졸림 등의 짧은 전환 | 기존 Mood·체력·배고픔의 다른 계산 원천이 아니다. |
| 취향·버릇 | 쉬는 자리, 좋아하는 놀이 방식, 대표 몸짓 | 실제 경험에 근거하고 경제적 우열이나 강제 훈련 숙제로 만들지 않는다. |
| 교감 기억 | 방금 한 놀이, 보여준 장면, 발견한 반응, 함께한 가구 사용 | 관찰하지 않은 사건·외부 앱·카메라·마이크 정보를 꾸미지 않는다. |
| 성장 표현 | 승인된 성장에 따른 새 자세·놀이 방식·형태 | 기존 성장·진화 산식을 변경하거나 클릭 EXP를 추가하지 않는다. |

### 5.1 대표 개성: ‘새침하지만 먼저 챙기는 장난꾸러기’
주인공 츤데레의 중심은 까칠한 문장보다 **겉과 행동의 작고 다정한 차이**다.
- 먼저 다가오되 공을 핑계 삼는다.
- 쳐다보는 건 피하지만 몸은 손에 기대 놓는다.
- 공을 가져다주고는 자기 것이 아니라는 듯 다른 곳을 본다.
- 엉뚱한 작은 실수를 하면 잠깐 태연한 척한다.
- 편안해질수록 표현이 자연스러워지되 다른 성격으로 교체되지는 않는다.

일관성 비교용 솔직한 아이는 같은 애정을 더 빠른 눈맞춤·기대기·제안으로 표현한다. 여러 성격을 동시에 새로 만들기보다 이 두 스타일의 실제 차이를 먼저 완성한다. 최종 16유형이나 인간 MBTI 판정을 이번에 추가하지 않는다.

### 5.2 취향이 쌓이는 방식
서로 다른 실제 경험이 어느 정도 누적될 때 약한 선호를 만들고, 같은 입력 연타만으로 곧바로 고정시키지 않는다. 별도 호감도 바·외로움 바·스트레스 관리 항목을 만들지 않는다. 접속하지 않았다고 선호나 애정을 깎지 않는다.

경험의 변화는 ‘최근에는 공을 앞에 가져다 놓네’, ‘저 쿠션에 자주 눕네’처럼 행동으로 보인다. 기록에 적기만 하고 실제 행동 선택이 바뀌지 않으면 미구현이다. 저장 시 petId·schemaVersion·크기 제한을 두고, 경제 원장과 성격 기억의 실패 복구 정책을 구분한다.

## 6. 혼자 살아가는 생활 — 목적·시작·과정·끝이 있는 행동

단순 interval에서 랜덤 좌표·대사를 선택하는 구조를 넘어서라. 현재 상태·사물·최근 경험에 맞는 의도를 고르고, 행동 중인 의도는 완료/취소까지 유지한다. 작은 상태 머신, 점수 기반 선택 등 구현 방식은 스스로 정하되 디버그에서 이유를 설명할 수 있어야 한다.

하나의 행동 계약에는 최소한 **전제 조건 / 대상 사물·장소 / 접근 / 실제 수행 / 결과 / 취소·실패 복구**가 있어야 한다. 없는 가구로 이동하거나 실제로 먹지 않고 먹었다고 말하지 않는다.

### 6.1 이번 개편에서 구현할 생활 장면
다음은 새 제작 요구다. enum 항목이나 동일한 배회+다른 대사로 세지 말고 실제 다른 몸짓과 사물 상호작용으로 만든다.

| 장면 | 화면에 나타날 행동과 후속 결과 |
|---|---|
| 사용자를 알아봄 | 잠깐 시선을 주고 귀/몸을 기울이며 인사. 카메라로 사람의 존재를 추적하지 않는다. |
| 주변 살피기 | 창·식물·소품을 바라보고 고개/몸 방향을 바꾼 뒤 원래 생활로 돌아온다. |
| 몸 풀기 | 늘어남→작게 퍼짐→몸 정돈. 순간 찌그러짐 하나로 끝내지 않는다. |
| 공 살펴보기 | 냄새 맡는 듯 가까이 보고 앞발로 툭 건드린다. |
| 놀이 제안 | 공을 사용자 쪽으로 보내고 기다림. 수락하면 놀이, 무응답이면 압박 없이 다른 생활. |
| 혼자 장난 | 공이 굴러간 방향을 따라가거나 한 바퀴 돌아 확인한다. |
| 자리 고르기 | 두 휴식 위치를 살펴보고 앉음. 선호가 있어도 항상 같은 자리로 고정하지 않는다. |
| 쿠션 생활 | 앞발로 눌러보기→몸 묻기→자세 바꾸기. |
| 졸음 신호 | 느린 눈깜빡임/꾸벅임. 실제 게임 수면 진입·회복은 기존 승인 명령과 분리한다. |
| 식사 신호 | 실제 허기·먹이 가용성에 맞게 그릇 쪽을 보고 행동. 배부른데 배고프다고 하지 않는다. |
| 식사 | 가용 먹이 확인→접근→섭취 연출→입 정리/만족 반응. 정산은 기존 계약대로 한 번. |
| 배변·화장실 | 승인된 배설 사건을 근거로 화장실 이동·귀여운 가림 연출·나와 몸 정돈. 자세한 배설 묘사는 불필요하다. |
| 사용자 곁에 있기 | 입력 가능한 화면 쪽에 다가와 앉거나 몸을 기댐. 항상 말을 걸지 않는다. |
| 작은 해프닝 | 공을 잡으려다 살짝 헛디딤→민망한 표정→태연하게 정돈. 파괴·재화 손실 없음. |
| 성장 발견 | 새 동작을 해보고 스스로 놀라거나 같은 놀이를 다른 자세로 해봄. 실제 성장 해금과 연결한다. |

### 6.2 생활의 리듬과 반응 우선순위
- 쉬는 시간과 움직이는 시간을 섞는다. 펫을 계속 뛰거나 말하게 만들어 생동감을 흉내내지 않는다.
- 표현용 행동 스케줄러는 실제 도메인 정산 시계와 별개다. 하루를 몇 분으로 압축하거나 허기·배설 주기를 몰래 단축하지 않는다.
- 자율 제안은 깨어 있고, 필요한 사물이 있고, 사용자 조작·대화·식사에 방해되지 않을 때 나온다.
- 제안을 무시하면 스스로 다른 활동으로 전환한다. 같은 제안을 연속해서 재촉하거나 관계 수치를 깎지 않는다.
- 기본 후보 목표: 신규 깨어 있는 체험에서 2분 동안 비이동 행동을 3계열 이상 관찰하고, 약 45~90초 안에 1회의 자연스러운 놀이/교감 제안을 만난다. 이것은 새 **체험용 표현 튜닝 목표**이며 식사/배변 타이머가 아니다. 영구 대본 순서로 맞추지 말고 장면 조건에 맞춰 변동시키며 실제 설정을 기록한다.
- 과도한 말 걸기를 막기 위해 자동 말풍선은 초기 조정안으로 최소 20초 정도 간격을 두고, 선택 대화 종료 뒤에는 더 쉬게 한다. 사용자 요청 응답·중요 오류에는 이 간격을 강제하지 않는다. 정확한 값은 표현 config에서 조정 가능하다.

## 7. 함께 노는 재미 — 세 가지 완성된 짧은 놀이

모든 놀이에 시작·사용자 입력·펫 행동·마무리·취소가 존재해야 한다. 버튼을 누른 뒤 반응 영상만 보는 세 가지가 아니라 실제 입력 방식과 후속 행동이 달라야 한다.

### A. 공 굴려주고 받기
사용자가 바닥 방향이나 공을 조작하면 펫이 따라보고 찾아가 돌려준다. 츤데레는 잠깐 공을 앞발로 붙들거나 다른 쪽으로 툭 보내는 작은 장난을 칠 수 있다. 실제 공 위치·속도와 펫의 접촉이 맞아야 하며 공이 벽/가구 뒤로 사라지면 안전하게 복구한다. 사물이 없는 경우 허공에서 실행하지 않는다.

### B. 손가락 까꿍
사용자가 화면의 좌/우 작은 가림 영역이나 표시된 손 위치를 선택하면 펫이 그쪽을 엿보고, 나타났을 때 놀람/태연한 척/다시 확인을 한다. 카메라나 얼굴인식은 사용하지 않는다. 압박 있는 타이밍 점수나 실패 벌점 없이, 무응답이면 자연스럽게 끝난다.

### C. 자세 따라 하기·하이파이브
사용자가 제시한 두세 가지 간단한 몸짓에 펫이 앞발 들기·몸 기울이기 등으로 응답한다. 처음부터 완벽하지 않은 귀여운 차이와 경험 후 편안해진 연기를 표현한다. 반복 클릭으로 EXP나 유료 이득을 주지 않는다.

새 가벼운 교감은 자원 중립으로 한다. 이미 승인된 적극적 놀이에 체력 비용이 있다면 해당 명령의 기존 계약을 확인해 유지하고, 자율 연출·클립 반복·프레임마다 비용을 만들지 않는다. 놀이를 강제로 해야 성장·수면·성격이 좋아지는 구조는 추가하지 않는다.

무료 손 교감 두 종류는 빈 방에서도 가능하게 한다. 공놀이 등 사물 기반 콘텐츠는 기존 소유·설치 정책을 지킨다. 신규 체험에 필요한 사물을 넣는 것은 체험 데이터에서만 한다.

## 8. 배변과 청소 — 자동화 이후에도 생활은 보이게

이 요구는 기본 화장실을 없애라는 뜻이 아니다. 화장실이 자동으로 청결을 유지하더라도 펫이 화장실을 쓰는 생활은 보여야 한다.

- 기존 배설·자동 청결의 확정 사건이나 안전한 표시용 projection을 사용한다. 렌더러가 배설물 수를 직접 증가·감소시키지 않는다.
- 사건별 표시 ID로 애니메이션 재생과 경제/청결 정산을 분리한다. 재실행·중단·리플레이에서 배설/정산이 중복되지 않는다.
- 전경에서는 귀여운 준비 동작→시설 이용→나오기→몸 정돈/짧은 반응을 보여준다. 순서가 막히면 상태를 훼손하지 않고 연출만 복구한다.
- 부재 중 사건을 수십 번 강제 재생하거나 실제로 보지 않은 행동을 관찰 일지로 꾸미지 않는다.
- 배설물이 실제로 남는 기존/격리 시나리오에서는 대상 터치→치움→펫 반응이 작동한다. 대상이 없으면 정상 상태임을 차분하게 알려준다.
- 기본 화장실에 유지비·새로운 청소 미니게임·필수 보충재를 붙이지 않는다. 건강 행동 부족을 배변·질병으로 벌주지 않는다.
- 배변 시험 때문에 일반 저장 시간을 조작하지 않는다. 별도 ‘생활 장면 체험’에서 배설 사건이 가까운 격리 상태를 제공하고 동일한 코드 경로를 검증한다.

## 9. 자연스러운 대사와 말풍선

### 9.1 말투 원칙
펫 대사는 짧고 자연스러운 구어체다. 시스템 처리 문장, 번역체, 길고 반복적인 말줄임표, 매번 ‘흥’이나 ‘싫진 않지만’으로 끝나는 츤데레 공식은 줄인다. 까칠함은 주로 시선·타이밍·행동 반전으로 표현한다.

새 콘텐츠 예시 — 아래 문구만 순서대로 반복 구현하지 않는다:

| 상황 | 츤데레 후보 | 함께 나와야 하는 행동 |
|---|---|---|
| 공을 먼저 보냄 | ‘이거, 굴러왔네.’ | 이미 펫이 밀어놓고 딴청 |
| 다른 방향으로 공을 다시 보냄 | ‘이번엔 저쪽.’ | 시선과 앞발이 목적지로 |
| 쓰다듬기 | ‘거기. 조금만.’ | 고개보다 몸이 먼저 기대기 |
| 공을 잠깐 붙잡음 | ‘잠깐. 내 차례.’ | 공을 발밑에 둔 뒤 다시 건네기 |
| 쿠션으로 옮김 | ‘여기가 더 폭신해.’ | 직접 쿠션을 눌러 자리 잡기 |
| 함께 쉬자는 선택 | ‘그럼 잠깐만.’ | 몸을 낮추고 편안히 앉기 |
| 헛발질 후 | ‘못 본 걸로 해.’ | 태연한 얼굴로 몸 정돈 |
| 이미 경험한 놀이를 제안 | ‘아까 그거, 한 번 더?’ | 실제 최근에 완료한 놀이만 참조 |

접속·운동·돌봄을 탓하는 ‘늦었잖아’, ‘왜 안 왔어’, ‘너 없으면 못 살아’는 넣지 않는다. 사람과의 관계를 경쟁시키거나 외로움으로 붙잡지 않는다. 대사가 없는 시선·귀·소리 반응도 충분히 제작한다.

### 9.2 콘텐츠 범위와 반복 관리
- 먼저 대표 플레이를 연결한 뒤 생활 상황 12개 범주 이상을 채운다: 인사, 직접 접촉, 손을 뗀 뒤, 공놀이, 까꿍, 몸짓 놀이, 식사, 휴식/깨기, 화장실, 가구 탐색, 함께 쉼, 성장 발견.
- 이번 콘텐츠 최소 제작 목표는 의미가 다른 짧은 발화 약 60개와 말 없이 표현하는 장면 12개다. 두 성격 모두 주요 상황에서 고유한 반응을 갖고, 새 문장만으로 새 애니메이션이 생긴다고 세지 않는다.
- 60개는 완성도의 증거가 아니라 두 문장뿐인 결과를 막는 작업량 하한이다. 모든 발화에는 도달 가능한 조건과 대응 행동이 있어야 한다. 의미 없는 동의어·어미 변형으로 숫자를 채우지 않는다.
- 동일 상황에 적격 후보가 4개 이상 있으면 최근 3개 발화를 우선 제외한다. 대사가 다른데 행동이 동일한 계열도 별도로 반복 관리한다. 후보 부족 시 편안한 비언어 반응을 허용하되, 부족 원인을 개발 진단에 기록한다.
- 발화가 표시된 시점의 최근 사용과, 행동이 완료된 시점의 경험 기억을 구분한다. 중단한 장면을 매번 처음 후보처럼 돌리지 않는다.
- 후보/탈락 이유, sceneId/lineId, 최근 이력, fallback 사용 여부는 개발 진단에만 둔다. 초기화·고정 시드·전역 busy 때문에 두 줄짜리 fallback만 도는지 실제 일반 입력에서 검사한다.
- 무한 생성은 약속하지 않는다. 익숙한 대표 버릇은 남고 단기 몰림은 줄어야 한다. 외부 LLM 호출이나 무료 입력형 채팅 API를 이번 범위에 추가하지 않는다.

### 9.3 말풍선 계약
펫의 머리 옆을 따라가는 작은 말풍선을 사용한다. 꼬리 방향 등으로 화자를 분명히 하고 얼굴·뿔·귀를 가리지 않는다. 대화창 안에 ‘대사 적게 / 닫기’ 같은 설정 툴바를 상시 넣지 않는다. 작은 닫기·진행 수단과 접근성 설명은 유지한다.

동시에 한 개의 주 말풍선만 표시하고, 선택형 대화에만 최대 두세 답을 붙인다. 읽는 동안 호흡·눈·귀는 살아 있고, 모달이 아닌 말풍선은 전역 입력을 잠그지 않는다. 실제 walking을 잠깐 멈추는 연기와 렌더 스레드 정지는 구분한다.

표시 시간은 길이와 사용자 설정에 맞추고 선택 대화는 무응답을 압박하지 않는다. 오래된 대사는 큐에 계속 쌓지 않는다. 대화 닫기·패널 열기·앱 전환 후의 취소/복구가 명확해야 한다. 접근성 큰 글자에서 말풍선 높이를 측정해 안전 영역 안으로 옮긴다.

## 10. 키우는 재미 — 경험의 흔적과 성장 결과

### 10.1 성장과 관계를 혼동하지 않기
먹이 섭취에서만 발생하는 기존 EXP·성장·진화 규칙을 유지한다. 새 놀이·대화·관찰은 행동 기억과 발견에만 영향을 준다. 자동급식과 직접급식의 경제적 동등성, 수면 보너스와 재화 비회수 정책을 보존한다.

행동을 반복하면 관계가 ‘좋아진 점수’를 파밍하는 대신, **이 아이가 편하게 하는 몸짓과 자주 택하는 놀이를 알아가는 변화**를 보여준다. 부재 중 애정 감소·출석 streak·기간 한정 희귀 반응 강요를 만들지 않는다.

### 10.2 실제 성장의 표현
- 섭취가 확정되면 과하지 않은 만족 반응과 필요한 성장 안내를 연결한다. 아직 커밋되지 않은 보상을 화면만 먼저 확정하지 않는다.
- 성장 단계의 변화는 자세·말투·기존 놀이를 응용하는 방식·외형으로 표현한다. 숫자만 올리거나 ‘성장했어요’라는 문구만 내지 않는다.
- 같은 개체의 이름·성격·버릇·사물 선호는 진화 뒤에도 이어진다.
- 현재 단계와 다음에 발견할 변화는 선택적인 ‘우리 아이’ 패널에서 간단히 보여준다. 실제 없거나 미승인인 콘텐츠를 곧 열린다고 광고하지 않는다.
- 도감은 숙제가 아니라 이미 본 몸짓과 장면을 다시 떠올리는 작은 앨범이다. 미발견 항목을 거대한 수집 그리드·희귀도·일일 과제로 전시하지 않는다. 리플레이는 보상과 기억을 다시 생성하지 않는다.

### 10.3 1차 진화 형태
아기 아루콘, 말루(낮고 넓음), 모노(세로형·비대칭 귀), 피코(쫑긋한 귀·활동적인 자세), 몽글(둥근 귀·몽글한 굴곡)의 승인된 방향과 현재 분기 계약을 확인한다. 실제 자산이 있으면 연결하고, 없다면 기준 시트를 따르는 **게임용 초안 자산**을 별도 제작해 분기를 비교한다. 공통 애니메이션/변형 인터페이스는 재사용하되 동일 모델을 단순 색 변경·축 늘리기로 4종이라고 하지 않는다.

우선 아기형과 생활 플레이를 제대로 만들고 1차 초안을 확장한다. 도구나 아트 제작으로 막히면 ART_BLOCKED로 분리한다. 같은 공통 GLB fallback을 쓰면서 진화 외형 완료라고 보고하지 않는다. 2차 16성향·번식·소셜은 이번 범위 밖이다.

## 11. 아기 캐릭터 v3 — 포동한 몸과 분명한 인상

현재 앱의 정면뿐 아니라 측면·뒷면·작은 화면에서 다시 제작한다. 제시된 2D 시트는 형태 참고이지 실제 runtime 품질의 증거가 아니다.

- 이마에서 배·등·엉덩이까지 하나의 둥근 덩어리로 이어진다. 화면에서 무작정 키우지 말고 앞뒤 두께를 늘려 입체적으로 포동하게 한다.
- 뿔은 정중앙에 꽂은 긴 콘처럼 보이지 않도록 둥근 이마와 연결되는 짧고 둥근 실루엣을 다듬는다. 정확한 위치·각도는 정면/측면/3분의4 시점으로 비교한다.
- 따뜻한 크림 몸, 또렷한 작은 눈과 입, 보송한 모찌 느낌. 과노출로 얼굴이 지워지거나 플라스틱 광택으로 바뀌지 않게 한다.
- 기본 시크함과 만족·호기심·놀람·장난기·쑥스러움·졸림·민망함을 작은 게임 크기에서도 구분한다. 눈 텍스처만 바꾸지 말고 시선·귀·몸 자세를 함께 사용한다.
- 발 디딤·방향전환·멈춤 반동을 연결한다. 눌림과 복원은 앞뒤 볼륨을 살리되 고무판처럼 납작해지거나 얼굴이 분리되지 않는다.
- 사운드·햅틱은 선택적 보조다. 작은 소리나 무음 동작만으로도 표현이 이해되어야 하며 음성 합성·마이크 권한은 추가하지 않는다.

원본을 보존하고 **하나의 추천 개편 후보**를 검토용 빌드 기본값으로 연결해라. 외형 변화를 피하려고 이전 fallback만 보여주거나 비교 스위치를 주 화면에 늘어놓지 않는다. 대안이 유의미하면 개발용 비교에서 한 후보만 추가한다. 후보를 실제 사용자 최종 승인 아트로 기록하지 않는다.

편집 가능한 소스, runtime 자산, 변형/애니메이션 연결, 게임 화면 비교가 함께 있어야 한다. 사용할 수 없는 제작 도구가 있으면 범위와 대체 가능한 작업을 보고하고 정지 시안만으로 모델 납품 완료를 주장하지 않는다.

## 12. 구현 원칙 — 하나의 흐름으로 연결하고, 장부와는 분리

현재 도메인·저장 서비스는 보존하고 표현 레이어를 개편한다. 권장 책임 흐름은 다음이며 특정 라이브러리 채택을 강제하지 않는다.

현재 게임 상태 / 방 사물 / 사용자 입력 / 최근 실제 경험
                 ↓
       펫의 다음 의도 선택과 유지
                 ↓
    접근·행동·표정·대사·후속 반응 시퀀스
         ↙                       ↘
 필요한 게임 명령              표현·경험 기록
         ↓                       ↓
 기존 검증된 서비스·트랜잭션       제한된 기억·콘텐츠 이력

- 행동 선택기는 일관된 한 주체로 유지한다. React 렌더마다 성격·기억·난수 시드·진행 중 의도를 재초기화하지 않는다.
- 허기 등 필요를 읽고 식사를 제안할 수 있지만, 자동 섭취는 설치/동의/먹이/수면 조건을 통과한 기존 서비스만 실행한다. 연출 완료가 새 보상 생성 경로가 되지 않는다.
- 표정·호흡·시선은 대화 상태와 공존한다. 전역 busy 하나로 대화·렌더·저장·터치를 전부 잠그지 않는다.
- 입력 우선순위와 취소 토큰을 명확히 한다. 오래된 콜백이 끝난 대화·취소된 놀이를 되살리지 않는다. 빠른 연타는 의도를 합치거나 취소해 안전하게 처리한다.
- 버튼 쓰다듬기와 직접 접촉은 동일 서비스에 도달하되 시작/유지/해제 의미를 구분한다. 성공 설명만 출력하지 않는다.
- 정상적인 교감 저장은 조용히 한다. 실제 쓰기 실패는 보상 성공으로 숨기지 않고 안정된 안내로 처리한다. 표현 기억 저장이 실패해도 일반 접촉까지 영구 차단하지 않는다.
- 사건 중심 선택·제한된 큐·작은 이력을 사용한다. 매 프레임 전체 카탈로그 조회, DB 쓰기, 깊은 JSON 복사, React root state 갱신을 하지 않는다.
- 앱 비활성 상태에서는 렌더와 장식 시퀀스를 적절히 정지하고, 복귀 시 옛 말풍선과 이벤트를 폭주 재생하지 않는다. 부재 정산은 기존 엔진에 맡긴다.
- 기존 네이티브 등록·Hermes 호환·SQLite migration·플랫폼 fixture·App Group 수정을 보존한다. CNG가 생성하는 폴더만 임시 수정해 다음 prebuild에서 사라지는 해결을 만들지 않는다.

## 13. 성능과 조작 — 재미 검증의 입장 조건

먼저 화면 깨짐, 기록 닫힘, 직접/버튼 접촉, 대화 중 freeze를 재현하고 고친다. 3Hz가 캡처·모션 샘플·프레임 제한·실제 표시 중 무엇인지 확인하고 일반 플레이에 남은 진단 제한을 제거한다. 무조건 배속하거나 단색 대체 모델로 바꿔 해결하지 않는다.

이번 개편판의 새 제안 목표: **일반 모드 60fps 지향, 대표 검토 환경에서 안정적인 30fps 수준을 최소 품질 목표**로 둔다. 유효 입력 후 첫 시각 반응은 p95 100ms 이내를 초기 목표로 측정한다. 이는 사용자 측정값·실기기 출시 사양이 아니며, 장치·측정 방법과 함께 선언할 개발 목표다. 기존 승인 성능 요구가 더 엄격하면 그것을 유지한다.

평균 FPS 하나로 통과시키지 않는다. 프레임 간격 분포·긴 멈춤·대화 시작/종료의 입력 지연·draw/변형/레이아웃/DB 비용을 구분한다. JS callback 계측을 실제 GPU 표시나 물리 터치 지연이라고 부르지 않는다. 영상 인코딩 FPS는 앱 FPS가 아니다.

같은 Release 설정·장면·장치에서 전후 측정한다. GPU/드라이버나 실제 기기가 필요해 못 측정하는 항목은 PERFORMANCE_BLOCKED/NOT_RUN으로 남긴다. 저속 환경에서 기능만 확인할 수는 있지만 부드러운 플레이 준비 완료라고 하지 않는다.

저비용 렌더가 필요하면 보조 효과·중복 draw·해상도·메모리·프레임 예약을 먼저 다듬고 정상 설정과 비교한다. 얼굴·핵심 몸짓·말캉함을 버리지 않는다. 동작 줄이기는 별도 사용자 선택이며 일반 모드의 성능 실패를 숨기는 기본값이 아니다.

## 14. 검증 — 연속 플레이와 콘텐츠 도달성

선택된 소수 scene을 진단 메뉴에서 강제 호출하는 시험은 시스템 테스트다. 사용자가 만나는 정상 경로를 대체하지 못한다. 새 체험 저장과 기존 저장을 각각 확인하고 실패를 DB 삭제로 숨기지 않는다.

| L20 | Release 전후 성능·동작 줄이기 on/off | 환경과 측정 한계, freeze 여부, 실제 설정 복원 명시 |
| L21 | DB 실패·손상·취소·경제 회귀 | 원자성/중복 방지/데이터 보존, 실패와 성공 안내 구분 |
| L22 | 플랫폼별 실행과 Git | iOS/Android/실기기 분리, 재현 가능한 소스·lockfile·자산 추적 |

반복 검사는 고정 시드 단위 검사와 일반 앱 입력을 모두 사용한다. 시험 시나리오의 정해진 순서를 앱 안에 숨겨 넣거나 시험에서만 대사 선택을 다르게 하지 않는다. 모든 지표의 통과/실패뿐 아니라 플레이 맥락을 함께 검토한다.

### 14.2 증거 세트
- 현재 코드로 설치한 앱의 build/commit/환경을 명시한다. dirty build면 diff 식별과 커밋 후 대응을 남긴다. 오래된 설치본·Metro를 최신 결과로 다루지 않는다.
- **8~10분 연속 플레이 영상 1개**: 무입력 관찰, 펫의 제안, 놀이 3종, 쓰다듬기, 대화, 기록 닫기, 재접촉. 정상 속도이며 실패 구간을 잘라 숨기지 않는다.
- **별도 생활·성장 시험**: 일반 시간으로 기다리기 어려운 배설·성장 전후는 격리 시나리오임을 표시하고 같은 로직·연출 경로로 확인한다.
- 캐릭터 전후의 동일 카메라 캡처/짧은 동작 비교와 화면 크기별 UI 비교.
- 간결한 선택 trace로 상황·후보·선택 이유·중단/완료·기억 갱신을 연결한다. 개별 사적 데이터나 비밀을 로그에 남기지 않는다.
- 필요한 자동 테스트·lint/typecheck·현재 플랫폼 build를 수행한다. 작은 문구 수정마다 전체 스위트를 반복하지 말고 통합 시 필요한 회귀를 충족한다.

실제 화면/입력 접근이 없거나 호스트가 잠기면 그 검증은 BLOCKED다. 콘솔·상태값·정지 캡처만 보고 모션 PASS로 표시하지 않는다. SELF_REVIEW의 플레이 품질 판단과 사용자 최종 재미 평가는 별개다.

## 15. 진행·체크포인트·종료

순서는 고정 공정이 아니라 실행 권장이다: **기본 조작/성능 정상화 → 대표 플레이 §3 완성 → 생활/놀이/대사 확장 → 기억/성장과 자산 연결 → 통합 플레이 점검**. 더 효과적인 의존 순서를 직접 선택할 수 있다. 문서나 첫 코드만 쓰고 돌아오지 않는다.

현재 허용된 개인 원격과 `feature/arucon-mobile-autonomous`를 확인한 뒤 그 브랜치의 논리적 checkpoint commit·일반 push를 허용한다. 사용자 변경·원본 자산·소스·lockfile을 보존한다. mobile/.git을 만들지 않고 실제 파일이 루트 Git으로 추적되게 한다. CNG 재생성 전 수작업 원본/저장 상태를 보호한다.

비밀·실제 DB·계정 캐시·node_modules·개인 로그·불필요한 큰 영상/빌드는 stage하지 않는다. 플레이 증거는 사용자에게 접근 가능한 로컬 위치를 보고하고, 승인 없이 외부 업로드하지 않는다. main/merge/force push/tag/release/배포/공유 변경/유료 서비스·계정 생성/실결제/실제 건강 읽기/관리자·OS 보안 변경은 이번 요청의 권한이 아니다.

핵심 코드와 콘텐츠가 결과물이다. 추가 문서는 기존 파일을 재사용하여 최소화한다. 적어도 다음 정보를 남긴다:
- `docs/living-pet-design.md` 또는 기존 대응 문서: 성격 규칙, 행동·대사·기억 계약, 실제 콘텐츠 도달표, 조정 가능한 표현값.
- `LIFE-00-REPORT.md`: 사용자 증상 전후, L01~L22, 실제 영상/빌드, 구현/콘텐츠/자산/성능/플랫폼별 미완료.
- 기존 status·gap·재개 안내의 관련 부분. 과거 기록을 지우지 말고 이번 회귀로 재오픈한 범위를 표시한다.

동일한 가설·명령을 무한 반복하지 않는다. 한도·권한·호스트 잠금을 우회하지 않고, 세션 중단 전에 diff·체크포인트·다음 한 작업을 보존한다. 한 플랫폼/아트가 막혀도 독립 가능한 부분은 계속한다. 사용자의 최종 만족을 추측하며 무한 자율 수정하지 않는다.

### 종료 상태
- **READY_FOR_LIVING_PET_REVIEW**: 해당 검토 환경의 핵심 조작·대표 생활/놀이·성격·대화·기억·성장 체험과 필요한 자산이 실제로 연결되고, 선언한 성능 기준과 회귀 검증을 충족함. 재미와 최종 아트는 USER_REVIEW_PENDING, 실기기 미검증은 별도 유지.
- **PARTIAL_WITH_BLOCKERS**: 구현 가능한 부분은 완료했으나 native 환경·실제 입력 도구·자산 등 때문에 필수 결과를 확인하지 못함. 어떤 목표가 남았는지 구체적으로 명시함.
- **REWORK_REQUIRED**: 화면 깨짐·대화 freeze·접촉 무반응·두 문장 반복 등 핵심 결함이 남음. 자동 검사 PASS 수로 덮지 않음.

최종 보고의 첫 부분에는 테스트 개수보다 **‘펫이 혼자 무엇을 하고, 함께 무엇을 할 수 있고, 지난 경험과 성장으로 무엇이 달라졌는지’**를 실제 장면과 증거로 설명한다. 이 프롬프트 작성·정적 검사·브라우저 데모를 아루콘 앱 구현 완료로 보고하지 않는다.
