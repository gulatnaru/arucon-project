## 1. 사용자 실제 피드백

- 아직 눈이 짝짝이처럼 보이는 순간이 있다.
- 장난·다정·도도의 구분이 뚜렷하지 않다.
- 행동이 어떤 감정을 의미하는지 알기 어렵다.
- 표정이 추가됐지만 반복적으로 보인다.
- 대사가 거의 없다.
- 방 디자인이 만족스럽지 않다.
- 귀가 감정과 상황에 맞게 움직였으면 한다.

이 피드백을 단순 미승인/PENDING으로만 남기지 말고 해당 제품 기준의 불충족으로 기록한다. 과거 기능 PASS를 삭제하지 않되 사용자 표현 평가를 덮어쓰지 않는다.

이번에는 성격 구조를 다시 만들거나 새 시스템 이름을 늘리지 않는다. 기존 두 발 아기, 세 성격과 기억을 유지하고 눈·귀·시선·몸짓·대사가 같은 의도를 전달하게 다듬는다. 넓고 단순한 방의 공간감도 별도 시안 하나로 검토한다.

## 2. 먼저 사실과 가설을 분리한다

이전 두 발 영상과 보고서는 이름/말풍선을 숨긴 비교 조건이다. 이 영상에 대사가 없는 것을 대사 코드 부재의 증거로 삼지 않는다. 반대로 사용자의 실제 일반 플레이에서 대사가 적다는 피드백도 무시하지 않는다. 정상 모드에서 표시 설정·발화 선택·표시 억제·대기열·취소를 따로 추적한다.

확인한 babyPose.ts에는 일반 playful 상태를 왼쪽 wink에 연결하는 분기와 주기적 귀 회전이 있다. 이것은 조사 지점이지 모든 비대칭/귀 문제의 확정 원인이 아니다. 현재 두 발 후보의 실제 bone/mesh 연결과 최종 출력 pose에서 확인한다.

최신 사용자 영상의 접촉 중에는 다정과 도도 모두 몸을 기울여 머무는 구간이 많고, 장난도 초반 반응 뒤 유지 자세의 변화가 작게 읽힌다. 느린 RAF, 입력 유지에 의한 정상 휴식, 의도적인 정지 연기, 표현 반복을 구분한다.

## 3. 눈: 기본 균형과 의도된 비대칭을 분리

1. 같은 정면·기본 시선·중립 표정에서 양쪽 눈/눈꺼풀/동공/하이라이트를 확인한다.
2. blink만, gaze만, 감정 shape key만, 혼합 상태를 분리해 원인을 좁힌다. 시선·머리 회전에 따른 원근 차이를 모델 비대칭으로 단정하지 않는다.
3. 의도하지 않은 shape key 잔류·누적·이중 적용·좌우 매핑 오류가 있는지 전환·취소·수면 복귀·프로필 전환에서 확인한다. 근거 없이 모든 가중치를 강제로 초기화해 정상 연기를 없애지 않는다.
4. 장난기라는 상태 전체를 긴 왼쪽 윙크와 동일시하지 않는다. 윙크가 필요한 장면에서만 짧게 발생하고 정상 두 눈으로 복귀해야 한다.
5. 의도된 윙크와 고개 갸웃은 유지한다. 모든 표정을 완전 대칭으로 만들거나 눈 자체를 사용자 승인 없이 전면 교체하지 않는다.
6. 실제 화면 크기와 같은 조건의 전/중/후 프레임으로 확인한다. 확대된 축소 영상만으로 geometry 파손을 확정하지 않는다.

## 4. 표현: 성격은 감정이 아니라 같은 감정을 표현하는 방식

세 성격 모두 호기심·기쁨·놀람·편안함을 표현할 수 있어야 한다. 장난은 늘 윙크, 다정은 늘 웃음, 도도는 늘 찡그림으로 고정하지 않는다. 아기는 공통적으로 호기심 많고 가벼운 장난기가 있으며 기질의 차이가 그 위에 나타난다.

기존 director에 짧은 표현 계약을 정리한다:
- 실제 사건/대상
- 이 순간 펫이 하려는 일
- 시선과 귀의 준비 반응
- 몸/발/얼굴의 핵심 행동
- 결과를 확인하는 표정 또는 짧은 말
- 편안한 유지 또는 원래 생활로 복귀

새 범용 감정 엔진이나 데이터베이스를 먼저 만들지 않는다. 현재 레이어에서 책임을 정리하고, 아래 장면을 실제 연결한 뒤 검증한다.

### 대표 장면 A: 같은 손을 제안하고 거두기

장난: 손을 바라보며 귀가 관심 방향을 향함 → 앞발로 가볍게 건드리고 몸을 옆으로 빼며 반응 확인 → 짧은 장난 표정 → 손이 남아 있으면 자연스러운 눈맞춤/편한 자세. 윙크를 오래 고정하지 않는다.

다정: 먼저 시선을 맞춤 → 손 쪽으로 볼 또는 옆구리를 실제로 맡기고 발 위치를 편하게 정리 → 귀와 눈의 긴장이 풀리는 모습 → 손을 거두면 잠깐 바라보고 스스로 생활 복귀. 손이 사라져도 애정 벌점·재촉·죄책감 표현 없음.

도도·호기심: 먼저 손과 대상을 살펴봄 → 몸은 비교적 세운 채 약간 옆으로 접근 → 짧게 접촉하고 눈/귀로 관심을 다시 확인 → 손을 거두면 원래 관심 대상으로 복귀. 다정의 재생 속도를 낮추는 것으로 대신하지 않는다.

위 문장은 제작용 대표 의도다. 매 입력마다 같은 고정 대본으로 돌리지 않는다. 현재 행동·실제 최근 경험·짧은 탭/유지/해제 조건에 맞게 선택·마무리한다. 장난을 모두 보려고 손을 20초 이상 붙잡아야 하는 구조를 만들지 않는다.

### 대표 장면 B: 기존 휴식 사물의 변화 알아보기

사물 이동을 직접 본 경우에는 옛 자리로 일부러 잘못 가지 않는다. 보지 못한 이동과 구분한다. 현재 위치가 최종 사실이며, 실제 관찰 경험을 이용한다. 같은 발견 상황에서 세 기질이 살피기·접근·사용·사용자 확인을 다르게 표현하는지 검토한다. 새 가구 시스템이나 강제 미니게임은 추가하지 않는다.

## 5. 귀를 읽을 수 있는 표현 기관으로 연결

- 관심: 눈과 함께 대상 방향을 향하고 짧게 세워짐.
- 기대/기쁨: 몸의 작은 준비 동작과 귀의 들림을 연결.
- 편안함: 손에 기대는 몸과 귀의 긴장이 함께 풀림.
- 놀람: 짧은 귀 반응 후 대상 재확인과 자연스러운 복귀.
- 장난 후 확인/민망함: 몸과 시선의 마무리에 맞춘 짧은 귀 반응.

이는 허구 캐릭터의 표현 규칙이며 실제 동물의 감정 진단 규칙이 아니다. 귀가 아무 이유 없이 같은 주기로 계속 펄럭이거나, 모든 표정에서 같은 진폭으로 흔들리지 않게 한다.

현재 Blender rig의 실제 귀 bone/부모 공간/정지 변환/skin을 대조한다. 얼굴·몸에 붙은 상태로 움직이며 뿔/모자와 관통하지 않는다. 머리 움직임의 작은 지연과 복원은 가능하지만 펄럭임 과장은 피한다. 동작 줄이기에서는 작은 자세 변화로 의미를 유지한다.

현재 둥근 귀로 표현이 안 읽히면 귀 크기/형태를 임의 확정하지 말고 작은 가역 초안으로 비교한다. 기존 한 뿔·두 발·승인된 아기 인상은 보존한다.

## 6. 대사와 반복: 가린 비교와 일반 플레이 모두 검사

말풍선 가리기는 비교 모드에만 적용한다. 일반 플레이의 표시 설정을 몰래 바꾸지 말고 현재 사용자가 고른 설정을 확인한다. 비교 스위치가 기본 방의 발화를 영구 차단하지 않게 한다.

정상 표시 모드에서 다음을 확인한다:
- 사건에 적합한 대사가 실제로 선택됐는가.
- 말풍선 억제/쿨다운/우선순위/취소 때문에 전부 버려지고 있지 않은가.
- 같은 문장 ID뿐 아니라 같은 뜻·같은 연기 구조만 순환하고 있지 않은가.
- 완료한 경험과 아직 하지 않은 행동을 혼동해 말하지 않는가.
- 발화가 렌더/터치/생활을 멈추거나 저장 토스트를 만들지 않는가.

사용자가 대사가 너무 적다고 평가했으므로 의미 있는 인사·발견·접촉·작은 장난 뒤에는 짧은 말을 만날 기회를 확보한다. 정확한 초 단위 발화 할당량이나 무조건 출력 규칙은 만들지 않는다. 말하지 않는 표정 반응도 함께 쓴다.

짧은 예시: 실제 앞발 장난 직후 ‘내가 먼저!’, 편한 자리를 잡으며 ‘여기 좋다.’ 등. 예시 문장을 고정 3문장 순환으로 구현하지 않는다. ‘여기 눌러 봤어’, ‘자세가 달라졌네’ 같은 기술 시연 안내는 일반 펫 대사와 분리한다. 매번 ‘흥’이나 관계 압박을 쓰지 않는다.

대사 없이 감정을 읽는 비교와, 대사 ON으로 자연스럽게 대화하는 일반 플레이를 모두 제시한다. 가린 영상만 보고 대사 품질 PASS를 부여하지 않는다.

## 7. 방 디자인: 새 시스템 대신 동일 크기의 한 시안

사용자는 방 디자인도 불만족이라고 평가했다. 큰 베이지 평면과 임시 도형을 그대로 두고 ‘깔끔함’을 이유로 완료 처리하지 않는다.

제작 제안은 ‘햇살이 드는 작고 포근한 보금자리’ 한 안이다. 최종 디자인 승인으로 기록하지 않는다.
- 넓은 이동 공간과 작은 UI는 유지한다. 여백을 작은 장식으로 빽빽하게 채우지 않는다.
- 벽/바닥 경계와 재질을 분리해 방의 깊이가 느껴지게 한다. 밝은 우드 계열 바닥·따뜻한 크림 벽·절제된 파스텔 포인트를 초안으로 사용한다.
- 창문과 빛 방향, 러그/쿠션의 바닥 접촉이 일관되게 읽히게 한다.
- 정체가 불분명한 초록 구 같은 요소는 실제 역할을 확인하고 명료한 화분/배경 표현으로 정리한다. 보유 아이템 데이터를 삭제하거나 숨긴 공놀이를 되살리지 않는다.
- 실제 가구 좌표/충돌/행동 대상과 보이는 위치를 일치시킨다. 지금은 소품 시스템이나 상점·시설 가격을 만들지 않는다.
- 기존 성능 문제가 있으므로 다수 실시간 조명/고해상도 텍스처/무거운 효과를 무작정 넣지 않는다. 정적인 빛·그림자를 미리 제작하는 대안 등을 비교하되 실제 실행 비용을 확인한다.

먼저 현재 펫을 넣은 같은 화면 비율의 방 시안 하나와 현재 방 비교를 보여줄 준비를 한다. 새 방으로 모든 검증을 한 번에 바꾸지 말고 성격 비교는 기존 방에서 통제한다. 방 시안은 컨셉, 앱 내 연결 결과는 runtime 증거로 구분한다. 시안 검토 전 큰 방 자산 제작·기본 방 교체는 하지 않는다.

성장 게이지는 현재 레벨/진행만 표시하며 다음 모습·미발견 행동을 예고하지 않는다. 간단한 메뉴와 직접 교감 유지. 하단 손 제안은 검토 도구이며 일반 게임의 큰 상시 버튼으로 승격하지 않는다.

## 8. 실행 순서와 완료 범위

첫째, 현재 설치/로컬 소스/저장을 확인하고 눈 비대칭의 원인을 재현한다.
둘째, 같은 세 기질에서 손 교감의 눈·귀·몸·짧은 대사를 함께 다듬는다. 무입력 생활에도 동일한 표현 규칙을 연결한다.
셋째, 기존 사물 반응과 짧은 탭/유지/해제/메뉴 취소를 확인한다. 일반 말풍선 ON 검사와 대사 가린 비교를 따로 남긴다.
넷째, 방 시안 하나를 기존 펫·동일 화면 비율로 비교한다. 첫 검토 전에 방 전체 구현이나 성장형 확장으로 넘어가지 않는다.

실제 게임 크기의 짧은 전후 영상, 의도된 비대칭과 오류를 구분한 눈 전환 장면, 귀 표현, 세 성격의 같은 사건 반응, 일반 발화 장면을 우선 산출한다. 부분 프레임/확대 분석으로 장시간 자연스러움·GPU 성능을 승인하지 않는다.

SELF_REVIEW는 ‘무슨 감정을 표현했는가/어떤 단서로 읽히는가/사용자에게 아직 안 읽히는가’를 기록한다. 표정·대사·애니메이션의 개수만으로 통과하지 않는다. 정확한 유형 이름을 맞추도록 학습시키기보다 장난/편안함/조심스러운 관심과 방식 차이가 읽히는지를 사용자에게 보여준다. 사용자가 직접 피드백하기 전 자동으로 최종 재미 승인하지 않는다.

PERF-01·CANTOPEN VFS 원인 OPEN을 유지한다. 이번 기능/표현 평가와 성능을 분리하고 기존 해상도·품질 기준을 낮춰 통과시키지 않는다. 동일 런타임에서 변화 비용을 기록하고 기기/GPU 미검증은 NOT_RUN이다.

## 9. 보호 경계
