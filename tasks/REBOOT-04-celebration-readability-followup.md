## 1. 착수 기준과 이번 승인 범위

사용자는 v11 검토 후, 기능 확장 대신 **같은 목표 달성을 세 성격이 어떻게 축하하는지 더 분명하게 표현하고, 펫의 표정이 잘 읽히는 화면 후보를 비교**하는 제안에 동의했다.

제공된 최신 보고의 앱 소스는 `317ca1e`, 설치 이름은 `reboot-04-context-v11`이다. 이는 보고 기준이며 현재 Git HEAD를 확인했다는 뜻이 아니다. 실행자는 AGENTS.md, NEXT-RESUME.md, 최신 REBOOT-04 보고와 실제 HEAD/dirty/설치본을 읽고 이어간다. 더 새로운 작업이 있으면 보존하고, 과거 SHA로 reset하거나 이미 끝난 기능을 다시 만들지 않는다.

이 문서는 사용자 보고와 승인된 후속 방향을 바탕으로 작성한 **개발 지시서**다. 아래 연출·비교 수치는 제작 초안이며, 구현 완료나 최종 아트·크기 승인으로 기록하지 않는다.

### v11에서 보존할 것

- 같은 두 발·한 뿔 아기와 장난/다정/도도 세 성격, 현재 모션·기억 기반.
- 합성 LifeContext의 유효성·시간창·출처·개인 기준·쉬기·자기보고 구분.
- 기록 없음/지연/권한 불명확을 활동 부족이나 피로로 바꾸지 않는 규칙.
- 사건 claim, 중복 발화 방지, 취소/완료 구분, 재실행 후 상태 보존.
- 실제 텍스트 크기에 맞는 말풍선, X 없음, 탭 닫기, 읽기 시간/hold/stale timer 처리.
- 실제 건강 읽기 OFF, 경제·EXP·성장·수면/동면·SQLite 대기열·진단 기록.
- PERF-01과 STORAGE-01 CANTOPEN 원인의 OPEN 상태. 실기기/GPU/물리 입력 미검증.

v11의 대사와 기능이 부족하다고 가정해 모두 교체하지 않는다. 이번 수정은 **표현의 읽기성과 장면 구성**에 집중한다.

## 2. 이번 결과물은 세 가지뿐

1. **같은 합성 목표 달성**에 대한 세 성격의 짧고 분명한 축하 장면.
2. 현재 화면과, 펫을 조금 더 잘 보이게 한 **구도·크기 후보 한 개**의 비교.
3. 진단 메뉴를 최소화한 정상 속도 MP4 한 개를 기존 개인 iCloud 영상함으로 전달.

상점, 성장형/진화형, 8/16유형, 실제 건강 연동, 자유 대화 LLM, AI B 통합, 새 미니게임, 새 아기 모델은 추가하지 않는다. Blender 방 시안의 본격적인 앱 이식·새 방 테마 제작도 이번 범위가 아니다.

## 3. ‘축하’가 먼저 보이고, 말이 자연스럽게 따라오게

기존 LifeContext → director → 성격별 행동 → 발화 → 복원 경로를 재사용한다. 같은 근거를 가진 합성 목표 달성 사건을 주고, 성격 이름이나 설명 없이도 축하의 공통 감정과 각 아이의 표현 차이가 읽히게 한다.

### 공통 원칙

- 관심 전환 → 감정이 드러나는 짧은 몸짓 → 짧은 대사 → 여운 → 생활 복귀의 연결을 만든다.
- 대사보다 눈·귀·몸의 반응이 먼저 시작되되, 긴 무언 준비로 사용자가 사건과 반응의 관계를 놓치게 하지 않는다. 발화는 핵심 몸짓과 겹쳐도 된다.
- 눈/귀/입/몸을 서로 독립적으로 무작위 선택하지 않는다. 같은 의도와 현재 실행 상태를 사용한다.
- 평소 걷기나 기지개에 축하 문장만 붙이는 것으로 끝내지 않는다. 반대로 계속 점프하거나 윙크하는 공연으로 만들지도 않는다.
- 짧은 눈깜빡임과 의도된 윙크를 구분한다. 한쪽 눈을 닫은 상태가 계속 남거나, 표정 혼합/취소 뒤 비대칭이 남지 않아야 한다.
- 귀는 현재 대상으로 향하거나 기대에 들리는 준비, 몸짓 뒤 이완을 표현한다. 항상 같은 사인파로 흔들지 않는다. 몸에 가려 안 읽히면 실제 카메라에서 움직임 범위를 먼저 다듬고 귀 자체를 크게 재디자인하지 않는다.
- 앞발을 들 때 지지와 중심 이동을 유지한다. 없는 손이나 가구에 기대지 않는다. 목표 축하에는 실제 손 입력이 필수가 아니다.
- 다음 자율행동이 핵심 축하를 중간에 덮지 않되, 실제 사용자 이동·수면·메뉴 취소는 기존 계약대로 작동해야 한다.

### 세 성격의 연출 초안

| 성격 | 몸과 시선의 역할 | 대사 톤의 예시 | 생활 복귀 |
|---|---|---|---|
| 장난꾸러기 | 사용자를 확인하고 귀가 들림 → 짧은 통통 도약 또는 앞발 축하 → 사용자 반응 확인. 몸 전체의 신남이 읽혀야 한다. | “해냈네! 나도 신나!” | 짧은 만족 표정 후 다른 관심사로 가볍게 복귀. 윙크를 쓴다면 짧은 마무리 한 번. |
| 다정 | 부드러운 눈맞춤 → 사용자 쪽으로 조금 가까이 → 기쁜 얼굴과 안정된 자세로 잠깐 함께 머묾. 실제 손이 없으면 손 기대기 모션을 재생하지 않는다. | “오늘 목표 채웠네. 잘했어.” | 시선을 한번 더 맞춘 뒤 편안하게 자기 생활로 돌아감. |
| 도도·호기심 | 하던 일을 잠깐 멈추고 살핌 → 몸을 세운 짧은 앞발 인사와 절제된 미소. 무표정/무반응이나 단순 느린 다정 모션으로 대체하지 않는다. | “흠, 해냈네. 제법인데?” | 사용자를 짧게 확인한 뒤 실제 이전 관심으로 복귀. |

예시 문장은 새로 제안한 방향이지 고정된 3문장 납품 조건이 아니다. 현재 더 자연스러운 대사가 있으면 유지한다. 새 문장 수를 채우기보다 행동과 말의 의미가 맞는지 본다. 체중·외모 비하, 쉬는 날 재촉, 접촉 보상, 사용자 운동을 펫의 성격 진단으로 바꾸는 기능은 추가하지 않는다.

시간 길이·진폭·발화 시작점은 가역 튜닝으로 둔다. 각 성격의 속도만 다르게 하지 말고 **신남을 같이 나누는 방식**을 다르게 만든다. 기존 문맥·최근 이력에 따른 변주를 보존하며 모든 반복을 같은 대본으로 고정하지 않는다.

## 4. 화면에서 표정이 읽히도록 — 현재판과 후보 하나

사용자는 이전에 지나치게 큰 펫도 원하지 않았다. 따라서 무조건 크게 만들지 않고, **방의 활동 공간을 남기면서 얼굴·귀·앞발을 읽기 쉽게 하는 것**이 목표다.

### 비교 순서

1. 현재 설치판의 논리 viewport, 모델, 카메라, 렌더 품질, HUD와 실제 펫 화면 점유율을 기록한다. 모델 원점/정면/표정과 위치를 맞춘 기준 캡처를 보존한다.
2. 먼저 카메라·방·해상도를 고정하고 현재판 대비 **화면상 높이 약 12% 증가**를 출발점으로 후보 하나를 만든다. 이는 `현재 × 1.12`라는 제작 제안이며 이전의 +25/+35 선택을 다시 만들라는 뜻이 아니다. 최종값은 미승인이다.
3. 증가한 크기가 얼굴 가독성을 높이는지, 이동 영역을 답답하게 하거나 머리/뿔/말풍선을 가리지 않는지 확인한다. 후보는 기존 검토 모드에서만 선택 가능하게 하고 일반 저장의 기본 크기를 덮어쓰지 않는다.
4. 필요하면 같은 후보 안에서 HUD·러그의 시각적 비중·카메라 구도를 최소 조정한다. 크기 조정과 구도 조정의 결과는 별도로 기록해 무엇이 개선됐는지 구분한다. 가구를 많이 추가하거나 계속 카메라가 펫을 쫓게 만들지 않는다.

### 지켜야 할 조건

- 같은 화면 원본으로 비교한다. 확대 crop만 보여주거나 저해상도 전달 사본을 고품질 증거로 쓰지 않는다.
- 구도 변경 시 펫/가구의 실제 좌표·기억을 임의로 고치지 않는다. raycast, 터치, 화면 말풍선 투영, 바닥 접지, navigation, 앞/뒤 가림이 일치해야 한다. 단순 전체 View 확대나 잘라내기로 터치 영역을 틀리지 않게 한다.
- 러그 외관을 건드리더라도 이동 가능한 쿠션과 시설의 소유/위치/기억·충돌 계약을 바꾸지 않는다.
- 현재 레벨과 성장 게이지, X 없는 말풍선, 간단한 메뉴는 유지한다. 다음 성장 변화나 미발견 형태는 예고하지 않는다.
- 기존 넓고 깔끔한 방의 장점은 유지한다. 새 조명·무거운 실시간 그림자·PBR 전체 전환으로 이번 범위를 넓히지 않는다.
- 목표 달성 같은 일반 발화는 몸짓이 보일 공간을 확보하고, 말풍선이 귀·눈·뿔을 가리지 않게 한다. 텍스트를 작게 줄여 맞추지 않는다.

## 5. 개발자 메뉴가 아닌 ‘실제 반응’을 보여주는 검토

테스트 설정은 촬영 전에 하고, 설정하는 긴 화면을 대표 영상의 대부분으로 쓰지 않는다. 이미 있는 합성 관찰 입력으로 정상 director를 호출하되, 강제 아트 clip을 재생한 것을 자율 반응으로 기록하지 않는다.

- 동일한 가구·현재 상태·성장 단계·비교용 경험에서 세 성격에 같은 의미의 합성 목표 달성을 전달한다.
- 현재 일반 개체의 경험/경제를 초기화하지 않는다. 동일조건 검사는 별도 합성 저장/프로필에서 한다. 반복 비교를 위해 새 petId/사건을 썼다면 명시한다.
- 일반 앱에서는 같은 사건을 여러 번 선택하거나 앱을 재실행해도 중복 발화/보상이 없어야 한다. 비교 영상을 찍으려고 claim이나 간격 제한을 제품 경로에서 우회하지 않는다.
- 대사 ON이 실제 플레이의 주 검토다. 비언어 판독용 OFF는 별도 동일조건 장면 또는 동일 원본의 명시된 분석용 파생본으로 구분한다. 끈 상태를 정상 대사 빈도 검증으로 쓰지 않는다.
- 잠깐의 무입력 생활과 축하 후 자율 복귀도 포함한다. 직접 손 내밀기 도구가 없어도 목표 축하가 시작되는지 확인한다.
- 합성 상황을 선택한 기능 검증이며 실제 걸음 데이터 연동이나 하루 동안의 자연 발견을 시험한 것이 아니라는 점을 표시한다.

## 6. 검증은 이번 변경에 필요한 만큼

### 표현/기능

- 각 성격의 귀·눈·시선·전신·발화·복원이 같은 사건을 표현하고, 실제 작은 화면에서도 중요한 몸짓이 가려지지 않는다.
- 대사를 읽기 전에도 긍정적/축하 반응이 어느 정도 읽히는지 SELF_REVIEW한다. 스스로 본 결과를 독립 블라인드 사용자 검증이나 재미 승인이라고 하지 않는다.
- 장난=지속 윙크, 다정=졸린 자세, 도도=무반응 같은 고정 표현으로 귀결되지 않는다.
- 목표 달성 직후 다른 유효 입력·수면·메뉴가 들어올 때 기존 우선순위/취소 계약을 지킨다. 늦은 콜백이 과거 표정·말풍선을 되살리지 않는다.
- 짧은 대사/두 줄/긴 한국어, 가장자리에서 내용 기반 크기·읽기 시간·탭 닫기를 재확인한다. 말풍선을 닫는 탭이 뒤의 펫/바닥까지 실행되지 않는다.
- 같은 사건 중복, 기록 없음/지연/권한 불명확, 사용자 쉬기와 수면 배려의 기존 회귀를 유지한다. 경제 원장과 승인되지 않은 건강 읽기는 변하지 않는다.
- 정상 취소·재실행과 보존된 저장/진단을 확인한다. 표현 기억이 정상 갱신되면 ‘모든 기억 byte동일’이라 주장하지 말고 기존 보관 정책의 변화로 보고한다.

### 남은 결함과 성능

PERF-01과 CANTOPEN을 새 표현 작업의 검사 숫자로 닫지 않는다. 표현·구도 변경이 있으면 같은 품질·장면 조건에서 v11과 후보의 관련 비용을 비교하고, 가능 범위의 표준 절차로 regression 여부를 본다. 기존 실패/호스트 변동·실기기 미검증을 함께 기록한다. 해상도/표정/행동·판정 기준을 낮추거나 좋은 창만 고르지 않는다. 기존 성능 문제 해결을 위해 근거 없는 장기 실험을 반복하면서 표현 검토 전달을 무기한 미루지 않는다.

v11의 이모지 대체 글리프, 실제 긴 누르기·VoiceOver 읽기, OS 전체 큰 글자, 실기기 미확인도 별도로 남긴다. 이번 시연에 꼭 필요하지 않은 이모지를 넣거나 새 폰트/SDK 패치를 시작하지 않는다. 이모지가 없는 문장으로 시연했다고 이모지 결함을 CLOSED하지 않는다. 읽기 hold·접근성 동작은 제거하지 말고 도구가 지원하지 않는 실제 검사는 NOT_RUN으로 남긴다.

## 7. 산출물과 원격 전달

수정된 실제 앱의 짧은 첫 검토판을 만든다. 내부 연출을 여러 번 무한히 바꾸지 말고, 명백한 결함을 수정한 뒤 비교 가능한 근거를 사용자에게 전달한다. 완료 전에 16유형·성장·새 아트로 확장하지 않는다.

### 기본 전달물

- **대표 MP4 한 개, 2~3분 이내**: 현재/후보의 동일 화면 크기 비교 → 장난/다정/도도의 같은 목표 축하 → 정상 생활 복귀·말풍선 닫기.
- 대사 ON을 기본으로 하며, 긴 진단 메뉴 조작은 제외한 연속 장면 발췌를 사용한다. 컷과 원본 시각은 `_scenes.txt`에 남긴다. 원본/실패 구간은 로컬 보존한다.
- 원본 화면의 세로 해상도·정상 속도를 우선한다. 프레임 보간·샤픈·생성 보정으로 연기를 개선한 듯 만들지 않는다. 확대 얼굴은 보조 분석에만 사용하고 실제 게임 크기 장면을 먼저 보여준다.
- H.264 등 기존 검증된 전달 형식을 재사용하고 전체 디코딩/길이/용량/원본·복사 해시를 확인한다. 원본 인코딩 FPS를 앱 표시 FPS로 보고하지 않는다.

기존 `docs/remote-video-delivery.md`와 승인된 **개인 iCloud Drive → Arucon → Reviews**를 재사용한다. MP4와 짧은 안내문만 복사한다. 합성 데이터만 담고 DB·로그·실건강정보·소스는 전달하지 않는다. 공개 링크·localhost 전달·포트 개방·회사 계정 사용·기존 영상 자동 삭제는 하지 않는다.

파일명은 실제 날짜/최신 빌드/소스 SHA를 반영한다. 예: `2026-10-13_arucon_REBOOT04_celebration_<build>_<source>_review.mp4`. v12는 다음 빌드의 제안 이름일 뿐, 이미 사용된 버전이면 재사용하지 않는다.

로컬 파일 준비, iCloud 업로드, 사용자 휴대폰 재생은 각각 구분한다. **v10 재생 확인을 새 전달본의 MOBILE_PLAYBACK_VERIFIED로 복사하지 않는다.**

## 8. 보고와 권한 경계

기술적 선택·결함 수정은 현재 직접 개발/SELF_REVIEW 방식으로 처리한다. 새 모델 전환·강제 하위 에이전트·새 설치·계정 승인 절차를 만들지 않는다. 실제 사용한 Blender/도구만 기록한다.

첫 보고는 다음 네 가지에 답한다.
1. 세 성격이 같은 성취를 어떤 다른 행동으로 축하하는가?
2. 현재 화면과 크기/구도 후보의 실제 가독성이 어떻게 다른가?
3. 최신 동일 설치본의 관련 기능/성능/보존 결과와 남은 미확인은 무엇인가?
4. 사용자가 휴대폰에서 열 MP4 파일명과 장면 시각은 무엇인가?

좁은 비교가 준비되면 `CELEBRATION_EXPRESSION_REVIEW_READY — 범위 한정`으로 보고할 수 있다. 필수 표현·입력 결함이 남으면 REWORK_REQUIRED, 실행 환경 때문에 필수 검증을 못 했으면 PARTIAL_WITH_BLOCKERS로 구분한다. 전체 프로젝트의 PERF-01 미달·STORAGE-01 OPEN과 사용자 재미·최종 성격 표현·아트·크기 승인은 별도이며 임의로 통과시키지 않는다.

기존 feature의 논리적 checkpoint commit/일반 push만 사용한다. main/merge/force/배포·실건강 읽기·실결제·DB 초기화·Git reset/clean·OS 보안 변경·무단 파일 삭제는 하지 않는다. 보고용 기록을 무한히 새로 만들지 말고 기존 작업 지시·REBOOT-04 보고·NEXT-RESUME에 필요한 변경만 남긴다.

## 2026-10-14 사용자 v15 제품 평가 후속

사용자는 대사에 비해 눈·귀·몸짓의 성격 차이가 약하다고 평가했다. v15 기능/보존 증거를 유지하고 표현은 REWORK_REQUIRED로 다시 검토한다. 같은 합성 목표의 시작→감정→짧은 말→마무리→생활 복귀에서 세 성격을 구분한다. 말풍선 OFF 정상 사건 비교와 ON 플레이를 같은 최신 Release로 제시한다. 대사/행동 수를 늘리는 방식으로 완료하지 않는다.

+12% 후보는 유지하며 최종 채택하지 않는다. 넓은 바닥을 유지하는 구도 한 후보를 비교한다. 기존 Blender 햇살 시안의 실제 게임 GLB 후보를 사용하고 기본 방 A를 보존한다. 기존 REBOOT-05의 방 제작 결과를 새로 만들었다고 기록하지 않는다. 생활 맥락 판단·claim·말풍선 구조·기억·저장·성장/경제 규칙은 유지한다.

구현 초안: 장난은 열린 눈/들린 귀→짧은 도약→옆으로 기울여 반응 확인, 다정은 양발 접지/부드러운 눈·낮아지는 귀→짧은 인사/함께 머묾, 도도는 옆 시선/한쪽 관심 귀→앞발 인사/절제된 미소→실제 이전 관심 복귀. 기존 네 beat와 대사를 재사용하며 숫자·시안은 승인된 최종 표현이 아니다. 구도 후보는 수평 활동 span과 모델 크기를 유지하고 시점을 조금 낮춘다. 자동 검사·실제 정상 속도 비교·개인 iCloud Reviews 전달 후 SELF_REVIEW와 사용자 평가 대기를 구분한다. PERF-01/STORAGE-01 OPEN 및 기존 feature/외부 권한 경계 유지.
