# REBOOT-04 — 16유형 펫 성격 기반과 대표 3종

## 작업 목표

아루콘의 최종 목표는 MBTI처럼 구분되는 **16가지 펫 성격**이다. 이번에는 기존 앱에서 확장 가능한 성격 기반과 대표 3종만 구현한다. 문서·클래스 작성이나 대사 교체만으로 끝내지 말고 실제 생활·교감에서 차이를 확인한다.

이번 네 축은 펫 게임용 정의다. 실제 MBTI 검사·사용자 성격 진단이 아니며, 임의로 INTJ 같은 실제 MBTI 코드와 대응시키지 않는다. 기존 REBOOT-04 성장 디자인 시안은 보존하고, 그 시안의 미승인 레벨·외형을 이번 정책으로 채택하지 않는다.

## 1. 현재 상태와 보존

현재 HEAD/작업 트리/설치본과 NEXT-RESUME.md, 관련 AGENTS·성격·성장 문서를 먼저 확인한다. 과거 보고의 SHA로 reset하지 않는다. 기존 일반 저장, A/B/C 원본, Blender 원본, 시간·수면·동면·SQLite 대기열·중복 정산 방지는 보존한다. STORAGE-01 등 기존 OPEN 결함을 이번 작업으로 자동 종료하지 않는다.

현재 Codex에서 선택된 모델이 직접 구현·검증하며 SELF_REVIEW로 기록한다. 새 강제 분업·단계별 승인 절차는 추가하지 않는다. 요청 모델명과 실제 런타임 확인은 구분한다.

## 2. 고정할 제품 방향

- 사용자가 선택한 새 성장 디자인은 **네발 기반, 유니콘 뿔 하나**다. 이는 제작 방향 승인이지 기존 두 앞발 모델의 네발 보행 검증 완료가 아니다.
- 성격 비교에는 같은 외형·크기·렌더 설정을 사용한다. 네발 후보가 아직 없다면 기존 Blender 제작 흐름으로 공통 후보 하나만 준비하고 접지·걷기·정지부터 확인한다. 아기 3종의 외형을 각각 새로 만들지 않는다.
- 외형 계열과 성격은 별개다. 장난꾸러기=특정 진화형처럼 고정하지 않는다. 기존 진화형 이름·분기 정책을 이번 세 성격으로 대체하지 않는다.
- 아기는 공통적으로 호기심 많고 까불거리는 면을 유지하면서, 작은 접근 방식·반응 차이로 잠재 기질을 드러낸다. 성장하면서 개성이 더 구체화되도록 한다.
- 현재 레벨·성장 게이지는 유지하지만 다음 행동·진화 모습·미발견 특성은 예고하지 않는다.
- 공놀이·까꿍 등 수동 미니게임을 복원하지 않는다. 교감은 선택 활동이며 클릭 횟수로 EXP나 성격 우위를 주지 않는다.

## 3. 성격 기반과 대표 3종 구현

기존 성격·기억 구조를 먼저 점검하고 확장한다. 같은 책임을 가진 새 엔진·DB·대사 선택기를 중복 생성하지 않는다.

네 축은 다음으로 정의한다.
1. 외향 ↔ 내향: 먼저 접근하는 방식과 혼자 지내는 리듬.
2. 장난형 ↔ 차분형: 장난의 선택과 몸짓의 크기·강도.
3. 애착형 ↔ 독립형: 함께 있는 방식과 자기 활동을 이어가는 방식.
4. 호기심형 ↔ 안정형: 새로운 대상 탐색과 익숙한 선택의 경향.

축 값은 연속값으로 표현할 수 있게 하고, 버전과 저장 계약을 둔다. 최종 16조합으로 확장 가능하게 하되, 이번 세 프로필은 비교용 대표 조합이지 최종 타입 전체가 아니다. 단일 접촉·기분 변화마다 타입을 재추첨하거나 축을 크게 바꾸지 않는다.

형성 규칙은 잠재 기질·실제 완료 경험·성장 단계의 역할을 구분해 작은 가역 검토안으로 만든다. 일반 저장의 성격을 소급 변경하거나 임의의 건강 데이터로 성격을 재분류하지 않는다. 사용자 운동량·수면으로 사람의 성격을 진단하지 않는다. 미접속·자동급식 사용·교감 부족으로 애정이나 성격을 나쁘게 만들지 않는다.

이번 대표 프로필:
- **장난꾸러기형:** 먼저 살펴보고 가볍게 접근하며 작은 장난을 시도한다. 반응 후 사용자 쪽을 확인하고 스스로 생활로 돌아간다.
- **다정형:** 시선 맞추기와 몸을 기대는 교감을 즐기고, 함께 쉬거나 곁에 머무는 표현이 풍부하다. 매번 달라붙거나 조작을 요구하지 않는다.
- **도도·호기심형:** 자기 템포로 관찰·탐색하다 관심이 생기면 다가온다. 표정은 새침해도 애정은 몸짓으로 보인다. 무표정·무기력함으로 대신하지 않는다.

성격별 자율 행동·접촉 반응·표정 패턴은 각각 최소 6개 이상을 기존 자산의 유의미한 조합으로 지원한다. 이름·어미만 바꾸거나 속도만 조절해서 개수를 채우지 않는다. 같은 표현 자산을 재사용하되 시선→접근→행동→결과→후속 반응의 연결이 달라야 한다.

선택에는 현재 상태·대상·진행 중 행동·성격 축·성장 단계·관련 완료 경험·최근 반복 이력을 함께 사용한다. 같은 성격이 같은 사건에 일관된 스타일로 반응하면서도, 같은 장면이 짧은 시간에 고정 순환하지 않게 한다. 대사는 실제 사건을 짧게 표현하고 동작 설명으로 연기를 대신하지 않는다.

## 4. 비교 방법과 성장 연결

일반 펫과 분리된 검토 저장에서 세 프로필을 비교한다. 프로필별 petId·기억·난수 입력을 구분하고 다른 아이의 기억이 섞이지 않게 한다. 검토용 프로필 선택기를 일반 사용자의 성격 선택·변경 기능으로 노출하지 않는다.

같은 방·외형·크기·상태·동등한 초기 경험에서 다음을 정상 입력으로 비교한다.
- 2분 무입력 생활.
- 기존 소품의 변화 또는 새 위치 확인.
- 머리·몸 접촉, 손을 놓은 뒤 반응, 행동 중 접촉·취소.
- 자율생활 복귀와 앱 재실행 후 같은 성격·기억 유지.

대사·성격 라벨을 가린 정상 속도 비교도 남긴다. 행동 이유와 차이가 실제 화면에서 읽히는지 확인하며, 로그의 다른 ID를 시각적 차이로 간주하지 않는다. 통제 비교만으로 자율생활을 통과시키지 말고 자유 관찰도 함께 한다.

성장 연결은 이번에 인터페이스와 대표 변화 설계까지 둔다. 예: 같은 기질의 아기가 조심스럽게 손을 확인하던 행동이 성장 후 익숙하게 먼저 기대는 반응으로 성숙한다. 기존 레벨·EXP·성별·진화 경계와 경제 산식은 변경하지 않는다. 성장기·진화형 전용 모델과 전체 Lv.1~20 새 콘텐츠는 이번에 제작하지 않는다.

## 5. 도구와 신뢰성

기존 Blender 원본·제작 스크립트·시각 검증 스킬을 재사용한다. Context7 등은 현재 세션에서 실제 호출 가능한 경우 해당 버전 문서 확인에 사용한다. 사용하지 않은 도구를 사용했다고 보고하지 않는다. 새 유료 서비스·전역 설치·외부 업로드·계정 권한 확대는 임의로 하지 않는다.

필요한 자동 회귀와 같은 최신 Release의 실제 메뉴·접촉·취소·생활 복귀·저장 복원을 수행한다. 수면/동면 때의 입력 조건, DB 공통 대기열, 중복 보상 방지를 유지한다. 추론·대사 선택·전체 DB 저장을 매 프레임 실행하지 않는다.

원래 선택된 렌더·크기를 보존하고 실제 적용값을 기록한다. Simulator proxy를 GPU 표시 FPS나 실기기 성능으로 표현하지 않는다. 호스트 잠금은 우회하지 않으며 가능한 독립 작업만 계속한다.

## 6. 범위와 종료

이번에 하지 않는 것: 최종 16종 전체 구현, 8종 즉시 확장, 전 진화형 제작, 상점/가격/성장 먹이/변기 이전, 자유 대화 LLM, AI B 통합, 신규 미니게임.

최종 자료는 짧은 설계 문서 하나, 실제 3종 비교 경로, 같은 조건의 정상 속도 비교 영상, 관찰한 차이와 남은 한계다. 다음 3종→8종→16종 확장 순서만 정리하고 사용자 검토 전에 확장하지 않는다.

실제 화면에서 세 성격의 접근·자율생활·교감·표정 차이가 연결되고 필요한 회귀를 충족하면 `PERSONALITY_3_REVIEW_READY`로 보고한다. 구현/조작 결함이 남으면 `REWORK_REQUIRED`, 필수 실행을 환경 때문에 못 하면 `PARTIAL_WITH_BLOCKERS`다. 재미·아트·성격 표현 최종 승인은 사용자 검토로 남긴다.

기존 feature 브랜치의 승인된 checkpoint commit·일반 push만 유지한다. main/merge/force push/배포/실건강정보 읽기/실결제/DB 초기화/보안 설정 변경은 하지 않는다. 보고 첫 부분에는 테스트 개수 대신 같은 상황에서 세 아이가 실제로 어떻게 다르게 행동했는지 적는다.
