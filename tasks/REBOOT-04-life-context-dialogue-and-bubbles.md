# 아루콘 — 생활 맥락 반응·대사 연기·말풍선 후속 지시

작성: 2026-10-12
적용: 현재 REBOOT-04 후속. 새 전면 개편이나 실제 건강정보 연결 승인이 아니다.

## 1. 최신 요청과 이번 실행 범위

사용자 요청:
- 나중에 걷기·달리기·수면을 연결하면, 확인된 생활 맥락에 대해 펫이 먼저 말을 걸고 성격별로 다르게 반응한다.
- 말의 의미와 표정·귀·시선·몸짓이 맞아야 한다.
- 말풍선은 말 길이에 맞게 크기가 달라지고, 시각적인 X 닫기 표시는 없앤다.

사용자 예시에는 체중에 따른 거친 놀림이 포함됐다. 아래는 그 예시를 그대로 구현하지 않고 **까칠한 말투는 유지하되 체중·외모 비하를 제외하는 대안**을 제안한다. 이를 사용자가 이미 승인한 변경으로 기록하지 않는다. 체중 수집·비하 대사를 추가하지 말고 기존 사용자 비난 금지 경계를 보존한다. 판단이 더 필요하더라도 말풍선 개선과 합성 맥락 검증은 독립적으로 진행한다.

이번에 할 일:
1. 현재 펫 말풍선의 내용 기반 크기와 X 없는 닫기 동작을 구현한다.
2. 기존 세 성격과 표현 체계를 재사용해 합성 생활 맥락 반응을 작은 범위로 연결한다.
3. 같은 상황을 서로 다른 성격이 표현하는 실제 장면을 확인한다.

이번에 하지 않을 일:
- 실제 HealthKit/Health Connect 읽기 활성화, 새 건강 권한/체중 권한 요청.
- 실제 스마트워치·심박수 연동, 새 외부 AI API, 실건강정보 업로드.
- 16유형 전체 제작, 성장·경제 산식 변경, 방 전체 재제작, 강제 운동 미션.

현재 HEAD/작업 트리/설치본과 기존 승인 문서를 확인하고 기존 작업을 보존한다. 아기 두 발·한 뿔·기억·저장·경제·성장 구조는 유지한다. 변경 없는 부분을 다시 만들지 않는다.

## 2. 생활 데이터는 ‘사실’과 ‘추정’을 구분

공통 맥락 입력에는 출처(합성/실데이터), 관찰 기간, 조회 시각, 관찰 근거, 개인 목표 또는 비교 기준, 관련 세션/사건 ID와 revision을 둔다. 당장 실제 OS 어댑터를 만들지 않고 합성 공급자를 사용한다.

예시 상황:
- 충분한 최신 기록이 있는 늦은 시간대에 본인이 정한 걷기 목표가 남아 있음.
- 사용자가 정한 활동 목표를 달성함.
- 실제 확정된 달리기 세션이 끝남.
- 본인이 ‘잠을 잘 못 잤다’고 알려줌.
- 유효한 수면 기록의 길이가 개인 기준보다 짧음.
- 사용자가 오늘 쉬겠다고 선택함.
- 기록 없음/연결 미완료/조회 실패/동기화 지연/해석 불충분.

핵심 규칙:
- 낮은 걸음 수를 ‘운동을 전혀 안 했다’로 바꾸지 않는다. 다른 운동이나 기기 미소지 가능성을 없다고 가정하지 않는다.
- 조회 결과 없음은 0걸음·0시간 수면으로 바꾸지 않는다. UNKNOWN에서 생활 부족을 꾸짖는 대사는 생성하지 않는다.
- HealthKit의 읽기 권한은 앱이 허용/거부를 확실하게 구별할 수 없는 경우가 있다[S1]. 요청 창 완료나 쓰기 권한을 읽기 허용의 증거로 삼지 않는다.
- 짧은 수면 기록만으로 수면의 질, 피로, 질병을 확정하지 않는다. 사용자의 직접 표현과 측정 기록을 구분한다.
- 오전에 하루 목표 미달이라고 말하지 않는다. 본인 목표와 시간대를 함께 보고, 비교 기준이 없으면 임의 평균·일률적인 건강 기준을 만들지 않는다.
- 여러 기기/겹치는 세션의 합산·시차·수정 기록은 기존 정산 계약과 일관되게 처리한다. 대사 시스템이 별도의 걸음/수면 정산 엔진이 되어서는 안 된다.
- 건강 정보는 사용자의 성격/MBTI를 진단하거나 펫의 성격을 매번 재추첨하는 입력이 아니다.

## 3. 까칠함·장난·상냥함의 구분

다음은 제작 초안이며 최종 대사 승인이 아니다. 성격 이름만 바뀐 같은 문장으로 구현하지 않는다.

| 상황 | 장난꾸러기 | 다정 | 까칠·도도 |
|---|---|---|---|
| 늦은 시간, 본인 걷기 목표가 남고 관찰이 유효함 | “오늘은 내가 더 씩씩한데? 같이 한 바퀴 어때?” | “오늘 바빴어? 괜찮으면 잠깐 걸을까?” | “흥, 목표는 세워 놓고. 기운 있으면 한 바퀴 돌까?” |
| 사용자가 잠을 잘 못 잤다고 알려줌 | “그럼 오늘은 내가 조용히 놀게!” | “피곤하겠다. 괜찮아? 오늘은 무리하지 말자.” | “잠도 못 잤다며. 오늘은 쉬어. 괜히 고집부리지 말고.” |
| 본인 목표 달성 확인 | “해냈다! 오늘 발 엄청 바빴네!” | “오늘도 해냈네. 같이 있어서 기뻐.” | “진짜 다 했네? 흥, 제법인데.” |

- 까칠함은 툴툴대는 말투와 숨기지 못하는 관심으로 만든다. 체중·체형·외모·질병·이동 능력을 깎아내리는 문장은 제외한다.
- 거친 농담 강도는 사용자가 별도로 선택/낮출 수 있는 옵션으로 제안한다. 펫이 까칠하다는 이유로 건강 잔소리까지 강제하지 않는다.
- 휴식일·피곤함·‘오늘은 쉬기/이런 말 줄이기’를 선택하면 재촉을 멈춘다. 선택을 비난하거나 보상·애정·기분을 차감하지 않는다.
- 잠을 못 잔 상태와 저활동이 동시에 있을 때 운동 독촉을 먼저 하지 않는다. 상태가 불확실하면 질문이나 일반적인 교감을 사용하거나 아무 말도 하지 않는다.
- 건강 주제의 말걸기는 기본적으로 드물게, 부정적 방향의 재촉은 최대 하루 한 번을 초기 제안값으로 둔다. 정확한 빈도는 가역 설정으로 관리하며 사용자 최종 승인값으로 기록하지 않는다.
- 좋은 변화도 다룬다. 활동 완료·목표 달성·편안히 쉰 날을 알아보는 반응이 부족한 날 지적보다 중심이어야 한다.
- 동일 사건/revision 재처리·앱 재실행·화면 재진입으로 같은 말을 반복하지 않는다. ‘쉬기로 했음’ 등의 실제 사용자 선택은 보관 정책에 맞게 존중한다.

## 4. 대사·귀·눈·몸이 한 의도를 표현

`상황 해석 → 의도(초대/축하/배려/확인) → 성격별 표현 → 실제 실행 → 완료/취소`로 연결한다. 기존 구조를 재사용하고 별도 거대한 감정 엔진을 중복 구축하지 않는다.

- 각 cue는 같은 eventId/intent와 실행 가능 조건을 공유한다. 문구는 위로인데 몸은 공격적인 재촉을 하거나, 축하 대사 중에 졸림 루프가 덮는 모순을 막는다.
- 장난스러운 산책 제안: 귀·시선으로 사용자를 확인 → 작은 앞발 제안/짧은 몸짓 → 한마디 → 선택을 강요하지 않고 생활 복귀.
- 다정한 수면 배려: 귀의 긴장을 낮추고 부드럽게 눈을 맞춤 → 곁에 가까이 머묾 → 짧은 말 → 조용히 자기 생활.
- 까칠한 배려: 몸은 태연하게 두고 시선만 한번 확인 → 짧게 툴툴댐 → 실제 행동은 무리하게 재촉하지 않음.
- 기본 눈은 안정적으로 돌아오고 윙크는 짧고 맥락 있는 동작이다. 감정 이름만 바꾸거나 일정한 사인파 귀 흔들림을 감정 표현 완료로 세지 않는다.
- 상태가 바뀌거나 사용자가 쉬겠다고 하면 오래된 제안·말풍선·귀/눈 포즈를 취소하고 자연스럽게 복귀한다. 늦은 콜백이 이전 표정을 되살리지 않게 한다.
- 상황별 반응은 대사 ON에서 읽히는지와 대사 OFF에서도 의도가 어느 정도 읽히는지를 따로 확인한다.
- 아기 단계에서는 짧고 아기다운 말/소리와 전신 반응을 우선한다. 성격별 말투를 붙인 긴 사람 독백을 만들지 않는다. 성장별 확장은 기존 인터페이스를 유지하며 별도 단계다.

## 5. 말풍선 — 내용 기반 크기, X 없음

시각적인 X/닫기 아이콘은 펫 말풍선에서 제거한다. 오류·권한·설정 패널의 기능을 무차별 제거하지 않는다.

- 짧은 대사는 작은 폭, 긴 대사는 여백을 유지하며 넓어지고 안전 영역의 최대 폭에서 자연스럽게 줄바꿈한다.
- 작은 문장에도 고정된 큰 카드 폭을 쓰지 않는다. 한국어 글자 수만으로 폭을 추정하지 말고 실제 텍스트 레이아웃/폰트 크기로 측정한다.
- 글자를 작게 줄이거나 긴 문장을 잘라내서 맞추지 않는다. 큰 글자 설정과 이모지, 개행을 검사한다. 지나치게 긴 콘텐츠는 자연스러운 짧은 발화로 나누되 명시하지 않은 생략을 하지 않는다.
- 말 길이에 맞는 읽기 시간을 주고 부드럽게 사라진다. 고정 초마다 새 문장이 강제로 덮지 않게 한다. 표시 시간은 읽기성 검토용 설정으로 둔다.
- 빨리 닫고 싶으면 말풍선 자체를 탭해 닫을 수 있게 한다. 이 탭이 뒤의 펫 교감/바닥 이동까지 이중 실행되지 않게 한다.
- 길게 누르거나 접근성 포커스로 읽는 동안 자동 사라짐을 멈추는 방식을 적용한다. 시각적인 X 없이도 접근성의 닫기/스크린리더 읽기 경로를 제공한다.
- 화면 가장자리·메뉴·게이지·펫 얼굴·뿔·귀를 가리지 않게 앵커와 배치를 조정한다. 펫 움직임에 맞춰 따라가되 좌우를 계속 튀며 바꾸지 않는다.
- 말풍선 상태 갱신 때문에 GLView/펫 모델이 재생성되거나 이동·교감이 멈추지 않는다.
- 말풍선 닫기는 문장 표시를 끝내는 일이다. 유효한 생활 행동 전체를 영구 취소하거나 전역 입력 잠금을 남기지 않는다.
- 저장 실패·권한 실패 등 중요한 오류 안내는 이 자동 사라짐 규칙을 적용해 숨기지 않는다.

## 6. 검사와 완료 범위

현재 실제 건강 읽기는 OFF, 합성 프로필에서만 검사한다.

검사할 핵심:
1. 같은 유효한 낮은 걸음 맥락·같은 짧은 수면/직접 보고 맥락에서 세 성격의 대사·귀·시선·몸짓 비교.
2. 목표 달성 축하와 사용자의 ‘오늘은 쉬기’ 뒤 재촉 중단.
3. 기록 없음/조회 지연/새벽/권한 불명확에서 잘못된 ‘운동 안 함/잠 못 잠’ 반응이 나오지 않음.
4. 짧은 말·두 문장·긴 한국어·큰 글자·화면 가장자리의 말풍선과 X 없는 즉시 닫기.
5. 말풍선 생성/닫기/대체 중 이동·교감·수면 복귀·앱 재실행, 중복 대사와 중복 정산 없음.
6. 같은 설정의 현재 실제 Release에서 성능 영향을 확인. PERF-01이나 CANTOPEN이 자동으로 CLOSED가 된다고 보고하지 않음.

교감 개선/말풍선 기능/합성 생활 반응/실데이터 미연동/성능 미검증을 각각 구분한다. 현재 근거 없이 특정 모델·새 외부 API·SDK 업그레이드를 요구하지 않는다.

시연은 최신 빌드의 정상 속도·대사 ON MP4 1~3분과 짧은 장면 안내를 제공한다. 승인된 개인 iCloud Drive `Arucon/Reviews`를 재사용하되 **합성 데이터와 합성 대사만** 전달한다. 실제 건강 원본·사용자 건강 내용을 드러내는 대사/로그/DB를 이 전달 승인으로 업로드하지 않는다[S2]. 로컬 생성, 업로드, 모바일 재생 확인은 구분한다.

현재 직접 개발/SELF_REVIEW와 feature checkpoint/일반 push만 유지한다. main/merge/배포/실건강 연결/실결제/보안 설정 변경/DB 초기화는 하지 않는다. 원본과 작업 중 변경을 보호하고 기술적 결함은 직접 수정·재검증한다.
