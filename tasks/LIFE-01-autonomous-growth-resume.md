# LIFE-01 — 화면 복구 + 자율 생활·성장 중심 재개

이 문서 전체를 `tasks/LIFE-01-autonomous-growth-resume.md`로 저장하고 현재 아루콘에서 실행해라. 문서 저장이나 계획 작성만으로 종료하지 마라.

## 1. 현재 상황과 목표 변경

사용자는 이전 잠금 해제 후 재개 프롬프트를 아직 전달하지 않았다. 현재 Mac 잠금은 해제했다고 알렸다. 실제 화면/입력 접근을 먼저 확인하고, 이전 보고서의 BLOCKED_HOST_LOCKED를 그대로 복사하지 마라. 다시 잠기면 해당 검증만 정확히 차단으로 기록한다.

사용자가 최신 앱에서 다시 확인한 문제:
- 화면이 여전히 깨진다.
- 사람이 반복해서 놀아줘야 하는 비중이 크다.
- 플레이의 결과로 성장·외형 변화·기질 발현이 잘 보이지 않는다.
- 펫이 혼자 생활하는 느낌보다 이동하는 캐릭터와 수동 미니게임처럼 느껴진다.

최상위 목표를 다음으로 수정한다.
“사용자는 현실에서 걷고·뛰고·수면을 취한다. 그 결과가 기존 규칙에 따라 펫의 성장으로 이어지고, 펫은 스스로 생활한다. 사용자는 달라진 모습과 그 아이다운 버릇을 발견하고 필요할 때 짧게 교감한다.”

핵심은 수동 놀이 횟수가 아니라 자율 생활·성장·발견이다. LIFE-00의 ‘놀이 3종 수행 중심 대표 플레이’와 충돌하면 이번 우선순위를 적용한다. 기존 놀이를 폐기할 필요는 없지만 선택 활동으로 낮추고, 자율 생활의 선행 조건으로 두지 마라. 수동 놀이에 EXP나 코인을 붙여 필수 숙제로 만드는 것은 이번 해결책이 아니다.

## 2. Astra 직접 개발과 보존

ASTRA_DIRECT를 유지한다. 새 서브에이전트를 만들지 않고 직접 설계·수정·앱 조작·자체 검토를 수행한다. 검토는 SELF_REVIEW라고 기록한다. 강제 모델 위임/단계별 승인 규칙만 필요한 범위에서 정리하고 자동 검사·데이터 보호는 유지한다.

현재 branch/HEAD/미커밋 변경과 설치 앱을 확인해라. 원격에서 확인된 체크포인트는 c79f158이지만 현재 로컬이 같다고 가정하거나 과거 커밋으로 reset하지 마라. 보고서상 앱 코드 커밋과 문서 커밋도 구분한다.

AGENTS.md, LIFE-00, LIFE-00-REPORT.md, NEXT-RESUME.md, 현재 SRS/DEC/config, 생활·성장 구현의 관련 범위를 읽고 재사용한다. 새 앱·새 엔진을 먼저 만들거나 기존 저장본을 초기화하지 마라. 사소한 기술 선택은 스스로 결정하고 실제 구현을 진행한다.

## 3. 화면 깨짐부터 실제로 해결

다른 기능을 늘리기 전에 사용자가 보는 설치 앱에서 기존 일반 방과 별도 생활 체험을 모두 열어 재현하고, 같은 장면의 수정 전후를 남겨라.

UI 겹침/잘림/안전영역 문제와 3D 렌더 문제를 구분한다. 후보로는 GLView 크기/재생성, 렌더 해상도, 재질/조명, 카메라/클리핑, geometry batching, morph/normal 변환, v3 및 진화 자산을 확인하되 증거 없이 원인을 확정하지 마라. 필요하면 보존된 원본과 후보를 같은 카메라로 비교해 자산 문제와 렌더러 문제를 격리한다.

- 정상 앱에서 방·펫·가구·얼굴·텍스트가 찢어지거나 겹치거나 잘리지 않아야 한다.
- 대화/저장/패널 변화로 방이나 GL 컨텍스트를 불필요하게 재생성하지 않는다.
- 대화 중 호흡·시선·귀까지 얼어붙거나 입력이 잠기는 문제를 재검사한다.
- 기록 열기·닫기, 직접/버튼 쓰다듬기, 손 떼기·취소 후 재접촉을 확인한다.
- ‘로컬저장중’ 깜빡임과 ‘손길에 반응했어요’만으로 몸 반응을 대신하지 않는다. 실제 저장 실패는 숨기지 않는다.
- SOURCE_SYNTHETIC·내부 enum·중복 제목을 일반 방에서 제거하고 실제 건강 미연결 안내는 작은 체험 표시와 설정에 남긴다. 사용자 이름은 보존한다.

프레임 저하를 ‘시뮬레이터라서’라고 단정하지 마라. 기존 3Hz/30Hz가 요청·계측·실제 표시 중 무엇인지 확인한다. 같은 Release 조건에서 프레임 간격/긴 멈춤/입력 지연을 비교한다. 영상 FPS나 RAF 횟수를 실제 표시 성능으로 대체하지 않는다. 기존 LIFE-00 성능 목표는 유지하며 실패 후 기준을 낮추지 않는다.

## 4. 아무것도 누르지 않아도 자기 생활을 하게

깨어 있는 펫은 사용자의 클릭 없이도 주변 살피기, 몸 풀기, 자리 선택, 혼자 공 건드리기/따라가기, 소품 탐색, 편안히 앉기, 작은 장난과 정돈을 스스로 시작·수행·종료한다. 계속 이동만 하거나 몇 개 동작을 고정 순서로 재생하는 자동 시연은 아니다.

현재 필요·사물·자세·성격·최근 경험으로 다음 의도를 선택하고, 수행 중 의도와 취소/복구를 관리한다. 사용자에게 놀이를 제안할 수 있지만 답변 대기 때문에 생활 전체가 멈추면 안 된다. 무응답이면 스스로 다른 일을 한다. 때로는 말없이 다가와 앉고, 때로는 혼잣말이나 작은 장난을 보인다. 말풍선 빈도로 생동감을 흉내내지 마라.

공이 없거나 사람이 놀아주지 않아도 기본 생활과 기질 표현이 나온다. 수동 놀이를 해야만 생활 장면·기본 성격·성장을 해제하는 조건을 만들지 않는다. 사용자의 손길은 이미 진행 중인 생활에 자연스럽게 끼어드는 선택적 교감이다.

이번 검토 기준으로, 깨어 있고 기본 환경이 준비된 상태에서 3분 무입력 관찰 시 이동을 제외한 의미가 다른 행동을 3계열 이상 볼 수 있게 해라. 이는 관찰 시험 조건이며 허기·배설·경제 시계를 빠르게 돌리라는 뜻이 아니다. 타임라인 고정 대본이나 테스트 전용 선택 경로로 통과시키지 마라.

## 5. 다마고치처럼 시간에 따른 생활 신호

허기·섭취·배설·수면/휴식의 기존 실제 규칙을 재사용하고 화면에 연결해라. 먼저 현재 앱이 적용하는 허기 증가율·식사 임계값·배설 조건·수면/동면 조건·전경 갱신 간격을 짧은 표로 확인한다. 이름에 source/dev/approved가 붙은 설정 중 실제 적용 경로가 무엇인지 확인하고, 문서의 옛 숫자를 가져오지 마라.

[허기와 식사]
- 실제 허기가 임계값을 넘으면 그릇을 보거나 다가가고, 필요할 때 ‘밥 먹을까?’ 같은 짧은 말로 상태를 드러낸다.
- 식탁 설치·자동급식 동의·먹이·수면 등 기존 조건을 충족하면 사용자 버튼 없이 기존 서비스로 먹고, 실제 확정된 섭취 결과를 연출한다.
- 식탁이 없거나 먹이가 부족하면 사실에 맞는 한 번의 안내/행동을 제공한다. 계속 조르거나 전체 플레이를 잠그지 않는다.
- 같은 허기 상태를 매 틱 새 사건처럼 발화하지 않는다. 상태 변화와 재알림 정책을 구분한다. 배가 부른데 ‘배고파’를 랜덤 출력하지 않는다.

[배변과 화장실]
- 기존 시간·섭취 조건에서 확정된 배설 사건을 준비 동작→화장실 이용→나와 몸 정돈으로 보여준다.
- 기본 화장실과 자동 청결은 유지한다. 배변을 보여주려고 바닥에 강제로 변을 남기거나 청소를 필수 숙제로 만들지 않는다.
- 기존 저장에 실제 잔여물이 있으면 청소와 반응이 작동하고, 없으면 정상 상태로 안내한다.
- 화장실/청소 연출의 중단·재실행이 배설 사건이나 정산을 중복시키지 않는다.

[휴식·시간·복귀]
- 쉬는 자리 고르기·꾸벅임·편안한 자세를 스스로 표현한다. 장식 졸음이 실제 수면/회복 기록을 꾸며내지 않는다.
- 경제·허기·배설 시간은 기존 엔진이 한 번만 정산한다. 프레임이나 말풍선 타이머로 진행량을 만들지 않는다.
- 앱이 닫힌 동안은 현재 부재 정산·동면 정책을 유지하고 복귀 시 상태를 정합하게 반영한다. 무한 백그라운드 렌더, 자동 Health 읽기, 오프라인 무제한 EXP 적립은 이번 승인 범위가 아니다.
- 빠른 체험을 위해 일반 허기·배설·성장 주기를 몰래 줄이지 않는다. 주기 자체의 제품 변경이 필요하면 추천과 영향을 별도 기록하고, 그 전에 가능한 연결·표현 수정은 계속한다.

## 6. 성장 자체가 주 보상으로 느껴지게

게임의 주 성장 경로는 기존 계약대로 유지한다.
실제 활동(현재 테스트는 합성 입력) → 먹이·코인 → 실제 섭취 확정 → EXP/레벨 → 단계·진화 변화.
수면 결과는 승인된 성장 보너스·회복에 반영한다. 걷기나 대화마다 EXP를 별도로 더해 이중 지급하지 않는다.

사용자가 느껴야 할 보상은 새 레벨 숫자만이 아니다.
- 확정된 성장 직후 작은 축하와 ‘무엇이 달라졌는지’를 볼 수 있는 결과.
- 같은 행동에서 성장 전후 자세·솜씨·몸짓·표현의 변화.
- 다음 단계에 실제로 준비된 변화의 간단한 예고.
- 진화 후 외형 변화와 함께 이어지는 기존 이름·취향·기억.
- 실제로 본 새로운 버릇/몸짓을 다시 떠올리는 선택적 기록. 수집 숙제는 아니다.

현재 성장 표현이 첫 단계 뒤 앞발 응답 하나에 그치는지 조사해라. 부족하면 이미 승인된 단계에 연결되는 시각적·행동적 변화로 확장하되, 레벨/진화 산식이나 경제 보상은 바꾸지 않는다. 한쪽 앞발을 양쪽으로 바꾸는 정도만으로 성장 체감을 충분하다고 판정하지 마라.

‘수동 놀이를 안 하면 성장할 수 없다’는 전역 선행 조건은 없어야 한다. 기존 진화 결정표의 교감 기록 영향은 그대로 확인하고, 자율 행동을 사용자의 교감 기록으로 조작해 분기 조건을 채우지 마라. 기존 분기 규칙 변경이 정말 필요하면 근거와 범위를 분리한다.

## 7. 성장할수록 그 아이다운 기질이 선명하게

기본 성격·순간 감정·생활 취향·성장 표현을 구분한다. 건강 데이터를 사용자 MBTI나 성격 진단으로 해석하지 않는다. 외형과 성격을 강제로 일대일 대응시키지 않는다.

성격을 메뉴에서 골라야만 개성이 보이는 상태로 두지 마라. 일반 개체의 저장된 성격으로 자율 생활부터 실제 차이가 나야 한다. 비교용 성격 선택기는 개발 도구일 뿐이다.

츤데레는 얼굴은 무심하지만 공을 먼저 가져다 놓거나 곁에 앉는 행동으로, 솔직한 아이는 바로 눈을 맞추고 기대는 방식으로 같은 애정을 표현한다. 성장하면 이 스타일을 유지하면서 행동과 표현이 더 분명해지게 하라. ‘흥/싫진 않지만’ 두 문장 반복으로 성격을 대신하지 마라.

자율 생활에서도 취향이 드러날 수 있게 하되, 기억에는 실제 일어난 게임 사건만 기록한다. 새로운 선호 정책이 필요하면 크기 제한·반복 억제·버전과 되돌리기를 둔다. 교감 연타 보상·접속 안 했을 때 애정 감소·외로움 벌점은 추가하지 않는다.

## 8. 성장을 실제로 확인하는 시험을 끝내라

‘성장 코드는 있으니 테스트만 남았다’고 통째로 분류하지 말고, 계산 / 저장 / 실제 변화 / 기질 표현 / 자산 / 시각 검증을 나눠 점검하고 빈 연결은 구현해라.

다음 두 경로를 별도로 검증한다.
A. 현재 일반 방의 정상 시간·입력·기존 자원에서 자율 생활과 허기/식사 조건이 작동하는가.
B. 별도 체험 저장에서 실제 성장과 생활 경계를 빠르게 재현할 수 있는가.

B에서는 레벨업 직전, 성격 발현 비교 단계, 1차 진화 직전, 허기 임계값 직전, 배설 사건 직전 상태를 격리해 준비한다. 체험임을 표시하고 일반 이름·DB·재화·위젯 상태를 변경하지 않는다.

- 성장 체험은 ‘진화형 강제 선택’ 대신 동일한 섭취 서비스로 EXP 경계를 통과해야 한다.
- 진화에 레벨 외 관찰 일수 등이 필요하면 합성 이력으로 전제조건을 명시해 준비한다. 일반 저장에 이력을 만들어 넣지 않는다.
- 자동급식 체험은 식탁과 동의/먹이 등 조건을 갖추고, 버튼 없이 허기 경계부터 섭취·성장·새 표현까지 이어지는 것을 확인한다.
- 다른 조건이 같고 수면 보너스만 다른 두 격리 사례에서 실제 섭취 결과가 승인 규칙대로 달라지는지 보여준다. 실제 사람의 수면 데이터는 읽지 않는다.
- 레벨업/진화 후 재실행해 결과가 유지되고 중복 지급·재추첨이 없는지 확인한다.
- 말루·모노·피코·몽글은 실제 모델 선택 경로와 자산을 확인한다. 공통 GLB나 이름 교체만으로 외형 진화 완료라고 하지 않는다.
- 버튼으로 모델만 바꾸는 아트 비교와 실제 성장에 따른 모델 전환을 서로 다른 시험으로 기록한다.

체험에서만 새 생활 시스템이 돌고 일반 방은 예전 배회만 하는 분리는 허용하지 않는다. 차이는 초기 상태/자원/가구여야 하며 핵심 코드 경로는 공유한다.

## 9. 이번 대표 플레이와 완료 증거

기존 ‘사람이 놀이 3종을 연속 수행하는 영상’ 대신 아래 흐름을 중심으로 같은 설치 빌드의 정상 속도 연속 플레이를 기록한다.

1. 일반 방 열기 → 무입력으로 비이동 자율 생활 관찰.
2. 짧은 손길 1~2번 → 그 아이다운 반응 → 사용자가 다시 관찰만 해도 자기 생활 복귀.
3. 실제 상태에 맞는 생활 신호와 자연스러운 말풍선 확인.
4. 격리 체험임을 명시한 뒤 허기 경계 → 조건이 갖춰진 자동 식사 → 실제 성장 결과.
5. 성장 전후 같은 행동/기질 비교, 진화 경계와 실제 외형 전환.
6. 배설 경계 → 화장실 → 자동 청결 유지 → 자기 생활 복귀.
7. 기록 열기·닫기, 대화 닫기, 앱 전환·복귀, 종료·재실행 후 상태 유지.

전체를 강제 대본·내부 함수 호출·장면 순간이동으로만 연결하지 마라. 실제 시간으로 기다리는 일반 플레이와 격리 경계 시연은 구분한다. 하나의 10분 영상만으로 장기간 성장/성능을 모두 검증했다고 하지 않는다. 필요한 경계 자동 검사와 원자성·시간 중복·앱 수명주기 회귀를 함께 수행한다.

같은 환경 전후 화면, 실제 입력 경로, 선택/사건 trace, 성능 측정 한계를 남긴다. 편집·배속·실패 장면 삭제로 품질을 과장하지 않는다. 앱 코드를 바꾸면 그 코드가 반영된 빌드에서 다시 확인한다.

## 10. 종료·Git·권한

화면 깨짐/대화 정지/접촉 무반응이 남으면 REWORK_REQUIRED다. 필수 실행 검증이 환경으로 막히면 PARTIAL_WITH_BLOCKERS다. 자율 생활·성장 변화가 실제 경로로 확인된 경우에만 READY_FOR_AUTONOMOUS_LIFE_REVIEW로 보고하고 재미·최종 아트는 USER_REVIEW_PENDING으로 둔다. iOS 결과를 Android/실기기 결과로 재사용하지 않는다.

현재 허용된 개인 origin과 feature/arucon-mobile-autonomous의 논리적 checkpoint commit/일반 push만 유지한다. main/merge/force push/배포/실결제/실제 건강정보 읽기/새 외부 서비스/관리자·보안 설정 변경은 하지 않는다. 비밀·실제 DB·빌드·사적 로그·대형 증거 영상은 임의 업로드하지 않는다.

새 공정·보고서 증설보다 실제 앱 수정을 우선한다. LIFE-00-REPORT.md와 기존 status/gap/재개 안내의 관련 부분을 갱신하고, 과거 결과는 보존한다. 최종 보고 첫 부분에 ‘내가 놀아주지 않아도 무엇을 하는가 / 생활 상태가 어떻게 드러나는가 / 어떻게 성장하고 무엇이 달라졌는가’를 실제 증거로 적어라.

Mac이 열려 있는 지금 직접 확인 가능한 경로부터 진행해라. 중간 단계마다 사용자 승인이나 수동 시험을 요청하지 말고 가능한 수정·검증을 계속한다. 권한·한도·호스트 잠금을 우회하지 않으며 중단이 필요하면 체크포인트와 다음 한 작업을 보존한다.
