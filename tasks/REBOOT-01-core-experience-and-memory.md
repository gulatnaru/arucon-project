## 1. 이번 지시의 의미

사용자는 기존 LIFE-02를 플레이한 뒤 ‘재미와 원래 방향이 충족되지 않았다’고 평가했고, 다시 작은 단위로 개발하기를 승인했다. 과거 자동/기능 PASS는 보존하되 현재 아트·재미 승인으로 재사용하지 않는다.

이번 결과물은 문서나 기술 데모만이 아니라, 기존 앱 안에서 열 수 있는 **분리된 리부트 검토판**이다. 핵심은 아기→성장기→진화 후 같은 아이가 달라지는 매력과, 경험 때문에 반응이 달라지는 장면이다. 모든 상점·진화형·20개 레벨 콘텐츠를 동시에 다시 만들지 않는다.

기존 수면/동면 복귀, 시간 정산, SQLite 공통 파일 대기열·오류 원인 구분, 중복 정산 방지, 가속 성장 서비스는 재사용한다. 앱·DB·Git 이력을 삭제하거나 과거 SHA로 reset하지 않는다. 원격 기준과 로컬 HEAD/dirty/실제 설치본이 다르면 먼저 대조하고 사용자 작업을 보존한다.

## 2. 사용자 확정 요구 — 이전 문서보다 이번 리부트에 우선

- 뿔은 **하나**다. 유니콘 느낌의 작은 나선형 뿔을 기본으로 한다. 진화 후에도 두 뿔·양/염소형으로 바꾸지 않는다. 색은 은은한 진주빛·파스텔 계열을 제작 초안으로 비교하되 최종 색 승인으로 기록하지 않는다.
- 게임 화면에서 펫은 이전보다 작고, 방은 더 깔끔하다. 작게 만들어 표정이 안 보이는 문제도 실제 화면에서 확인한다. 얼굴·전신 동작의 읽기성과 충분한 이동 공간을 동시에 확보한다.
- 아기부터 완성된 성격을 지정해 같은 대사를 재생하는 방식이 아니다. 작은 잠재 기질이 성장과 실제 경험을 통해 더 구체적인 몸짓·거리감·취향·말투로 드러나야 한다. 외형 계열과 성격을 일대일로 고정하지 않는다.
- 성장하면서 외형·표정·움직임·행동·말투 모두 변화한다. 스케일 조정, 설명 문장, 앞발 몇 번 움직이기만으로 충족하지 않는다.
- 시크함을 무기력함으로 해석하지 않는다. 활동적인 탐색·짧은 달리기·자발적인 장난과 편안한 휴식의 리듬을 만든다.
- 공놀이·까꿍·따라 하기 등 **수동 미니게임과 해당 메뉴·공 소품은 리부트 기본 화면에서 제외**한다. 사용자 교감은 직접 접촉이며 반복 입력은 성장의 필수 조건이 아니다. 구 저장의 아이템 소유권은 삭제하지 않는다.
- 기본 화면은 이름, 현재 Lv, 현재 EXP 진행 게이지, 단정한 메뉴 버튼을 중심으로 한다. **다음 행동/진화/변화 예고, 미발견 실루엣, 해금 목록은 노출하지 않는다.** 이미 발견한 변화만 회상할 수 있다.
- 메뉴는 ‘우리 아이 / 상점·꾸미기 / 설정’ 수준으로 단순하게 한다. 이번에 미구현인 상점 항목을 작동하는 척 전시하지 않는다. 깨어나기·동면 복귀·실제 오류 복구는 해당 상황에서 쉽게 찾을 수 있어야 한다.
- 향후 코인 소비 범위는 안경·모자·목도리 같은 **착용 아이템**, 가구·방 꾸미기, 성장에 유리한 먹이, 구매 후 자동 청소되는 변기다. 여기서 웨어러블은 실제 건강기기 연동이 아니다.
- ‘구매 변기’와 ‘코인 성장 먹이’는 새 리부트 방향이다. 이전 ‘기본 변기 제공/작은 카탈로그’ 지시로 이를 거부하지 않는다. 다만 이번 첫 작업에서 일반 저장의 시설을 회수하거나 가격/성장 배율/최대 레벨을 바꾸지 않는다. 후속 구현 시 새 시작 정책과 기존 저장 이전을 구분한다. 현금 성장 판매 승인이 아니다.

이전 AGENTS/스킬의 ‘새 기능 금지’, ‘기존 체형 변경 금지’, ‘현재 personality만 유지’ 등이 이번 승인된 후보 제작을 막으면 **적용 범위만 최소 수정**한다. 과거 문서 전체 삭제·검사 기준 약화·사용자 전역 설정 변경은 하지 않는다.

## 3. 첫 작업의 경계와 순서

### A. 한 성장 계열의 세 모습과 한 교감 장면

현재 모노 계열을 우선 검토 후보로 쓰되 최종 계열/아트 선택은 아니다. 아기, 대표 성장기, 1차 진화 후의 세 모습을 같은 조명·카메라에서 제작한다. 이름과 한 뿔 계보는 이어지지만 체형 비율·귀·자세·얼굴 인상은 설명 없이 성장 차이가 보여야 한다. 기존 GLB를 억지로 늘리는 방법만 고집하지 않는다.

정지 비교를 먼저 만든 뒤 **같은 ‘손을 내밀고 거두는 상황’**을 세 단계로 실제 렌더한다.
- 아기: 시선 추적→작은 접근→조심스러운 접촉→손을 놓은 뒤 확인.
- 성장기: 먼저 접근→짧은 망설임/그 아이다운 장난→기대기→스스로 복귀.
- 진화 후: 익숙한 접근과 분명한 개성→안정된 체중 이동→그 아이의 마무리 습관.

이 장면 예시는 연기 목표이며 고정 대본을 생활 AI의 증거로 삼지 않는다. 말풍선을 가려도 의도와 성장 차이가 읽혀야 한다. 피부/귀/장착물의 연결, 발 미끄러짐, 바닥 관통, 회전의 급변, 눌림/복원을 전·중·후에서 본다. 손이 닿기 전에 반응을 시작하거나 손을 뗐는데 눌린 자세가 남지 않게 한다.

검토 화면에서는 세 단계를 비교할 수 있지만, 이를 실제 EXP 지급·진화 진행이라고 표시하지 않는다. 정상 게임의 성장과 비교 프리뷰를 구분한다. 이 세 단계의 매력을 먼저 평가하고, 그 뒤 기존 Lv.1→20 연속 성장에 확장한다. Lv.20 검토 목표를 취소하는 것이 아니다.

### B. 자율 생활 + 기억 반응 한 장면

아기 한 마리/같은 계열과 **착용 아이템 한 개(작은 모자)**, 이동 가능한 휴식 소품 한 개만 사용한다. 모자는 한 뿔을 없애거나 뚫고 지나가지 않도록 디자인/장착점을 정한다. 검토용 아이템과 소품은 분리된 합성 프로필에서 제공하며 코인 구매 완료로 가장하지 않는다.

정상 입력 경로:
1. 아무 입력 없이 주변을 살피고 목적 있는 짧은 이동/탐색을 한다.
2. 사용자가 처음 모자를 씌우면 실제 착용 확정→살피기→몇 걸음 움직여 확인→그 아이다운 표정/마무리.
3. 모자를 벗겼다가 다시 씌우면 ‘처음 본 물건’처럼 완전히 같은 순서를 반복하지 않는다. 실제 착용 경험이 선택에 반영된다.
4. 하던 일이 있을 때 같은 모자를 씌우면 현재 의도와 양립 가능한 반응을 하고 그 일로 돌아간다. 기억 때문에 매번 연기를 강제하지 않는다.
5. 휴식 소품을 옮기면 실제 좌표 변화에 맞게 살펴보고 이동한다. 옛 위치의 기억을 현재 사실로 오인하지 않는다.
6. 앱 재실행 후 같은 개체의 경험이 남고, 비교 프로필/다른 펫의 기억은 섞이지 않는다.

모든 생활에 대사를 강제하지 않는다. 동일 문장 순환을 ‘AI’로 포장하지 않고, 현재 상황·실제 기억·잠재 기질·성장 표현의 차이가 **행동 선택과 연기**에 나타나게 한다. 익숙한 버릇은 반복될 수 있지만 동일 루프 고착과 이유 없는 랜덤 행동은 다르다.

## 4. AI 실험 — 실제 추론을 확인하되 제품 핵심을 인질로 삼지 않는다

EmbeddingGemma 2는 검색/분류용 임베딩 모델 후보이며 자유로운 대사 생성 모델이 아니다[S1,S2]. MediaPipe Decision Maker의 iOS 안내가 검색되지만[S3], **공개 안내 존재와 현재 Expo55/Xcode/Simulator 조합의 실행 가능성은 별도**다. 검색 요약을 복사해 존재하지 않는 API·배포 패키지를 만들지 않는다.

### 착수 시 작은 실제 실행부터
- 공식 배포 모델 ID, 리비전, 파일 해시, 라이선스, 텍스트 전용 런타임/변환물, SDK 버전·지원 OS·Simulator 아키텍처를 확인한다. ‘latest’ 설치로 프로젝트 전체를 올리지 않는다.
- 현재 앱과 별개인 프로젝트 로컬 검증 환경에서 한국어 합성 문장 한 쌍을 **실제 모델로** 임베딩/유사도 계산해라. 이후 지원되는 iOS 경로를 연결한다. Mac 호스트 실행은 iPhone/Simulator 성공과 분리한다.
- iOS 연결은 Expo 로컬 네이티브 모듈과 재생성 가능한 설정을 사용한다[S4]. 생성된 ios 폴더만 수정해 다음 prebuild에서 사라지는 해결을 만들지 않는다.
- 모델 파일을 아직 못 받았거나 장치/SDK가 맞지 않으면 AI_ADAPTER_BLOCKED와 정확한 원인을 남긴다. 무한한 변환·재설치·다운로드 반복 대신 확인된 대안과 첫 장애 지점을 기록한다. 캐릭터/모션/기억 저장 작업은 독립적으로 계속한다.
- 임베딩을 하드코딩하거나 임의 난수 벡터로 바꿔 AI 연동 완료라고 하지 않는다. 테스트 더블은 테스트 범위로 표시한다.

### 비교할 두 경로
A: 정확한 게임 이벤트·구조화된 기억 조회 + 설명 가능한 행동 점수/상태 머신.
B: 같은 상태·자산·허용 행동에 실제 EmbeddingGemma 2 의미 검색을 추가. 필요할 때만 검증된 Decision Maker로 후보 순위를 보조.

공급/섭취/EXP/코인/시설 소유/현재 아이템 위치는 원래 서비스가 최종 권위다. 의미 유사도를 사실 판정이나 보상 명령으로 쓰지 않는다. 작은 기록에서 A가 충분하다면 B의 존재 자체를 채택 이유로 삼지 않는다. **비슷한 뜻의 다른 한국어 표현이나 여러 관련 경험을 찾을 때 실익이 있는지** 비교한다.

입력은 합성 게임 사건과 최소한의 로컬 맥락만이다. 사진·마이크·카메라·실제 건강 원본·연락처·사용자 사적 문서는 필요 없다. 외부 유료 추론/생성 API나 자유 대화는 이번 범위가 아니며 추가 승인이 필요하다.

### 런타임 계약
- 행동 시작 가능 여부를 결정하는 로컬 gate는 항상 먼저 실행한다. 수면/동면·입력 잠금·식사·장착 가능 여부를 우회하지 않는다.
- 기억 후보에는 petId, eventId, 발생시각, 실제 완료 여부, 아이템 ID, 근거와 버전을 둔다. 유사도만 높고 다른 펫이거나 취소된 사건이면 제외한다.
- `Decision`은 허용된 intentId/targetId/memoryIds/reasonCode만 반환한다. 새 애니메이션 이름·없는 가구·임의 SQL을 만들지 못하게 검증한다.
- 임베딩 추론은 별도 작업 큐로 사건 시 실행한다. 렌더 프레임·터치 첫 반응·DB 트랜잭션을 기다리게 하지 않는다. 동일 요청 합치기, 캐시, 취소, 시간 제한을 둔다.
- 요청 당시와 현재 상태 revision이 다르면 오래된 결과를 버리거나 재검증한다. 앱 전환·프로필 변경 시 취소하고 늦은 결과로 옛 모자/말풍선을 되살리지 않는다.
- 시간 초과·모델 미설치·실행 실패·무관한 검색 결과이면 A로 복귀한다. 기본 생활은 계속한다. 실제 모델 사용/대체 경로 사용은 개발 로그에 분리한다.
- 기억 저장은 기존 SQLite 파일 대기열·정리 완료 보장·bounded retry를 사용한다. 모델 추론/다운로드를 트랜잭션 안에서 하지 않는다. 경제 원장과 표현 기억을 같은 성공으로 오해하지 않는다.
- 배포 파일 다운로드 비용/용량, 앱 전체 메모리, 발열, 시작 지연은 별도다. ‘API 비용 없음’을 ‘운영비 0원’ 또는 ‘모든 폰에서 191MB’로 기록하지 않는다.

## 5. 도구와 스킬은 실행한 만큼만 기록

- 현재 채팅에서는 Context7으로 Expo SDK55 모듈 문서를 조회했고, 저장소의 `.agents/skills/arucon-visual-verification/SKILL.md`를 읽었다. 이것이 Mac Codex에서도 도구가 노출됐다는 뜻은 아니다.
- Codex의 실제 목록에서 Context7/Blender/Maestro/Figma와 로컬 명령을 확인한다. 확인된 도구는 버전·성공한 호출·해당 산출물을 남긴다. 설치 목록만으로 사용했다고 하지 않는다.
- Blender 또는 동등한 편집 환경이 있으면 원본을 복제해 체형·리깅·표정·전신 애니메이션을 시각적으로 다듬고 편집 소스와 runtime 자산을 함께 보존한다. 도구 부재를 핑계로 기존 모델의 축만 늘려 완성 아트라고 하지 않는다.
- 현재 가능한 Simulator 조작과 검증 스킬은 계속 사용한다. Maestro가 없다고 기본 검증을 중단하지 않는다. Context7이 안 보이면 정확한 공식 버전 문서로 진행한다.
- 새 전역 설치, 유료 에셋/생성 서비스, 계정 생성, 외부 이미지·DB 업로드는 자동 승인하지 않는다. 필요 사항은 한 번에 모아 요청한다. 공개 모델 다운로드가 계정 약관 동의·관리자 변경을 요구하면 그 부분은 승인 대기다.
- 단계별 강제 분업·새 reviewer 대기열을 만들지 않는다. 같은 세션이 직접 구현하고 SELF_REVIEW한다. 실제 스타일·계열 최종 선택은 사용자 검토다.

## 6. 이번 완료 증거

**시각:** 같은 게임 viewport에서 아기/성장기/진화 후의 비교와 동일 교감의 정상 속도 전·중·후 영상. 정지 이미지/생성 홍보 영상을 앱 실행 증거로 쓰지 않는다. 한 뿔·장착물·발·그림자의 접촉, 작아진 펫의 표정 가독성을 확인한다.

**행동/기억:** 처음 착용/재착용/다른 일 중 착용/소품 이동/앱 재실행을 같은 빌드의 정상 입력으로 확인한다. A/B에 같은 자산·상태를 주고 기억 유무만 바꾼 대조도 남긴다. 무작위로 행동이 달라진 것과 기억이 원인이 된 것을 구분한다.

**AI:** 합성 한국어 사례를 별도 평가 세트로 고정한다. 최소 24개 정도의 초안 사례에 같은 물건/다른 물건, 관련 기억 없음, 부정 표현, 취소된 사건, 상태 변경·오래된 결과를 포함한다. Recall@k/불필요한 기억 사용/허용 행동 위반/지연/메모리를 A/B로 비교한다. 이 개수는 새 작업 제안이지 제품 품질의 증명이 아니다. B가 더 낫다고 미리 결론 내리지 않는다. NaN/벡터 차원·정규화·모델 리비전 불일치도 검사한다.

**신뢰성:** 원본 Sim과 기존 성장 저장·아이템 소유·EXP/원장/위젯을 보존한다. 검토용 반복 재생이 보상/성격/기억을 중복 지급하지 않게 한다. 메뉴 닫기, 교감 취소, 수면/동면 복귀, 앱 재실행과 저장 경합의 관련 회귀를 유지한다.

**성능:** 같은 Release에서 AI OFF/ON을 비교하며 기존 렌더·입력 기준을 유지한다. 모델 최초 로딩과 warm 추론을 따로 기록한다. Simulator/호스트 실행과 실기기 GPU·물리 입력·발열·배터리는 분리하고 못 한 것은 NOT_RUN이다.

## 7. 자동 진행과 멈출 지점

짧게 설계하고 A→B의 연결된 장면까지 구현·영향 검사·실제 실행·수정한다. 사소한 기술 선택이나 테스트 한 번 통과로 사용자에게 돌아오지 않는다. 작업 중 잠금이 확인되면 동일 실패를 반복하거나 보안을 우회하지 말고 그 검증만 BLOCKED로 남기고 가능한 소스/자산 작업을 이어간다. 종료된 세션이 잠금 해제 때 저절로 재개된다고 약속하지 않는다.

현재 승인된 개인 origin의 feature 브랜치에서 논리적 commit과 일반 push만 허용한다. main/merge/force push/태그·배포/실결제/실제 건강 읽기/DB 삭제/OS 보안 변경은 하지 않는다. 모델 가중치·DB·비밀·빌드·대형 영상은 Git에 넣지 않는다.

이번 리뷰 전에는 전 계열·Lv1~20 새 콘텐츠·전체 상점·성장 먹이 가격·변기 정책 이전을 구현하지 않는다. 이들은 삭제된 요구가 아니라 **첫 핵심 장면 승인 뒤의 다음 단계**다.

첫 보고는 결과에 맞춰 하나로 정리한다.
- `READY_FOR_CORE_EXPERIENCE_REVIEW`: 실제 앱에서 세 성장 모습/연기와 경험 반응이 연결되고 관련 검증 완료. AI는 별도로 REAL_LOCAL_VERIFIED / NOT_ADOPTED_AFTER_COMPARISON / BLOCKED로 명시한다. AI가 BLOCKED면 AI 검증 완료라고 표시하지 않는다.
- `PARTIAL_WITH_BLOCKERS`: 제작/실행 환경 때문에 핵심 비교를 완료하지 못했다. 어떤 작업이 남았는지 하나씩 명시한다.
- `REWORK_REQUIRED`: 입력·저장·연기 연결의 명백한 결함 또는 기존 모델을 거의 그대로 보여주는 수준이 남아 있다.

기능 검사, 아트·연기 비교, 기억/모델 효과, 최종 재미 판단을 각각 분리한다. 사용자 재미/최종 아트는 `USER_REVIEW_PENDING`이며 과거 재미 불충족 피드백을 덮어쓰지 않는다. 첫 리뷰 후 한 번의 집중 수정 범위를 정하고, 이 승인 없이 전체 제작을 무한 확장하지 않는다.

보고는 기존 NEXT-RESUME와 리부트 결과 문서 하나에 모은다. 첫 줄에는 테스트 개수 대신 ‘실제로 무엇이 다르게 보이고, 어떤 경험이 다음 행동에 반영됐는지’를 적는다. 소스/설치 해시, 실제 도구 사용, 영상의 짧은 핵심 구간, 원본 보존과 AI 실행 환경을 함께 남긴다.
