# 아루콘 — 원격 검토용 MP4 전달 규칙

## 목적과 적용

사용자는 휴대폰에서 원격 Codex를 이용한다. 앞으로 앱 화면·행동·표정·성장·기억·UI가 변경된 작업을 사용자 검토로 넘길 때에는, Mac 로컬 플레이어 주소만 제공하지 말고 실제로 받을 수 있는 MP4를 전달한다.

이 내용을 프로젝트의 `docs/remote-video-delivery.md`로 저장하고, 루트 AGENTS.md에 ‘사용자 검토 완료 보고 시 이 문서의 MP4 전달 절차를 적용한다’는 짧은 항목을 추가한다. 기존 AGENTS.md·개발/검증/권한 규칙은 덮어쓰지 않는다. NEXT-RESUME.md에도 아직 미전달인 영상과 다음 전달 작업을 기록한다.

매 테스트·커밋마다 새 영상을 만드는 규칙은 아니다. 의미 있는 UI/플레이 변경의 검토 체크포인트마다 적용한다. 문서만 변경했거나 설치 앱 코드가 그대로면 기존의 해당 빌드 영상을 재사용하고 그 사실을 표시한다.

## 1. 먼저 실제 전달 경로부터 확인

- 현재 Codex 세션에 파일을 실제 첨부/전송하는 도구가 있는지 확인한다. 있으면 작은 기존 게임 영상 발췌 한 개로 전달을 시험한다. 새 기능을 개발하기 전에 한 번 경로를 확인하고 이후 재사용한다.
- `http://127.0.0.1:...`, `localhost`, `/Users/...` 링크는 파일 위치 안내일 뿐 휴대폰 전달 완료가 아니다. 로컬 서버를 켰다는 사실만으로 원격 접근 가능이라고 하지 않는다.
- 실제 런타임/전달 도구 근거 없이 `sandbox:/mnt/data/...` 주소나 외부 다운로드 URL을 만들어내지 않는다. 경로 문자열만 고쳐 보내지 않는다.
- 직접 첨부가 지원되지 않거나 실제 전달이 실패하면 `DELIVERY_BLOCKED`로 분리해서 보고한다. 사용자에게 승인된 개인 비공개 동기화/전송 경로가 이미 있다면 그 범위 안에서만 사용한다. 없다면 전달할 영상만 보관할 개인 폴더/서비스와 대상 계정을 한 번 확인받는다. 새 회사 계정·공개 사이트·포트 개방·터널·공개 저장소 업로드는 임의 진행하지 않는다.
- 승인받은 전달 방법은 다음 작업부터 같은 경로로 재사용한다. Mac에서 재생됐다는 사실과 사용자 휴대폰에서 재생됐다는 사실은 구분한다. 휴대폰 재생 확인이 없으면 SENT 또는 MOBILE_NOT_VERIFIED로 기록한다.
- ZIP은 첨부 형식 문제의 대안일 수 있지만, 파일 전송 자체가 없는 상황을 해결한 것으로 취급하지 않는다. 다운로드 뒤 독립적으로 재생할 MP4가 반드시 포함돼야 한다.

## 2. 기본 전달물

- 대표 시연 MP4 1개: 보통 1~3분, 최신 수정의 핵심을 바로 확인할 수 있는 정상 속도 영상. 게임 화면만 담는다.
- 비교가 필요한 작업에만 보조 MP4 최대 3개: 같은 상황의 성격/외형/수정 전후를 보통 20~60초씩 보여준다. 원본을 수십 개씩 휴대폰에 전달하지 않는다.
- 파일명은 `arucon_<task>_<build>_<sourceSHA>_<scene>.mp4`처럼 구별되게 한다. 'latest.mp4' 한 파일을 계속 덮어쓰지 않는다.
- 완료 보고에는 실제 첨부나 승인된 다운로드 위치, 길이, 용량, 소스/설치 빌드, 볼 장면 2~3개와 해당 시각을 적는다.

## 3. 화면·소리·용량

- MP4 전달용 인코딩은 H.264/일반적인 8-bit yuv420p를 우선 검토하고, 실제 음성이 있는 경우에만 AAC 등 호환 경로를 사용한다. 지원되는 기존 도구로 파일 앞부분부터 재생할 수 있게 패키징하고 디코딩 확인을 한다. 새 도구 설치가 필요하면 기존 승인 범위를 확인한다.
- 원래 세로 화면 비율과 가능한 원본 해상도를 유지한다. 데이터/파일 크기 때문에 경량본이 필요하면 '모바일 경량본'으로 구분하고 해상도·재인코딩 여부를 표시한다. 품질 비교용 PNG와 원본은 별도로 보존한다.
- 이동·입력·귀·눈·접촉 해제·복원이 보이는 길이를 확보한다. 너무 짧은 클립이나 끝부분 누락으로 정상 복귀를 가리지 않는다.
- 배속·프레임 보간·샤픈·생성형 보정으로 움직임을 좋게 보이게 하지 않는다. 발췌/장면 편집은 가능하지만 원본 시간 구간과 컷 경계를 기록한다. 원본·실패 증거를 보존하며 요약본을 무편집 증거라고 부르지 않는다.
- 손 교감·성격 비교가 있으면 대사 ON 일반 플레이를 기본으로 제공하고, 비언어 비교에 필요한 대사 OFF 구간은 별도로 표시한다.
- 개념 렌더/Blender 정지 시안을 MP4로 변환해 실제 앱 플레이로 표시하지 않는다. 성능 숫자는 영상 인코딩 FPS가 아니라 별도 계측 근거를 사용한다.

## 4. 녹화·보존·디스크 안전

- 같은 최종 설치 빌드의 원본 영상을 우선 사용한다. 수정하지 않은 앱을 영상 포장만 위해 재빌드하거나 DB를 초기화하지 않는다.
- 원본과 검토본을 별도로 관리하고, 검토본은 Git 제외 경로에 모은다. 새 모델·DB·SDK·전체 프로젝트를 영상과 함께 보내지 않는다.
- 디스크 여유와 예상 출력 크기를 먼저 확인한다. 최신 원본 증거와 검토본 하나를 우선하고 무제한 중복 변환을 피한다. 이전 영상·DB·Blender 원본의 자동 삭제는 승인 없이 하지 않는다.
- 실제 건강정보·계정·알림·개인 문서·토큰이 화면에 담기지 않게 한다. 사용자에게 보내는 합성 게임 시연만 전달 대상으로 한다.
- Mac 잠금이나 녹화 실패로 최신 시연을 못 만들면 NOT_RUN/BLOCKED로 기록하고 이전 영상을 최신 검증처럼 보내지 않는다. 보안 설정을 우회하지 않는다.

## 5. 완료 보고의 구분

개발 상태와 전달 상태를 따로 기록한다.

- VIDEO_READY: 원본/검토본 존재, 길이·해상도·실제 디코딩 확인.
- DELIVERY_SENT: 실제 파일 첨부 또는 승인된 개인 전달 경로로 전송/동기화 결과 확인.
- MOBILE_CONFIRMED: 사용자 휴대폰에서 다운로드·재생 확인을 받은 경우에만 사용.
- DELIVERY_BLOCKED: 파일은 있으나 원격 전달 경로가 없거나 전송 실패. 원인과 필요한 한 가지를 명시한다.

파일 생성만 했는데 '보냈다'고 하지 않는다. 첫 휴대폰 전달 경로가 확인된 뒤에는 기술 작업마다 같은 설정 승인 질문을 반복하지 않는다. 품질·기능 검증과 실제 전달 성공은 서로 대신할 수 없다.

## 6. 이번 v10에 바로 적용

현재 REBOOT-04 후속 v10의 실제 소스/설치 상태와 기존 원본 영상 파일을 확인한다. 코드나 저장을 바꾸지 말고, 기존 영상에서 귀·눈·장난/다정/도도 반응과 대사 ON 생활이 읽히는 1~3분 전달용 MP4를 만든다. 해당 장면이 기존 영상에 없으면 그 사실을 표시하고 실행 가능한 경우에만 같은 설치본에서 부족한 구간을 녹화한다.

로컬 review.html이나 localhost 주소를 다시 최종 전달물로 제공하지 않는다. 실제 MP4 첨부를 시도하고, 안 되면 같은 경로 제시를 반복하지 말고 승인된 개인 전달 경로 사용 여부를 한 번 확인한다.

이 문서는 앞으로 Codex 작업 종료 절차에 적용할 규칙이다. ChatGPT가 Mac 파일을 계속 감시하거나 종료된 Codex 세션을 자동 재개하는 예약 작업을 설정한 것은 아니다.

## 7. 승인된 개인 iCloud Drive 전달 경로

사용자는 개인 iCloud Drive의 `Arucon/Reviews`를 이번 v10 및 이후 사용자 검토용 MP4의 재사용 전달 경로로 승인했다. 필요한 경우 해당 영상의 짧은 장면 안내문도 허용한다. 최초 사용 전 현재 Mac 계정이 사용자의 개인 계정이며 대상 iPhone과 일치하는지 확인한다. 계정이 불명확하거나 다르면 복사 전에 그 확인만 요청한다. 같은 승인 계정과 범위가 유지되면 폴더 사용 승인을 반복 요청하지 않는다. 계정 이메일과 식별 토큰은 이 저장소 문서에 기록하지 않는다.

- 이미 활성화된 개인 iCloud Drive의 정식 파일 접근만 사용한다. 기존 공유 폴더나 다른 사람 소유의 폴더는 사용하지 않는다. 새 폴더는 해당 개인 Drive의 비공개 위치에 만들며 심볼릭 링크로 다른 경로에 쓰지 않는다.
- 파일명에 날짜(KST), 작업, 빌드, 소스 SHA를 넣는다. 같은 이름이 있으면 새 고유 이름을 사용하고 기존 파일을 덮어쓰지 않는다.
- 프로젝트 밖 쓰기는 승인된 `Arucon/Reviews` 폴더와 허용 MP4/장면 안내문으로 한정한다. 보안 설정이나 차단된 첨부 UI를 우회하지 않는다.
- DB, 건강정보, 비밀, 로그, 소스, 모델 가중치, 전체 evidence 폴더는 제외한다. 공개 링크 생성, 다른 사람 공유, 요금제 변경, 원본 이동/삭제, 이전 영상 자동 삭제도 제외한다.
- 원본과 복사본의 크기·SHA-256을 비교한다. macOS에서 확인 가능한 iCloud 업로드·오류·공유 상태를 기록한다. 로컬 복사만 확인됐으면 `LOCAL_COPY_VERIFIED / UPLOAD_PENDING_OR_UNVERIFIED`이며 원격 전달 완료로 올리지 않는다.
- iCloud 업로드가 확인되면 `DELIVERY_SENT / MOBILE_NOT_VERIFIED`로 기록한다. 사용자 iPhone에서 다운로드·재생 확인을 받은 경우에만 `MOBILE_CONFIRMED`로 바꾼다.

최초 확인 진행: 설정 화면에서 현재 Mac의 iCloud Drive '이 Mac 동기화' ON을 확인했다. 계정의 개인 소유와 대상 iPhone 일치 여부는 한 번 요청한 확인에 대한 답변을 기다린다. 답변 전 폴더 생성/MP4 복사는 하지 않는다. 실행 상태와 다음 전달 작업은 NEXT-RESUME 및 로컬 전달 감사에 남긴다.
