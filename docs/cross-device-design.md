# 아루콘 — 같은 아이를 만나는 여러 화면

버전 v1.5 · 2026-09-17 · 대응: SRS 3-6 / FR-10.1·12·21~23 / DEC-27~31

> 모바일에서 함께 성장하고, PC에서는 곁에 두며, 홈 화면에서는 잠깐 마주친다.

## 1. 역할과 경계

**모바일 본게임**은 건강 기록·먹이/코인·성장·돌봄·꾸미기·정식 생활 기록의 중심이다. **PC**는 이미 키운 펫의 모습을 가져와 관찰하고 가볍게 교감하는 접점이다. **위젯**은 마지막 확인 상태와 앱으로 들어가는 경로이고, **Android 라이브 배경화면**은 가능성을 검증하는 선택적 배경이다.

모든 접점이 같은 화면·같은 입력·같은 실시간성을 갖는 제품이 아니다. OS별 표현을 조정하되 petId·확정 외형·성격·가구의 정체성을 유지한다. 초기 PC에서 모바일 경제 쓰기를 대신하지 않는다.

## 2. 화면별 구성안

| 화면 | 주인공 | 항상 보일 정보 | 조작/이탈 |
|---|---|---|---|
| 모바일 방 | 작은 펫과 넓은 바닥, 가장자리 가구 | 이름·짧은 상태·최소 세 버튼 | 상세 패널, 쓰다듬기, 본게임 돌봄 |
| PC 작은 방 | 작은 방 속 같은 펫 | 필요할 때만 연결/갱신 상태 | 창 이동, 확대 보기, 펫만 보기, 숨김/종료 |
| PC 펫만 보기 | 배경 없는 작은 펫 | 평소 정보판 없음 | 쓰다듬기, 자리 이동, 메뉴를 통한 방 보기·종료 |
| iOS/Android 위젯 | 작은 펫 또는 작은 방 정지 모습 | 짧은 상태·확인 시각 | 앱 진입, 지원 검증된 비경제적 반응만 추가 |
| Android 라이브 배경 | 앱 아이콘 뒤의 방 | 아이콘 가독성을 방해하지 않는 표현 | 런처가 허용한 입력만, 본격 돌봄은 앱 |

정확한 크기·폰트·위젯 가족·배경화면 공개 여부는 DEC-31에서 정한다. 그림 하나를 줄여서 모든 접점에 쓰는 대신 작은 크기에서도 시크한 눈매가 읽히도록 별도 검증한다.

## 3. PC 상호작용 — 초기 기능은 경제와 분리

‘조용히 다가오는 아이’는 눈으로 먼저 살피고 짧게 머뭇거리다가 가까워진다. 쓰다듬으면 낮게 눌리고 귀가 늦게 따라오며, 얼굴은 무심한 인상을 유지한다. ‘먼저 다가오는 아이’는 더 빠르게 반응하되 두 성격의 성장/먹이/체력 조건은 같다.

허용: 보기, 무료 인사·쓰다듬기, 위치/크기·모드 변경, 숨김/종료, 연결 상태 확인. 제외: 먹이 소비, 구매, 자동급식 정책 변경, 수면/동면 전이, 진화, 성격 점수, 공식 일지 추가. 이 제외는 첫 PC 버전의 범위 제한이지 영구적인 불가능 선언이 아니다. 나중에 추가하려면 쓰기 권한·원자성·중복 처리를 별도 승인한다.

항상 위 표시/자동 시작 OFF와 무음 기본은 DEC-30의 세부 제안이다. 숨김/종료가 어렵거나 다른 창의 클릭을 막는다면 데스크톱 기능 완료가 아니다. 다른 앱의 화면이나 키 입력을 분석해 반응시키는 감시 기능은 범위 밖이다.

## 4. 동기화 예시 — 기술 계약은 PROPOSED

### 연결

현재 모바일 계정의 소유권을 확인한 뒤 PC를 읽기용 기기로 연결한다. PC가 선택한 이름/사진만으로 같은 계정이라고 신뢰하지 않는다. QR·일회용 코드·일반 로그인 중 구체 방식과 만료 기간은 아직 결정하지 않았다. 미연결은 연결 안내/합성 데모로 표시하고 새 실제 펫을 지급하지 않는다.

### 갱신

모바일 서비스가 식사를 한 번 확정하면 같은 revision의 결과가 PC/위젯에 전달된다. PC는 변경된 모습을 보여줄 뿐 먹이를 다시 차감하거나 EXP를 다시 주지 않는다. 여러 PC 창·위젯·배경 미리보기가 떠 있어도 도메인 결과는 한 번이다.

PC 로컬 배회 위치와 애니메이션 프레임은 별개다. 화면마다 같은 위치에 서 있을 의무는 없다. 다만 잠든 스냅샷에 활발한 식사나 깨우기 성공 장면을 붙이지 않는 안을 제안한다.

### 오프라인·오래된 상태

마지막 확인한 모습과 시각을 표시한다. 오래됨을 방치·질병·실제 사용자 수면으로 추측하지 않는다. PC를 계속 켜놓아도 독립 경제 시계로 미래의 배고픔·성장·치료를 계산하지 않는다. 최신 상태가 도착하면 지원되는 revision으로 교체한다. 만료 뒤 얼마나 보관/표시할지는 DEC-30/31에서 결정한다.

### 철회

로그아웃/철회가 확인되면 읽기 자격과 허용 캐시를 정리한다. 이미 오프라인인 PC를 즉시 지우는 것은 보장하지 않는다. 재연결 거부·오프라인 만료·재인증·공용 PC 경고의 구체 정책은 승인이 필요하다.

## 5. 세 종류의 시간을 섞지 않는다

| 시간 | 예 | 영향 |
|---|---|---|
| 게임 정산 시간 | 원장의 식사/수면/동면 처리 경계 | 승인된 서비스가 한 번 계산 |
| 데이터 확인 시각 | PC/위젯이 본 revision의 확인 시각 | 정보 신선도 표시, 보상 없음 |
| 표시 시간 | 로컬 귀·시선·스프링 프레임 | 미적 반응만, 경제·정식 성격 변화 없음 |

PC·위젯·배경화면의 실행과 로컬 교감으로 모바일 lastActiveAt을 갱신하지 않는 안을 DEC-30에 제안했다. ‘PC를 켜놓으면 동면하지 않아 더 많이 자란다’는 유리함을 만들지 않기 위한 경계다. 정확한 동면 시간은 기존 DEC-07의 미정 상태를 유지한다.

## 6. 개인정보와 접근성

표시 정보는 필요한 petId/형태/성격/가구/상태·버전·시각으로 제한하는 방향이다. 원시 건강 기록과 불필요한 활동 합계·수면 점수를 PC/위젯에 복제하지 않는다. 로그인 비밀, 이메일, 생년월일, 위치를 일반 진단 로그에 넣지 않는다.

작은 펫의 보이는 크기와 누를 수 있는 영역을 분리하되, 투명한 창 전체로 클릭을 가로채지 않는다. 메뉴/종료 접근 경로, 텍스트 상태, 움직임 줄이기를 유지한다. 위젯은 줄어든 애니메이션 조건에서도 정보를 잃지 않아야 한다.

## 7. 제작 및 검증 순서 — 제안

먼저 모바일 방과 동일 외형의 두 성격을 실제 크기에서 검토한다. 이후 PC 로컬 합성 시연으로 투명 창·입력·절전·표정을 확인하고, X0 승인 뒤 읽기 모델을 연결한다. 기본 위젯은 D5c, 추가 교감은 X2, Android 배경화면의 타당성은 X3로 나눈다. 세부 일정은 DEC-31이다.

사람 평가: 시크한 아이를 설명 없이 구분하는가, 업무를 방해하지 않는가, 아무 조작 없이도 곁에 두고 싶은가. 자동 검증: 자원 변화 없음, duplicate/revision/스키마·토큰 경계, 숨김 렌더 정지, 입력/다중 모니터/런처 동작. 각각 별도 증거가 필요하다.

## 8. Figma와 실행 코드의 역할

Figma 보드는 화면 역할·상태·흐름을 전달하는 설계 자료다. 정적 프레임과 링크만으로 투명 PC 창·OS 배경화면·실제 말캉한 물리/애니메이션·동기화가 완성되지 않는다. 원격 반영 상태는 [Figma 보고](../figma/FIGMA-STATUS.md), 이번 문서 정합성 결과는 [문서 검증](../validation/WORKFLOW-QA.md)에서 확인한다.
