# REBOOT-04 성격 기반과 대표 3종

게임용 펫 성격의 검토안이다. 인간 MBTI 검사나 건강 진단이 아니다. [작업 지시](../tasks/REBOOT-04-personality-foundation.md), [실행 결과](../REBOOT-04-REPORT.md)를 따른다. 일반 저장의 성격 ID와 기존 성장·경제 정책은 변경하지 않는다.

## 구조와 형성

기존 RebootDirector, BabyPlan, BabyLines, RebootMemoryStore를 확장했다. 별도 경제 엔진·DB·대사 선택기·LLM은 만들지 않았다.

네 연속축 approach / play / company / novelty는 각각 외향↔내향, 장난↔차분, 함께함↔독립, 탐색↔안정을 나타낸다. 범위는 [-1,1], 저장 버전은 1이다. 부호 조합의 16주소는 확장키이며 완성된 16유형 목록이나 실제 MBTI 코드가 아니다.

| 대표 검토안 | 네 잠재축 | 격리 petId |
|---|---|---|
| 장난꾸러기 | .8 / .85 / .25 / .65 | reboot-04:playful |
| 다정 | .6 / -.25 / .85 / -.2 | reboot-04:warm |
| 도도·호기심 | -.35 / .15 / -.55 / .9 | reboot-04:poised |

이 값은 가역적인 검토 초안이다. ID·잠재축은 접촉, 기분, 부재로 다시 추첨하지 않는다. 다양한 완료 경험 3상황과 실제 머리·몸 접촉이 있으면 함께함 표현에 .035, 두 쿠션 위치의 완료 경험이 있으면 탐색 표현에 .025 이내의 작은 힌트를 더한다. 다른 petId, 취소, 미완료 사건, 건강·수면·자동급식·미접속을 형성 입력으로 쓰지 않는다. 경제적 보상이나 우열도 없다.

성장 인터페이스의 stage / maturity는 아기 0, 성장기 .5, 진화 후 1이다. 대표 설계는 아기의 조심스러운 확인이 성장 후 익숙한 접근으로 이어지는 것이다. 이번 실행은 공통 아기 Lv.1의 3종 비교다. 성장기·진화형 자산과 레벨별 신규 콘텐츠는 구현 범위가 아니다.

## 행동·표정·대사의 도달 경로

| 일반 경로 | 장난꾸러기 | 다정 | 도도·호기심 |
|---|---|---|---|
| 주변 살핌 | 훑기→통통→앞발 장난→돌아보기 | 살피기→눈맞춤→발 인사→기대기 | 오래 살피기→냄새 확인→툭→짧게 돌아봄 |
| 새 대상 탐색 | 보기→도약→가까워 놀람→실수 정돈 | 살핌→작은 놀람→사용자 확인→옆 기대기 | 빼꼼→꼼꼼 확인→짧은 신남→태연한 정돈 |
| 식물 주변 | 숨듯 살피기→앞발 장난→몸 털기 | 확인→사용자 쪽→기대기→앞발 | 낮은 접근→자기 템포 확인→작은 발짓 |
| 작은 개인기 | 앞발→헛디딤→털기→통통 | 발 인사→작은 실수→편히 기대기 | 살핌→발끝 장난→민망→정돈 |
| 사용자 쪽 | 빼꼼→앞발→통통→눈맞춤 | 옆 기대기→발 인사→조금 오래 기대기 | 살핌→몸은 기대고 시선은 옆으로→다시 확인 |
| 쿠션 사용 | 누름→꼼지락→자리잡기→확인 | 누름→옆 기대기→짧은 하품→편한 자리 | 자리 확인→누름→자기 템포 정착→돌아봄 |

각 유형은 서로 다른 6개 인과 시퀀스, 6개 접촉 동작 후보, 6개 이상의 얼굴 패턴을 지원한다. 기존 표정 morph와 몸·발·도약·정돈 동작을 재사용하며 진행 순서와 후속 행동을 바꾼다. 대사 수나 ID만으로 장면을 세지 않는다. 자동 검사로 후보 도달성을 검증하고, 실제 관찰된 부분은 실행 보고서에서 별도로 센다.

행동 선택은 네 축, 깨어 있는 상태, 이동·접촉, 현재 방 대상과 최근 2장면을 읽는다. 머리·몸 접촉은 진행 중 장면, 같은 개체의 완료 손 기억, 최근 2접촉 스타일도 읽는다. 의도는 완료나 취소까지 유지한다. 짧은 탭에도 후속 몸짓이 이어지며 이동·메뉴·수면·앱 전환은 취소할 수 있다.

발화 표시 이력과 실제 행동 완료 기억은 구분한다. 대화가 호흡·표정·일반 입력을 전역으로 정지시키지 않는다. 선택이나 DB 쓰기를 매 프레임 실행하지 않는다. 취소된 장면은 완료 기억이나 보상을 만들지 않는다.

## 저장·실패·비교

기존 격리 arucon-reboot-review.db의 JSON 기억에 성격 기반과 RNG 상태를 저장한다. petId·버전·유한 축 값·64개 사건·32KiB 한계를 검사한다. 처음/최근 사물 경험을 기존 크기 한계 안에 보존한다. 원장은 기존 서비스와 공통 SQLite 대기열을 사용한다. 단순 기억 저장 실패를 경제 성공으로 바꾸거나 원본 DB를 초기화하지 않는다.

쿠션 배치는 UI 클릭 시점의 오래된 revision을 대기열에 들고 가지 않고, 실행 시점의 최신 기억을 읽는다. 취소 epoch와 저장 가드는 유지한다. 오래된 위치는 확인 시선에만 쓰고 접근·정착·완료 기억은 현재 쿠션 위치를 사용한다.

3종 모두 같은 방, 공통 네발 GLB, +35 크기, DPR2.5/AA0, 일반 모션에서 비교한다. 제목은 모두 아루다. 성격명은 검토 메뉴에만 있고 말풍선 가리기로 비언어 비교가 가능하다. 개체별 실제 관찰 이력은 보존하며, 영상마다 누적 이력과 조작 시점을 기록한다. 초기화로 동일 이력을 꾸미지 않는다. 최종 크기·렌더 설정은 이 검토로 확정하지 않는다.

## 2026-10-11 동일 조건 비교 보강

**우리 아이 → 합성 동일조건 성격 비교**는 새 `reboot-04:compare:<caseId>:<profile>` 소유자만 만든다. 원래 세 개체와 일반 저장을 초기화하지 않는다. 기존 소유자에는 합성 seed를 넣을 수 없으며 이미 있는 비교 기억도 덮지 않는다.

같은 아기·아루·Lv1/EXP0/coin0/food0·awake/well/체력100/허기50·화장실·쿠션(-1.6,.2)·모자없음·quad/+35/2.5-AA0/일반모션·RNG0x3412abcd. 같은4개 합성 완료 경험(머리/몸 손, 쿠션, 주변 살핌)에 `synthetic_comparison` 출처를 붙인다. 원래 실제 경험이라고 주장하지 않는다. 도메인만 고정 anchor이며 표현·trace는 정상 시각이다. 기존 서비스로 생성/입력하며 경제 엔진·schema·원장·일반 시간은 그대로다.

표현 힌트는 비교용 고정 seed 경험을 읽어 누적량 차이를 막는다. 새 정상 완료는 새 소유자의 기존 제한된 기억에만 저장한다. 본래 세 아이의 일반 경로는 실제 기억을 계속 읽는다. **성장에 따른 성격 형성 검증이 아니다.**

시작 → asset-ready/interactive →30초 준비 → 정상 director60초. 시간 창은 장면을 강제 선택하지 않는다. 메뉴/배경으로 중단되면 성공 창으로 조용히 재시작하지 않는다. 성격명은 선택 메뉴에만, 방 이름은 모두 아루, 말풍선 기본 숨김. 성능의6접촉과 제품의 관찰/손 제안/거두기는 별도 절차다. 영상은 동일 대기 목표를 사용하지만 실제 입력·화면 획득 지연/시각을 trace·PTS로 남긴다.

기존 손 연결에서 장난의 빼꼼·발짓·윙크, 다정의 head/side lean·머무름, 도도의 scan·놀람·시선 돌림과 복귀를 실제로 비교했다. 정지 기본 얼굴만으로 구별하는 차이는 약하다. 새 행동 카탈로그/대사를 대량 추가하지 않고 실제 비언어 연결의 사용자 판독·선호를 대기한다. 최신 정상 영상3개/원본 PNG/완료 trace를 남겼다.

## 공통 자산과 확장 경계

C의 원본을 읽기 전용 기준으로 실제 Blender Python에서 공통 네발 후보 하나만 제작했다. 두 뒤발·유연한 상단 연결·정규화 skin weight·대각 발 track을 추가하고 런타임 접지와 네 발 그림자를 연결했다. A/B/C와 원본 .blend/GLB는 덮지 않았다. 편집 원본은 art/reboot-04/common_quad.blend, 제작 소스는 같은 폴더의 Python, 런타임은 mobile/assets/reboot-04/common-quad.glb다. 최종 아트 승인은 대기한다.

이번 3종 검토 뒤 대비되는 극성·중간 조합으로 8종을 설계하고, 행동 중복을 정리한 뒤 16조합으로 확장한다. 사용자 검토 전 다음 범위를 제작하지 않는다. 상점·가격·성장 먹이·새 진화형·AI B/LLM·미니게임은 이번에 추가하지 않는다.

Context7 plugin MCP의 공개 문서 조회를 실제 실행했다. SDK55 선택 결과에 일부 main URL이 섞여 [Expo SDK55 SQLite 문서](https://docs.expo.dev/versions/v55.0.0/sdk/sqlite/)와 설치된 55.0.20 소스를 다시 대조했다. 트랜잭션 안에는 txn을 사용하고, 외부 쓰기는 기존 앱 대기열로 직렬화하며 statement 정리를 유지한다. SDK 내부 패치·새 설치·프로젝트 데이터 전송은 없다.

기능·표현 검토는 SOL_DIRECT의 SELF_REVIEW다. 재미·최종 아트·성격 표현 선택은 USER_REVIEW_PENDING이며 실제 모델 ID는 ROUTING_UNVERIFIED다.
