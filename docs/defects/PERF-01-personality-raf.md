# PERF-01 — 성격 검토판 RAF 미달

상태: OPEN / REPRODUCED_SAME_CONDITIONS. STORAGE-01 CANTOPEN VFS와 별개다.

2026-10-10 v4에서 장난/도도 녹화OFF RAF p95 37.07/47.18ms가 기준33.34ms를 넘었다. 당시180초ON과60초OFF의 구간·입력·호스트 조건이 달라 녹화 원인으로 단정하지 않았다.

2026-10-11 재감사는 새 합성 petId에서 동일 상태·고정 경험·공통 RNG·가구(-1.6,.2)·아기 quad/+35·DPR2.5-AA0·일반모션을 사용했다. 기존34개 저장은 보존했다. 준비30초/측정60초/녹화OFF/측정 진입을 실제 UI에서 확인한 뒤 동일한6회 접촉. 순서는 장난→다정→도도→도도→다정→장난이다. 호스트 top/메모리/부하를10초 간격으로 동일하게 남긴다. 첫 시각 맞춤 실패 사례도 보존한다.

현재 확인한 지배 비용은 Apple Software Renderer의 GL 큐 동기 대기다. 행동 판단·자세/CPU morph·draw 호출·endFrameEXP·flushEXP·프레임 처리와 예약 사이 대기를 각각 계측한다. 호출 enqueue 시간은 실제 GPU 비용이 아니다. RAF callback은 설치 RN0.83.10 JSTimers가 performance.now()를 전달한다. 예약 시점 가설은 낮은 idle 비용 때문에 주원인으로 확정하지 않았으며 일반 동작에 적용하지 않았다.

해상도/표정/행동/판정 기준을 낮추지 않는다. 실기기 GPU·표시FPS·물리 지연은 NOT_RUN이다. 재현된 병목에 대한 기술 변경은 같은 조건의 원본 화면과 순서 반전 측정으로 검증해야 한다. 성능 통과와 성격 비교 준비는 독립 판정한다. 상세 새 원본은 evidence/reboot-04-followup-2026-10-11/에 보존한다.

## 호스트와 남은 판정

전체12회 같은10초 샘플: 1분 load5.05~9.54, CPU idle6.97~62.38%, 압축메모리6129~7297MiB, unused59~527MiB. 원본 epoch/프로세스/VM은 각 -host.json에 있다. 부하·메모리 압축 변동은 관찰했지만 특정 다른 앱/드라이버의 인과를 확정하지 않았다. 최초 top 프로세스CPU0 샘플로 개별 앱을 범인으로 지목하지 않는다. epoch를 KST로 해석하며 시계·보안·다른 앱 설정을 변경하지 않았다. 측정 중 build/전체 검사/영상 캡처는 병행하지 않았다.

macOS15.6/Xcode26.3/iPhone16e iOS26.3.1 Simulator/Apple Software Renderer. **OPEN: 현 환경의 전체 프레임 기준 미충족.** 자동456개 통과와 성격 비교 준비가 이를 닫지 않는다. 실제 iPhone/Android/GPU/표시FPS/물리 지연/발열·배터리는 NOT_RUN이다. 후속은 같은 절차의 호스트 안정 조건 반복과 기기 계측에서 지속되는 병목을 분리하는 것이다. 해상도/표정/행동을 낮추거나 기준을 완화하지 않았다.

performance-summary.json은 완료된60초 capture.summary만 사용한다. 최근10초 live 값/영상 encoding FPS를 전체 성능으로 쓰지 않는다. [RN0.83 공식 timers](https://reactnative.dev/docs/0.83/timers)와 설치0.83.10 JSTimers.js의 performance.now() callback 전달을 대조했다. 실제 생활/손 교감은 [보고서](../../REBOOT-04-REPORT.md)의 별도 정상 속도 영상이다. 실제 GPU 원인은 이 proxy만으로 확정할 수 없다.
