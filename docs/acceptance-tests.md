# 아루콘 — 수용 기준 및 경계값 테스트 명세

버전: v1.7 · 개정일: 2026-09-18  
기준: `arucon-SRS.md`, `decisions.md`

> **이 파일은 테스트 설계서이지 실행 결과가 아니다. 운영 MVP 사례는 미실행이다. 별도 PROTO 실행 증거는 해당 시제품 패키지의 QA 보고서에서만 보고한다. 이 묶음의 prototype-spec.md에 역사적 실행 범위를 구분했다.** 원문 기준과 이번 제안의 기대값을 구분했다. 미승인 DEC에 의존하는 기대값은 승인 후에만 운영 수용 기준으로 사용한다. 자동 테스트 코드는 각 D단계에서 작성·실행하고 증거를 남긴다.

2026-09-19 모바일 재구성의 **개발 fixture 실행 이력**은 아래 별도 절과 [APP-06 QA](../mobile/docs/APP-06-validation.md)에 기록한다. 이 기록이 본문 설계 사례 전체나 운영 MVP의 미실행 상태를 통과로 바꾸지는 않는다.

> **v1.7 변경**: 기존 214개 사례를 유지하고 진화형 명명/표시 분리 4개(AT-APPEARANCE-04~07)를 추가해 **총 218개 설계 사례**가 된다. 실행 통과 수가 아니다. 매 변경마다 218개를 전부 실행하라는 뜻은 아니며 영향 기반 검증을 따른다. 스킬 발동 검증은 별도이며 게임 AT 수에 합산하지 않는다.
> **v1.6 운영 변경**: 당시 214개 사례의 입력·기대값·승인 의존·미실행 상태를 보존했다.

## 공통 실행 조건

청결/발병 원문 사례는 별도 명시 없으면 화장실 미설치, 직접급식 사례는 식탁 자동급식 OFF 및 공통 배고픔 조건 충족으로 시작한다. 각 사례는 새 fixture에서 시작하며 ‘앞 사례 후’라고 명시한 경우만 상태를 이어 쓴다. 나머지 계수·활동·시간은 테스트에 영향이 없도록 고정한다. 타이머 단위 테스트는 의도하지 않은 동면을 피하도록 전경 사용 조건을 유지하거나 동면과 분리된 시계를 주입한다. 실제 앱 통합 테스트에서는 정상 생명주기를 사용한다.

제안 기본값을 사용하는 테스트는 테스트용 config임을 표시한다. 수면 점수 fixture를 읽을 수 있다고 실제 Health 수면 채점이 구현된 것이 아니다. 원문에 없던 외형 임계값·상품 가격·동의 절차의 테스트 기대값은 승인 없이 만들지 않는다.

`EXP_SCALE=1,000,000`, 일반 수면 4시간, 이전 배고픔 +4/-10(운영 재검증), 섭취8회 배설물, 동면24시간 등은 모두 승인 전 제안이다. 원문의 EXP15·500걸음·0점0.7·무기록1.0 등과 구분한다.

## 판정과 증거

| 상태 | 의미 |
|---|---|
| 충족 | 승인된 기대값과 실제 실행 결과가 일치하고 근거가 있음 |
| 미충족 | 실제 결과가 기대값과 다름 |
| 결정 대기 | 기대값에 필요한 제품 결정이 아직 승인되지 않음 |
| 해당 단계 범위 밖 | 현재 단계가 맡지 않는 항목. 최종 MVP에서 자동 제외되지 않음 |
| 확인 불가 | 코드/기기/계정/환경 부족 등으로 실제 검증하지 못함 |

문서상 현재 실행 상태는 전부 ‘미실행’이며 위 QA 판정과 구분한다. 실제 실행 시 문서 버전·코드 커밋/작업 상태·OS/기기·config/engine 버전·명령·결과·증거 파일을 남긴다.

## 핵심 불변식 — 매 단계 회귀 후보

동일한 시각·상태에서 활동 기록만 추가하면 EXP와 펫 체력이 직접 변하지 않는다. 동일 명령을 여러 번 처리해도 경제 효과는 한 번이다. 같은 누적 시간을 조각내 계산해도 같은 상태가 나온다. 재고·잔액·체력은 허용 범위를 벗어나지 않는다. 약 없이 자연 회복하는 경로가 존재한다. 원본 민감 데이터는 서버·로그·분석 허용 payload에 존재하지 않는다.

이 불변식을 속성 기반 테스트로 추가할 수 있으나 도구 선택은 S단계에서 정한다. 테스트를 통과시키기 위해 원문 요구를 약화하거나 미승인 제품 규칙을 기본값으로 바꾸지 않는다.

## 최종 MVP 점검

개별 테스트뿐 아니라 SRS 14장 체크리스트를 함께 대조한다. 플랫폼 확장은 14-3의 별도 완료 기준으로 검사하고, 현재 모바일 단계에서는 범위 밖임을 명시한다. 특히 수면 산식·외형 분기·실결제·실동의·실기기·정책 승인은 순수 함수 테스트로 대신할 수 없다. 코드 검증과 제품/법률/출시 승인은 서로 다른 근거다.
