- `living/memory.ts`: 기존 로컬 DB에 `living_memory` 별도 테이블. petId + schemaVersion 1, 표시 이력 48개, 완료 32개, JSON 16 KiB 한도. 직렬 쓰기. 손상/미래 버전은 덮어쓰지 않고 접촉과 게임은 유지하며 안정된 실패 안내. 경제 ledger의 원자성과 혼동하지 않는다.
- 취향: 완료 경험 6개 이상·3계열 이상·같은 활동 3회 이상일 때 약한 선호. 30초 이내 같은 경험 연타는 누적하지 않는다. 해당 자율 후보 가중치만 2배; 최근 3계열 제외는 유지한다. 부재 차감/관계 점수/클릭 EXP 없음.
- 별도 체험 DB `arucon-life-experience.db`: 이름/성격/성장/화장실/청소 시나리오별 petId. 최초 먹이40·코인400, 기존 서비스로 공30·쿠션40·식탁60 구매. 일반 DB는 자원 지급/이름 변경/초기화 대상이 아니다. 재진입은 잔량을 유지한다. 위젯은 체험 프로필로 덮어쓰지 않는다.
- `committedLife.ts`: 전경의 확정된 짧은 상태 전이에서 배설 사건을 projection한다. revision ID로 일회 연출. 부재 정산은 대상 밖. 화면이 poopCount를 바꾸지 않으며 청소는 기존 service만 실행한다.
- 성장: 확정 식사의 실제 EXP 경계를 읽는다. 첫 단계 변화 뒤 두 앞발 응답을 표시한다. 이름·personality·기억은 같은 petId에 유지. 앨범은 완료했던 장면만 보여 주며 replay 플래그로 경제·경험·발화 이력 추가를 막는다.

## 조정값

자율 휴식 6~11초, 제안 후보 48~76초 이후 가능한 공 장면, 제안 기다림18초. 공 마찰2.4/s, 안전 바닥 x±1.8/z1.5~5.5. 수면·허기·배변 주기는 승인 config 그대로다. 가구 접근 실패/12초 초과는 연출만 취소. UI 전경 정산은 실제 시간 30초 간격, 기존 `advanceTo` 사용.

이 값은 LIFE-00에서 허용한 가역 표현 튜닝이며 실제 관찰 결과나 재미 승인이 아니다. 성능 예산은 LIFE-00 §13: RAF p95 33.34ms/submit30Hz 최소 개발 목표, 입력 proxy p95 100ms. 실제 표시 FPS/물리 터치/GPU 시간과 다르다. `phaseCost`는 JS morph/draw 호출/Expo queue drain 비용만 분리한다.

## 아트 초안

`scripts/generate-living-characters.mjs`가 보존된 원본의 geometry/normal/morph를 함께 변환한다. 아기 v3의 앞뒤 볼륨과 짧은 뿔, 낮고 넓은 말루, 비대칭 귀 모노, 위로 선 귀 피코, 둥근 귀/굴곡 몽글은 별도 GLB다. 15 clips/18 morph binding 유지. 단순 전체 축 배율·색 변경만 사용하지 않는다. 앱 기본 검토 후보는 baby_v3, 설정의 비교에는 원본과 v3 및 각 형태를 둔다. 초안 연결/자동 검사와 실제 화면 품질·최종 아트 승인은 분리한다.
