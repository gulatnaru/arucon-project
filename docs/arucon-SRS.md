## 0. 이 문서를 읽는 개발 에이전트에게

- 이 문서는 **MVP(1단계) 우선 구현**을 전제로 한다. 각 요구사항에는 `[MVP]`, `[P2]`, `[P3]`, `[PROTO]` 및 플랫폼 확장 태그가 붙는다. **모바일 `[MVP]`를 우선**하며, 플랫폼 확장은 3-6의 별도 범위와 작업 배정에 따른다.
- `[P2]`(2단계: 소셜 방문), `[P3]`(3단계: 번식)은 데이터 모델과 인터페이스만 확장 가능하게 열어두고, 실제 구현은 MVP 완료 후 착수한다.

- `[EXT-PC]`는 PC 동반 펫, `[EXT-HOME]`은 위젯의 추가 상호작용, `[EXT-WALLPAPER]`는 Android 라이브 배경화면, `[EXT-SHARED]`는 확장용 같은 펫 읽기 모델이다. 소셜 P2·번식 P3·캐릭터 2차 진화와 별개다. 이번 요구 반영은 자동으로 모든 확장을 모바일 MVP 출시 차단 항목에 추가하는 것이 아니다.
- 게임 밸런스 수치(9장)는 **하드코딩하지 말고 단일 설정 파일(config)로 분리**할 것. 추후 튜닝이 잦다.
- 불명확하거나 의사결정이 필요한 지점은 13장 및 `decisions.md`에 정리되어 있다. 임의로 결정하지 않는다. 해당 부분은 **결정 대기**로 보고하고, 의존하지 않는 확정 범위만 진행한다. TODO나 테스트용 대체 구현을 기능 완료로 간주하지 않는다.
- **완성 원화·리깅·애니메이션 파일은 별도 아트 납품 범위다.** FR-10.1/16의 시각·성격 표현 방향은 본 SRS에 포함하며, 최종 리소스가 없으면 이를 반영한 시안으로 검증한다. 시안을 최종 아트 완료로 표시하지 않는다.

### 0-4. v1.9 승인된 MVP 기본 정책 — 사용자 / 2026-09-19

1. 이미 획득한 재화는 과거 수정이나 보관함 상한으로 회수하지 않는다. 수면은 중립 이상 추가 혜택을 주는 bonus 중심이다.
2. scorer는 개인 기준과 유효 세션을 사용하며 의료 정상/비정상을 판정하지 않는다. 정확한 계수는 config/ADR로 분리하고 경계·no_data·겹침/분할 세션을 테스트한다. 실제 HealthKit/Health Connect/센서 읽기는 OFF다.
3. 외형은 설명 가능한 케어 결정표로 arucon→mallu/mono/piko/mongle를 선택한다. personality는 독립 축이며 외형별 경제 우열이 없다.
4. 기본 화장실은 시작부터 사용한다. 작은 코인 카탈로그를 제공하며 효율 상품 현금 구매는 없다. 현금 코스메틱은 비활성 catalog/interface 수준이다.
5. MVP는 한 시점 한 쓰기 기기와 명시 이전을 사용한다. 충돌은 경제 상태를 임의 합산하지 않고 보존한다. 마지막 sync/복구 한계를 설명한다.
6. 위젯은 read-only snapshot·last-updated timestamp·앱 진입만 제공한다. OS 제한을 실시간처럼 표현하지 않으며 앱 안 안내를 우선한다. 비난·죄책감 문구는 금지다.

위 여섯 묶음의 구현 세부값은 기존 철학을 바꾸지 않는 가역 config/ADR로 엔지니어가 선택할 수 있다. 실제 정책 수치/표/검증 예시는 §9-4 및 ADR-005/006/007을 따른다. 외부/민감 행위는 아래 경계를 계속 지킨다.

- 실제 지원 OS/최소버전 최종 출시 보증은 실기기 검증 후에만 한다.
- 법정대리인 동의·실제 미성년 계정 정책은 법적 검토 전 활성화하지 않는다.
- 실제 건강정보 읽기/permission prompt와 실계정/외부 프로젝트 생성은 하지 않는다.
- 실제 결제 상품/결제/스토어/TestFlight/Play/운영 배포 및 시스템 설치는 하지 않는다.
- 이미 설치된 SDK/Java/emulator/simulator를 계정 인증·관리자 설치 없이 사용할 수 있으면 read-OFF 개발 빌드/합성 실행을 검증한다.

## 1. 제품 개요

사용자가 걷기·달리기로 먹이와 코인을 마련하고, 펫이 준비된 집에서 자기 성격대로 살아가는 모습을 함께 경험하는 생활형 펫 육성 게임. 수면은 개인 게임 기준과 유효 세션의 단순 비교로 추가 성장 보너스를 준다. 실제 건강 소스 연결은 비활성이다. 핵심 가치는 **"건강한 행동으로 마련한 작은 집에서, 자꾸 보고 싶은 친구와 함께 산다"**. 사용자 건강이나 성격을 진단하는 게임이 아니다.

이름의 유래(사용자 설명): **아루**는 일본어 ‘걷다’에서, **콘**은 유니콘에서 가져왔다. 걷기·달리기·수면 같은 건강 행동을 다마고치류 펫 돌봄에 접목한다. 

### 1-1. 핵심 루프

```
걷기·달리기 → 먹이 → 직접 급식 / 식탁 자동급식 → 실제 섭취 → 성장
            → 코인 → 화장실·식탁·장난감·휴식 가구 → 새로운 생활 행동
                                   수면 기록 → 추가 성장 보너스(실제 건강 연결 OFF)
```

**"걸어서 생활을 마련하고, 자기답게 살아가는 아루콘과 함께한다"**. 반복 작업은 줄이고 관찰·교감·꾸미기의 비중을 높인다.

### 1-2. 설계 원칙 (전 기능 공통)

1. **먹이의 실제 섭취가 성장의 조건이다.** 직접 급식과 사용자가 켠 식탁 자동급식은 동일 조건에서 동일한 성장량을 준다. 직접 급식·잦은 접속을 강요하지 않는다. 부재 중에도 사전 허용·기존 재고·깨어 있음·동면 전 조건 안에서 섭취 정산이 가능하다. (DEC-19/21)
2. **벌칙이 아닌 인센티브로 유도한다.** 못 한 것에 감점하지 않고, 잘한 것에 가점한다.
3. **되돌릴 수 없는 손실은 만들지 않는다.** 사망·영구 능력치 손실·데이터 소실 없음.
4. **사용자의 실제 신체 상태를 부정적으로 판정하지 않는다.** 운동을 못 한 날에 펫이 아프거나 지치는 인과는 금지(3-4 비대상 참고).
5. **성격은 능력 우열이 아니다.** 식사·화장실은 모든 성격에 동일하게 작동한다. 행동·표정·거리·리듬으로 개성을 표현한다.
6. **교감은 부담 없이 한다.** 가벼운 쓰다듬기·인사·관찰은 체력·재화·성장 효율·관계 수치를 소모하지 않는다.
7. **시설은 반복 작업을 졸업시키는 보상이다.** 기본 시설에 내구도·고장·소모품·유지비·유료 자동화를 붙이지 않는다.
8. **자동화로 관계가 불리해지지 않는다.** 자동급식 사용·미접속 자체를 성격이나 애정 감소의 입력으로 쓰지 않는다.

9. **어디서나 같은 아이, 중복 없는 성장.** PC·위젯·배경화면의 표시와 교감은 새 펫·새 지갑을 만들지 않으며, 실행 시간·동시 기기 수·조회·애니메이션 재생으로 먹이·코인·EXP를 추가하지 않는다. 정상 모바일 자동식사의 결과를 다른 화면에 반영하는 것은 가능하다.
10. **눈에 띄기보다 곁에 머문다.** PC와 홈 화면은 업무·앱 아이콘·입력을 방해하지 않는 작은 접점이다. 숨김·저동작 모드와 데이터 시각 표시를 제공한다. 불필요한 화면·키 입력 감시는 사용하지 않는다.

### 1-3. 비회수·보너스 원칙 — DEC-13 / APPROVED

34ab069 이후 사용자 승인으로 보너스 중심 커브를 채택한다. 이미 얻은 재화·EXP를 과거 기록 수정이나 보관함 상한으로 회수하지 않는다. 무기록은 중립 1.0, 유효 점수의 향후 식사 배율은 1.0~1.25다. 과거 0.7~1.5 커브는 역사적 fixture에서만 보존한다. 인간 수면의 정상/비정상이나 권장 시간을 판정하지 않는다.

## 3. 개발 범위

### 3-1. MVP (1단계) — 최우선 구현
- 계정/온보딩 (연령 확인 포함)
- 걸음/활동 트래킹 → **먹이·코인** 획득
- **직접 급식·동의한 식탁 자동급식** → 섭취 확정 → 성장
- 펫 성장: 레벨, 스테이지, 진화, 성별 결정, 개인별 외형 분기
- 수면 → **성장 배율** + 체력 회복
- 체력 시스템
- **청결(배설물) / 기분 시스템**
- **기운 없음 상태 및 회복**
- 펫 배회·표정 등 서식 공간 표현
- 상점 (기본 화장실·식탁·생활 가구·장난감 + 기존 승인 대상 상품)
- 성격에 따른 일관된 생활 반응·무료 가벼운 교감·선택적 생활 일지
- 홈 위젯의 펫 중심 상태 스냅샷·갱신 시각·앱 진입
- 방치 시 동면 처리

### 3-2. P2 (2단계) — MVP 이후
- 친구 시스템 (친구 코드/QR)
- 방문 기능 (같은 공간 상태 공유, 함께 운동 시 성장 가속)
- 실시간 동기화 백엔드

### 3-3. P3 (3단계) — 최후
- 번식 (성별, 애정지수, 아기 아루콘 탄생)
- 심박수 기반 성장 가속 (웨어러블 연동)

### 3-4. 명시적 비대상 (Non-goals)
- 걷기가 불가능한 사용자를 위한 대체 활동 경로 (서비스 대상 아님)
- 낯선 사용자와의 랜덤 매칭 / 채팅 기능 (아동 안전상 구현하지 않음)
- 현금으로 구매하는 성장·효율 아이템 (핵심 가치 훼손)
- **사용자의 운동으로 인한 펫 체력 소모** (많이 걸을수록 벌받는 구조가 되어 핵심 가치와 정면 충돌)
- **운동 부족을 원인으로 하는 펫의 질병·부정적 상태** (실제로 몸이 아파 못 걸은 사용자에게 해로움)
- **사망 / 영구적 능력치 손실 / 비난조 문구**

### 3-5. 프로토타입과 MVP 완료의 구분

이번 사용자가 요청한 PROTO는 방 1개·동일 외형 1종·비교용 성격 2종·기본 시설과 소수 가구의 행동 검증이다. 공통 아기형 및 1차 4계열은 아트 개발 방향, 2차 성체화+16성향은 확장 목표로 유지한다. **공통형의 표시명 `아루콘`과 1차 4계열의 대명사 `말루·모노·피코·몽글`은 DEC-32로 승인되었다.** 그러나 그 명명만으로 논리 분기·진화 시점·완성 아트가 승인된 것은 아니다. 기존 Lv6/Lv16 등의 경계는 이번 요청으로 변경하지 않는다.

미정 요구사항 때문에 특정 기능을 fixture로 시연할 수는 있으나 이를 ‘MVP 완료’라고 부르지 않는다. 현금 결제·아동 동의·외형 분기 등을 미루려면 사람이 범위 변경을 승인하고 본 장과 14장을 함께 수정한다. 에이전트가 기능을 숨기거나 삭제하는 것으로 수용 기준을 통과시키지 않는다.

## 4. 시스템 아키텍처 개요

### 4-1. 권장 스택 (변경 가능, 팀 판단 우선)
- **클라이언트**: React Native (크로스플랫폼, 헬스 데이터·위젯·백그라운드 처리 위해 네이티브 모듈 사용). Flutter도 대안 가능.
- **MVP 백엔드**: 계정·데이터 동기화 최소 구성. Firebase(Auth + Firestore + Cloud Messaging) 권장 — 인증·푸시·추후 실시간 확장까지 커버. 교체 가능.
- **로컬 저장소**: 활동/성장 데이터는 로컬 우선(SQLite 등) + 서버 동기화. 오프라인에서도 걸음 집계가 끊기지 않아야 함.
- **P2 실시간**: 방문 기능용 실시간 동기화 계층은 P2에서 추가.

- **플랫폼 확장**: PC 셸·위젯·배경화면 렌더러는 표시 어댑터로 분리한다. 모바일 게임 엔진과 중복되는 경제 정산 루프를 실행하지 않는다. 상세 통신·프레임워크는 DEC-30/31 승인 대상이다.

### 4-2. 헬스 데이터 소스
- **걸음/활동 — 수정 제안 DEC-01**: iOS HealthKit, Android Health Connect를 우선 검토한다. 해당 소스를 사용할 수 없으면 기기 페도미터(CMPedometer / Android step counter sensor)를 **별도 권한과 기능 가용성이 충족되는 경우** 대체 경로로 제공한다. 웨어러블 미보유 자체를 소스 사용 불가로 단정하지 않는다. 두 경로 모두 사용할 수 없으면 측정 불가 상태를 제공한다. 원문의 ‘항상 폴백 성공’ 요구를 조건부 지원으로 바꾸는 명시적 제안이다.
- **수면**: FR-6의 결정 필요 항목 참고. **MVP는 Health API의 수면 데이터를 읽는 방식을 기본으로 권장**하고, 마이크 기반 수면 분석은 별도 단계로 분리.

### 4-3. 레이어와 실행 경계 — 보완 제안 / DEC-12

```text
화면·애니메이션·위젯
        ↓ 명령 / 읽기 모델
애플리케이션 서비스: 권한·전경 상태 확인 / 트랜잭션 / 명령 중복 방지
        ↓ 명시적 입력
순수 도메인 엔진: 성장·체력·청결·수면배율·시간 경과 계산
        ↕ 인터페이스
저장소(SQLite), 활동·수면 어댑터, 계정·동기화·결제 어댑터
```

- 도메인 엔진은 시스템 시계, 난수, 네트워크, OS API, UI 상태를 직접 읽지 않는다. `now`, `configVersion`, 활동 집계, 확정된 랜덤 결과를 입력받는다.
- 순수 엔진은 `newState + domainEvents`를 반환한다. 실제 DB 트랜잭션과 중복 요청 처리는 애플리케이션 서비스·저장소 책임이다.
- 이름은 예시이며 기술 선택은 S단계에서 제안한다. React Native / Flutter, 로컬 DB, 인증·서버 스택 및 네이티브 모듈 버전은 DEC-12 승인 전 임의 확정하지 않는다.
- **MVP 로컬-서버 동기화**와 **P2 방문용 실시간 동기화**는 다른 범위다. 후자를 구현하지 않는다는 이유로 전자를 누락하지 않는다.

### 4-5. 본게임과 표시 접점의 분리 — 방향 승인 / 상세 구조 DEC-30 제안

```text
모바일 건강 어댑터 → 모바일 게임 서비스·원장 → 동기화 계층
                              ↓                       ↓
                       본앱·로컬 위젯          허용 목록 PetProjection
                              ↓                       ↓
                    선택적 Android 배경화면       PC 동반 펫
```

- 위 화살표는 데이터 책임의 개념도이지 승인된 네트워크 토폴로지가 아니다. 서버·로컬 저장·플랫폼 공유 저장의 구체 방식은 설계 단계에서 결정한다.
- 본앱과 위젯이 같은 기기에 있어도 **표시 요청이 새로운 식사/성장 명령이 되지는 않는다**. 정상 모바일 서비스가 별도로 확정한 이벤트를 위젯에 반영하는 것은 허용한다.
- PC 로컬 애니메이션 시계·위치·크기·쓰다듬기 반응은 `PresentationSession`에서 관리한다. 운영 펫의 배고픔·체력·EXP·외형 분기·성격 점수를 재계산하지 않는다.
- 같은 펫은 같은 `petId`, 승인된 외형·성격·가구 상태를 뜻한다. 서로 다른 화면에서 픽셀 위치·포즈·프레임을 실시간으로 일치시킬 필요는 없다.
- 플랫폼별 프레임 예산·갱신 주기·허용 입력은 다르다. 위젯에 본앱의 WebGL/애니메이션 루프를 그대로 실행한다고 가정하지 않는다. 외부 근거 EXT-07~12는 `platform-sources.md`에 분리했다.

## 5. 기능 요구사항 — 계정 / 온보딩

### FR-1.1 계정 생성 `[MVP]`
- 소셜 로그인 또는 이메일 기반 가입.
- 가입 시 **생년월일 입력**으로 연령 확인 (아동 안전 요건, 12장 연동).
- **원문 수용 기준**: 만 14세 미만으로 판별되면 법정대리인 동의 플로우로 분기(FR-CS.3). 이는 원문에서 정한 기획 기준을 유지한 것이며, 적용 국가·법률·플랫폼 정책 확인을 대체하지 않는다.
- **보완 제안 DEC-11**: 동의 상태를 `not_required / pending / verified / revoked` 등으로 구분한다. 테스트용 버튼이나 로컬 boolean 변경만으로 실제 동의를 완료 처리하지 않는다. 정책 미확정 환경에서는 합성 데이터로만 흐름을 검증하고, 해당 동의가 필요한 실제 계정의 가입 완료·건강 데이터 처리 경로를 출시 차단한다.

### FR-1.2 온보딩 — 펫 부여 및 명명 `[MVP]`
- 신규 유저에게 **초기 형태 펫 1마리 지급**(성별 없음). 모든 유저의 초기 형태는 동일.
- 유저가 이름 입력 → **접미사 "콘"은 입력창에서 분리되어 자동으로 뒤에 고정 표시**. 유저는 앞부분만 입력.
- **수용 기준**: 저장 시 종족명("아루콘")과 유저 지정 이름을 데이터상 분리 저장.

#### FR-1.2 보완 — DEC-15 / PROPOSED

- 초기 상태 제안: 레벨 1, 누적 EXP 0, 스테이지 1, 성별 null, 체력 100, 배고픔 50/100, 먹이 0, 코인 0, 배설물 0, 기운 없음 false, 동면 false. 기존 문서에 없던 시작값은 승인 전이다.
- 펫 지급은 계정별 고유 키로 한 번만 수행한다. 가입 완료 재시도·재설치가 추가 펫·재화를 생성하지 않는다.
- 입력한 이름 본문은 NFC 정규화·양끝 공백 제거 후 1~12개 사용자 인지 문자(grapheme cluster)로 제한하는 안을 제안한다. 공백만·제어문자는 거부한다. 종족명과 이름 본문을 저장하고 표시용 이름은 `givenName + "콘"`으로 만든다.
- 사용자가 이름 본문에 ‘콘’을 포함했다는 이유로 임의로 잘라내지 않는다. 중복 접미사 정책을 바꾸려면 승인한다.
- 위 초기값·이름 제한은 DEC-15 승인 전에는 테스트 fixture로만 사용한다.

### FR-1.3 권한 요청 및 프라이버시 고지 `[MVP]`

## 6. 기능 요구사항 — 활동 · 먹이 · 성장 코어

### 6-0. 날짜·시간·계산 공통 계약 — 보완 제안 / DEC-02, DEC-03, DEC-07

- 시각은 UTC instant로 저장하고, 계정 생성 시 정한 IANA `gameTimezone`으로 게임 날짜를 계산한다. MVP에서는 여행·기기 시간대 변경만으로 게임 시간대를 자동 변경하지 않는 안을 제안한다. 날짜 표시에 사용할 시간대는 사용자에게 알린다.
- `gameDayId`는 날짜 문자열만이 아니라 고정 시간대와 `[startUtc, endUtc)` 경계를 가진다. 서머타임 날짜를 무조건 24시간으로 계산하지 않는다.
- 자정 리셋은 **일일 표시·집계 구간 변경**이다. 펫 EXP·먹이·코인·미처리 명령·소수 전환 진행량을 초기화하지 않는다.
- 경과 시간은 명시적으로 주입한다. 미래 시각·시계 되돌림·오프라인 시간 조작은 이상 상태로 기록하고 이미 정산된 과거를 재실행하지 않는다. 기기 시각만으로 완전한 조작 방지가 된다고 주장하지 않는다.
- `advanceTo(state, now)`는 마지막 계산 시점부터 상태 변경 경계별로 처리한다. 동면 기준을 지난 장기 부재를 끝까지 계산한 뒤 동면시키지 않는다.
- 동일 시각 처리 순서 제안: **동면 진입 경계 → 일반 수면 경계 → 조건 타이머 완료 → 시간성 배설물 생성 → 사용자 명령**. 동면이 시작되는 바로 그 시각의 다른 시간성 변화는 정지하며, 복귀 이벤트만으로 만료 전이를 소급 실행하지 않는다. 임계치와 동면 경계가 정확히 겹친 타이머는 진행량을 보존하고, 복귀 뒤 첫 양의 활성 경과에서 전이 조건을 다시 평가한다. 사용자 명령 내부 순서는 각 FR을 따른다.
- 상태값을 변경하는 매 명령 전에 시간 경과를 적용한다. 같은 명령을 재시도하면 저장된 결과를 반환하고 시간 경과나 보상을 중복 반영하지 않는다.
- 시간 함수는 한 번에 12시간 계산한 결과와 같은 경계를 여러 번 나누어 계산한 결과가 같아야 한다. 중간 반올림 누적으로 결과가 달라지지 않도록 한다.

### FR-2 걸음/활동 트래킹 `[MVP]`
- Health API 또는 페도미터로 걸음수를 집계, **자정 기준 일일 리셋**.
- 러닝/고강도 구간 식별: MVP는 GPS 페이스 또는 Health API의 운동 세션으로 판별(심박수 기반은 `[P3]`).
- **수용 기준 수정 제안 DEC-01**: 헬스 데이터를 사용할 수 없을 때, 별도 권한과 기기 기능이 허용하면 페도미터로 대체 집계한다. 대체 경로도 불가하면 측정 불가를 안내하고 보유 펫·재화를 유지한다. 측정 불가·빈 결과·실제 측정된 0은 구분한다. iOS에서는 읽기 권한 거부를 판별했다고 허위 표시하지 않는다.

#### FR-2 보완 — 데이터 계약 / DEC-01, DEC-02

`ActivitySnapshot`은 `gameDayId, interval, provider, sourceRevision, steps, runningSteps, status, observedAt`을 포함한다. `0 ≤ runningSteps ≤ steps`, 두 값은 정수다. 센서 리셋·기기 재부팅·API 오류는 정상 0과 구분한다.

- 상태: `available / empty_or_unreadable / permission_required / unavailable / error`. 플랫폼이 구분해 주지 않는 상태를 앱이 추정해 확정하지 않는다.
- MVP 러닝 판별 **제안**: 우선 Health API의 러닝 운동 세션과 겹치는 걸음만 추가 배수 대상으로 한다. 세션 구간을 합집합 처리해 겹침을 중복 계산하지 않는다. 세션별 걸음을 신뢰성 있게 나누지 못하면 실제 확인된 걸음에 기본 배수만 적용하고 분류 한계를 표시한다. GPS 방식은 원문의 대안으로 유지하되 별도 승인 없이 추가 수집하지 않는다.
- 하루 보상에 사용할 공급자는 최초 활동 정산 시 고정하는 안을 제안한다. 지급이 0개이고 나머지 진행량만 생기는 정산도 여기에 포함한다. 같은 날짜의 Health 집계와 페도미터 전체 합계를 더하지 않는다. 소스 변경은 다음 게임 날짜부터 적용하고, 당일 긴급 변경·백필은 중복이 없음을 입증하는 별도 변환 규칙 승인 전 허용하지 않는다.
- 조회 자체는 여러 소스에 할 수 있지만 보상 입력은 선택된 정규화 결과 하나다. 공급자 내부 다중 소스 집계와 앱의 공급자 간 폴백을 분리한다.
- 보상 인정 시작은 해당 계정의 활동 연결 시작 시점으로 제안한다. 그보다 이전의 이력으로 가입 즉시 재화를 발행하지 않는다. 정확한 과거 재조회 범위·보존 기간은 DEC-17에서 확정한다.

### FR-3 먹이·코인 획득 `[MVP]`
- 걸음 → **먹이**로 전환(9장 상수). 러닝 구간은 배수 적용.
- 걸음 → **코인** 동시 지급(상점용).
- **먹이 보관함 상한 존재**(9장 `FOOD_CAP`).
  - 상한 도달 시 **획득만 중단**되며, 보유 먹이가 소멸하거나 차감되지 않는다.
  - 상한 도달 시 "먹이가 가득 찼어요"를 안내하되 불필요한 과식을 유도하지 않는다. 식탁 설정·현재 재고를 확인할 수 있다.
  - **목적 개정**: 재고 규모와 활동→생활의 흐름을 관리한다. 매일 수동급식을 강요하기 위한 제한으로 쓰지 않는다. 기존 상한 20은 재검증 대상이며 자동급식 도입 후 적정 용량은 DEC-24에서 결정한다.
- **수용 기준**: 걸음이 EXP로 직접 전환되는 경로가 코드상 존재하지 않을 것.

#### FR-3 정산 보완 — DEC-02 / PROPOSED

아래는 기존 500걸음·코인·러닝 배수를 바꾸지 않고 정산 방법을 제안한 것이다.

1. 중복 제거된 `S=steps`, `R=runningSteps`에서 가중 걸음은 `S + 0.5R`. 원문 배수 1.5에서는 정수 단위 `C=2S+R`로 표현할 수 있다. 배수가 바뀌면 같은 의미의 고정소수·유리수 규격을 사용한다.
2. 일별 `processedWeightedUnits`를 보존한다. 신규 단위는 `max(0, C - processedWeightedUnits)`이며 처리 후 최고 처리값을 갱신한다. 원본 수정으로 값이 감소해도 EXP·재화를 회수하지 않고 기록만 남긴다. 다시 최고 처리값을 초과한 부분부터 신규 정산한다.
3. 먹이와 코인의 나머지 단위를 각각 이월한다. 먹이는 1,000단위, 코인은 200단위마다 1개/1코인으로 전환한다. 전환 나머지는 자정에도 유지한다. 원문 배수에 대한 단위 환산이며 새로운 보상 배수가 아니다.
4. `potentialFood=floor((carryFood+newUnits)/1000)`, `grantedFood=min(potentialFood,max(0,FOOD_CAP-foodCount))`. 초과분은 `suppressedFood`로 기록하고 **나중에 지급할 대기 먹이로 쌓지 않는다**. 한 개 미만의 나머지 진행량만 유지한다.
5. 상한은 새 먹이 지급에만 적용한다. 이미 보유한 먹이·예약 중 먹이는 사라지지 않는다. config 상한을 낮춰 기존 보유량이 상한보다 많아도 강제 차감하지 않는다.
6. 코인은 먹이 상한과 무관하게 지급한다. 잔액·먹이·전환 나머지·처리 커서·원장·동기화 outbox는 하나의 트랜잭션으로 확정한다.
7. 지연 데이터는 **실제 정산 시 보관함 빈자리**를 기준으로 지급한다. 과거 먹이주기 상태를 재구성해 지급하지 않는다. 여러 미정산 날짜는 과거부터 정렬하고 순서를 원장에 남긴다. 지연된 기록을 어떤 범위까지 인정할지는 DEC-17의 선결 조건이다.
8. 앱을 다시 열거나 같은 API 결과를 다시 읽는 것은 신규 활동이 아니다. 중복 요청과 서로 다른 요청에 실린 동일 활동 데이터 모두 중복 지급을 막아야 한다.

예시(제안 승인 후 기대값): 먹이 20개인 상태에서 신규 일반 걸음 1,000보를 정산하면 먹이 20개 유지, 초과 미지급 2개 기록, 코인 10 지급. 이후 2개를 먹이고 동일 활동을 재조회해도 먹이는 18개다. 추가 500보가 확인되면 1개가 새로 지급된다.

검증: `AT-ACT-*`, `AT-REWARD-*`. 원문은 상한 초과분의 재지급·나머지 이월·수정 데이터 정책을 정하지 않았으므로 위 정책은 승인 대상이다.

### FR-4 먹이 섭취 — 직접 급식과 자동급식 `[MVP]`

- **승인 방향 / DEC-21**: EXP 원천은 먹이 섭취다. 직접 주기와 식탁 자동급식의 비용·식사 가능 조건·계수·성장량은 같다. 손으로 주면 특유의 교감 연출을 보여주되 별도 효율·애정 보너스를 지급하지 않는다.
- 공통 조건: 깨어 있음, 동면 아님, 승인된 배고픔 기준 충족, 허용한 먹이 재고 존재, 진행 중 다른 섭취 없음. 체력 0은 그 자체로 차단 조건이 아니다. 배부름으로 거절할 때는 부담 없는 포만 안내를 한다.
- 자동급식에는 추가로 식탁 설치와 사용자 opt-in이 필요하다. 설치만으로 켜지지 않는다. 매번 식탁으로 먹이를 옮길 필요 없이 보관함의 허용 먹이를 사용한다. 소모품 구매·코인 차감·현금 결제·먹이 생성은 하지 않는다.
- 먹이 1개 EXP는 기존 `EXP_PER_FOOD × 성장배율 × 기분계수 × 컨디션계수 × 저체력계수`를 유지한다. 성격·급식 모드·유료 가구는 계수가 아니다. 식사 직전 상태를 사용한다.
- 섭취가 성공하면 먹이 1개 차감, EXP 지급, 배고픔·소화·관련 타이머·원장을 함께 저장한다. 같은 입력/commandId 재전송은 한 번만 효과를 낸다.
- 앱 종료만을 이유로 모든 성장 금지를 적용하던 v1.3 수용 기준은 **폐기**한다. 부재 중 사전 허용 자동급식만 FR-18 범위에서 정산할 수 있다. 걸음·수면·구매·교감 이벤트에서 EXP를 직접 지급하는 것은 계속 금지다.

#### FR-4 구현 계약 — DEC-03/25 APPROVED (로컬 MVP)

직접/자동 모두 같은 consumeMeal 판정과 실제 섭취 시점의 원자 저장을 사용한다. 먹이·EXP·중복 원장·outbox를 같은 transaction에서 처리하고 UI 애니메이션은 확정 이벤트만 표시한다. 마지막 한 개 경쟁·실패·재시도·부재 중 시간순서를 검사한다. 미래 정책으로 과거 EXP를 재계산하지 않는다. 정확 정밀도/순서/생활 config는 ADR-005와 §9-4에 기록한다. 실제 server 연결은 외부 계정 승인 뒤 검증한다.

검증: AT-FEED/AUTO/EXP/TXN 및 approved local service tests.

### FR-5 펫 성장 / 레벨 / 진화 `[MVP]`
- EXP 누적 → 레벨업 → 스테이지 전환 시 진화(형태 변경).
- **성별 결정**: 스테이지 2 진입 시 랜덤 배정(초기 형태엔 성별 없음). 유저 선택 불가.
- **개인별 외형 분기**: 케어 히스토리(활동 종류 비중, 수면 패턴, 꾸준함 등)에 따라 외형 분기. 단 **최종 형태는 어떤 분기든 공통 정체성**을 유지한다(구체적 형태는 별도 아트 가이드에서 정의).
- **레벨 비공개**: 타 유저에게 레벨 수치 노출 금지. 외형·의상으로만 성장 표현.
- **수용 기준**: 동일 레벨이어도 케어 히스토리가 다르면 외형 분기가 달라짐. 분기 트리는 config로 정의(13장 결정 필요).

#### FR-5 성장 경계 — DEC-03/08/24 APPROVED (1차 로컬 정책)

레벨 비용·stage·성별 단회 확정·케어 결정표를 승인 config로 분리한다. 원문 레벨 비용은 다음 레벨로 넘어갈 때의 비용으로 해석하며, 미래 config 변경으로 누적 EXP를 재계산하지 않는다. 아루콘→말루/모노/피코/몽글 분기는 설명 가능한 기록 요약과 표로 판정하고, personalityProfileId를 form의 입력/출력으로 강제하지 않는다. 동률/기록부족/재시도와 이미 확정된 결과 재사용을 검사한다. 정확 threshold/시점/표는 §9-4 및 ADR-005다. 2차 진화·P3 번식·새 아트 재디자인은 범위 밖이다.

### FR-6 수면 → 성장 배율 `[MVP]` — DEC-05/13 APPROVED

- 점수는 사용자가 정한 개인 기준과 유효 수면 세션을 설명 가능한 간단한 규칙으로 비교하는 **게임용 값**이다. 의료 정상/비정상·권장 수면시간·수면장애를 판정하지 않는다.
- 유효 세션은 중복/겹침을 제거하며 분할·낮잠을 동일 규칙으로 처리한다. 잘못된/미래/미완료 기록은 error로 구분하고 저점으로 위장하지 않는다. 날짜와 입력 범위·개인 기준은 명시적 config/input이며 보상 이전 단계에서 검증한다.
- 점수0~100 → **1.0 이상 bonus 배율**, no_data=1.0. 점수 범위·bonus상한/반올림은 §9-4/config에 분리한다. 이전0.7 커브는 과거 fixture만 재현한다.
- EXP는 실제 섭취에서만 발생한다. 수면 자체·위젯·동기화·재시도는 EXP를 지급하지 않는다. 확정 배율은 이후 성공한 섭취에만 적용하고 과거 EXP 증감은 없다.
- 유효한 펫 휴식 후 깨우기의 체력 회복은 날짜당 최대 한 번이며 반복/늦은 수면 기록으로 재지급하지 않는다. 자격·회복량은 게임 config이며 인간 수면의 기준이 아니다.

#### FR-6.1 source와 오류 경계

실제 HealthKit/Health Connect/센서 읽기와 permission prompt는 OFF다. scorer 정책은 승인되었으므로 정책 미결정과 공급자 미연결을 구분한다. 합성 입력으로 scorer/혜택을 검증하고 실제 provider는 disabled/unavailable를 명시한다. 개인 기준이 없으면 baseline_required/not_configured 입력 상태를 보여주고 임의 의료 기본값을 채우지 않는다. 마이크 분석은 추가하지 않는다.

결과는 valid/no_data/unavailable/error/not_configured를 구별한다. unavailable/error를 0점으로 바꾸거나 실데이터 검사 PASS로 표현하지 않는다. 기존 확정 혜택의 보존·날짜 변경은 service/ledger로 처리한다.

#### FR-6.2 검증

경계0/100·기준 없음·무기록·분할/겹침/중복·잘못된 날짜/길이·상한·no penalty·하루 혜택 단회·늦은 수정·앱 재시작·식사 동등성을 검사한다. 실제 플랫폼 기록 검증은 별도 민감정보 승인과 SDK/기기가 필요하며 합성 PASS로 대체하지 않는다.

### FR-7 체력(스태미나) `[MVP]`
- 최대치 존재. **수면으로만 회복**(회복량은 성장 배율에 연동) + 체력 아이템으로 보조 회복.
- **감소 원인은 아래 세 가지로 한정한다:**
  1. **시간 경과** — 깨어 있는 동안 자연 감소. 주력 소모원이며 하루 리듬(밤에 재우기)을 만든다.
  2. **적극적인 놀이** — 별도 승인된 활동성 놀이 및 `[P2]` 함께 뛰놀기. 가벼운 쓰다듬기·인사·관찰은 제외한다. PROTO의 가벼운 공놀이는 무료이며 운영 활동성 놀이의 비용은 미정이다.
  3. **소화** — 먹이 섭취 시 소량 감소. 한 번에 몰아 먹이는 것을 자연스럽게 억제.
- **🚫 사용자의 걷기·달리기는 체력을 감소시키지 않는다.** (3-4 비대상 참고 — 핵심 가치와 충돌)
- **체력 임계치 미만 시**: 성장 속도 감소(소프트 넛지). **행동을 차단하지 않는다.** 체력 0에서도 먹이를 먹을 수 있으며 성장이 느려질 뿐이다.
- **수용 기준**: 걸음수 증가가 체력을 감소시키는 코드 경로가 존재하지 않을 것.

#### FR-7.1 배고픔과 일반 수면 — 보완 제안 / DEC-04

| 항목 | 제안 동작 | 원문과의 관계 |
|---|---|---|
| 배고픔 | 0=배부름, 100=최대 배고픔, 초기 50 | 범위·초깃값 신규 |
| 증가·감소 | 기존 +4/-10은 자동급식과 함께 재검증 필요. 운영값 OPEN(DEC-24), PROTO값은 별도 파일 | v1.3 제안값은 출시 기본값이 아님 |
| 영향 | 공통 식사 가능 기준·표현 임계값은 DEC-24에서 결정. 배고픔을 추가 EXP 감소 계수·기운 없음 원인으로 사용하지 않음 | 급식 두 모드의 조건 동등 / DEC-21 |
| 일반 수면 시작 | 사용자가 ‘재우기’를 선택. 체력 0이나 건강 기록을 이유로 강제 수면시키지 않음 | 전이 조건 신규 |
| 수면 중 | 먹이 섭취·놀이 불가. 시간성 체력 감소·배고픔 증가는 정지 | 세부 동작 신규 |
| 깨우기 | 사용자가 선택. 자동 EXP 없음. 휴식 누적 4시간 이상일 때 그날 최초 회복 가능 | 게임용 휴식 조건 신규 |
| 수면 기록과 관계 | 실제 사용자의 현재 수면 여부를 단정하지 않음. Health 수면 점수는 FR-6의 별도 입력 | 상태 분리 제안 |

- `PET_SLEEP_MIN_HOURS=4`는 **펫 게임의 회복 처리 기준 제안**이지 권장 수면시간·건강 기준이 아니다. 승인 전 운영 적용하지 않는다.
- 짧은 수면을 반복해 회복을 여러 번 받지 않는다. 1개 펫 수면 세션의 동면 제외 누적 시간이 기준을 충족해야 하며, 게임 날짜당 최대 1회다.
- 일반 수면 중에도 배설물 시간 경과와 기운 없음/회복 타이머는 진행한다는 안을 제안한다. 이들은 **동면**에서만 정지한다. 실제 사용자 수면이 기운 없음의 원인인 것처럼 표현하지 않는다.
- 잠들기 전에 pending 먹이주기가 있으면 먼저 완료하거나 취소하도록 안내한다. 잠들기와 섭취를 동시에 확정하지 않는다.
- 체력은 항상 0~100 범위다. 시간·놀이·소화 각각의 변화 원인을 기록한다. 청소·활동 수집 자체는 체력을 줄이지 않는다.

검증: `AT-STAMINA-*`, `AT-HUNGER-*`, `AT-PETSLEEP-*`.

### FR-8 청결(배설물) / 기분 `[MVP]`
- 펫은 시간 경과·섭취량에 따라 서식 공간에 **배설물**을 남긴다.
- 화장실이 없을 때는 유저가 **치우기**로 제거한다. 기본 화장실 설치 후 발생분은 자동 처리하며 바닥 배설물로 쌓이지 않는다(FR-17).
- **청결도는 체력이 아니라 기분(Mood)에 연결된다.** (체력=졸림 축 / 기분=청결 축으로 분리하여 유저가 무엇을 해야 할지 혼동하지 않게 한다.)
- 방치 시: 표정이 시무룩해지고 **성장 효율이 소폭 감소**. 배설물 개수에 따라 단계적 적용.
- 치우면 즉시 기분 회복.
- **수용 기준**: 청결 방치가 체력 수치를 직접 감소시키지 않을 것.

#### FR-8 생성·청소 계약 — 보완 제안 / DEC-06

- 화장실 미설치 상태에서 무작위 ‘평균 6시간’ 대신 **동면 제외 누적 6시간마다 1개**를 생성하는 결정적 타이머를 제안한다. 일반 수면은 이 누적에 포함한다. 앱 실행 횟수로 생성량이 달라지지 않는다.
- 화장실 설치 시 아래 시간·섭취성 생성 이벤트를 자동 처리한다. 펫이 이동하지 못하거나 화면이 꺼져 있어도 바닥에 쌓이지 않는다. 성격에 따라 시설 사용을 거부시키지 않는다.
- 섭취량 영향은 **성공한 먹이 섭취 8회마다 추가 1개**를 제안한다. 취소·실패·중복 섭취 요청은 세지 않는다. 시간성 타이머와 섭취 카운터는 독립이고 청소로 초기화하지 않는다.
- 청소 1회에 현재 배설물을 전부 치우는 안을 제안한다. 청소는 체력이나 코인을 소비하지 않는다. 중복 청소 명령으로 보상이 생기지 않는다.
- 배설물 개수에서 기분을 파생한다. 저장된 mood 캐시가 있다면 count 변화와 같은 트랜잭션에서 갱신하거나 다시 계산한다.
- `oldestCreatedAt`은 표시용으로 남길 수 있으나 기운 없음 발병 타이머의 기준으로 사용하지 않는다. 임계치에 처음 도달한 시각과 누적 지속시간을 별도 저장한다.

검증: `AT-CLEAN-*`.

### FR-9 기운 없음(컨디션 저하) `[MVP]`
> 다마고치식 "질병·사망"이 아닌, **회복 가능한 일시 상태**로 구현한다. 명칭도 "질병"이 아닌 "기운 없음" 계열의 순한 표현을 사용한다.

- **발생 조건은 단 하나: 청결(배설물) 장기 방치.**
  - 배설물이 `SICK_POOP_THRESHOLD` 이상인 상태가 `SICK_TRIGGER_HOURS` 이상 지속되면 발생.
  - **배고픔·체력·운동량 등 다른 조건으로는 발생시키지 않는다.** 원인이 여러 개면 유저가 무엇을 잘못했는지 알 수 없다.
- **증상 (눈에 띄게 표현할 것)**:
  - 표정이 시무룩해짐
  - 먹이 섭취 시 EXP 획득량 감소(`SICK_GROWTH_MULT`)
  - 이동/애니메이션이 느려짐
- **회복 경로 (둘 다 제공)**:
  1. **즉시 회복**: 배설물 전부 치우기 + **약 아이템** 사용. 약은 **코인으로만 구매 가능**(현금 결제 불가).
  2. **자연 회복**: 배설물을 치운 뒤 `SICK_NATURAL_RECOVERY_HOURS` 경과 시 자동 회복. **약이 없어도 반드시 나을 수 있어야 한다.**
- **금지 사항**:
  - 사망, 영구적 능력치 손실, 되돌릴 수 없는 외형 변화
  - "돌보지 않아서 아팠어요" 등 **유저를 비난하는 문구**
  - 눈물·붕대·체온계 등 사실적인 병증 묘사 → 가볍고 코믹한 표현으로 대체
  - **사용자의 실제 활동량·건강 상태와 연결 짓는 모든 인과**
- **수용 기준**: 약 미보유 상태에서도 청결 유지만으로 100% 회복 가능할 것.

#### FR-9 상태 머신 — 보완 제안 / DEC-06, DEC-07

| 상태/조건 | 전이 | 타이머 처리 |
|---|---|---|
| 정상 + 배설물 4개 미만 | 정상 유지 | 발병 누적 시간 0 |
| 정상 + 배설물 4개 이상이 됨 | 더러움 지속 추적 | **4개가 된 시점**부터 동면 제외 시간 누적 |
| 위 상태 24시간 도달 | 기운 없음 | 다른 원인으로 진입 불가 |
| 기운 없음 + 전체 청소 | 자연 회복 중 | 회복 누적 시간 0에서 시작 |
| 회복 중 + 배설물 4개 미만 유지 | 회복 계속 | 동면 제외 12시간 충족 시 정상 |
| 회복 중 + 배설물 4개 이상 | 기운 없음 유지, 회복 중단 | 회복 누적 초기화. 다음 전체 청소로 다시 시작 |
| 기운 없음 + 배설물 0 + 약 사용 | 즉시 정상 | 약 1개 차감·상태·타이머를 원자적으로 갱신 |
| 정상 상태에서 약 사용 / 배설물 잔존 | 적용하지 않음 | 약을 소비하지 않고 조건 안내 |

- ‘청결 유지’를 **전체 청소로 회복을 시작한 후 임계치 미만 유지**로 제안한다. 계속 0개여야 한다는 해석과 구분한다. 6시간 배설 주기와 12시간 자연 회복이 양립하도록 만든 신규 세부 규칙이다.
- 회복 중 1~3개일 때 다시 청소해도 이미 누적한 회복 시간을 초기화하지 않는다.
- `dirtyThresholdSince`, `naturalRecoverySince`는 추적용 시각이며, 실제 계산에는 `dirtyElapsedMs`, `recoveryElapsedMs`처럼 동면을 제외한 누적량을 사용한다. `now-since`만 계산하면 동면 시간까지 포함되므로 금지한다.
- 동면은 병이 낫거나 발생하는 이벤트가 아니다. 들어갈 때 상태·진행량을 보존하고 나올 때 남은 시간부터 이어간다.
- 원문 문구 ‘복귀 즉시 기운 없음 방지’는 동면 이후 새롭게 진행시키지 않는다는 뜻으로 구체화하는 안이다. **동면 전에 이미 기운 없음이었던 상태를 자동 치료한다는 뜻은 아니다.** 자동 치료로 바꾸려면 별도 승인한다.

검증: `AT-CONDITION-*`, `AT-HIB-*`.

### FR-10 서식 공간 / 펫 표현 `[MVP]`
- 화면 전체가 펫이 생활하는 공간. 펫은 공간을 자유롭게 **배회**한다.
- 상태에 따라 **표정이 변한다**: 평상시 / 기쁨 / 먹는 중 / 배고픔 / 졸림 / 시무룩(청결) / 기운 없음 / 수면.
- 유저의 터치(쓰다듬기)에 반응한다. 가벼운 교감은 자원 비용이 없고, 반응 반복에 변주를 주어도 성장·관계 손실로 제재하지 않는다(FR-16).
- **아트 리소스는 별도 가이드 제공 전까지 플레이스홀더로 구현**하되, 위 상태 전환이 데이터 기반으로 동작하도록 구조를 갖출 것.

#### FR-10 표시 상태 우선순위 — 보완 제안 / DEC-04

표시 우선순위 제안: **동면 > 일반 수면 > 먹는 중 > 기운 없음 > 배고픔 > 졸림(체력 임계치 미만) > 시무룩(기분 저하) > 터치 기쁨 > 평상시**. 이것은 게임 상태들을 하나로 합치는 것이 아니라 겹칠 때 대표 표정 하나를 고르는 규칙이다. 청결·기운 없음 등은 보조 상태 표시로 함께 확인할 수 있어야 한다.

UI는 상태에서 파생된 `PetPresentationState`를 렌더링한다. 이동 속도·표정·수면·먹기 연출은 아트 어댑터로 교체 가능하게 한다. 동작 줄이기 설정·접근성 이름·상태 텍스트를 제공하는 구현안을 S단계에서 명시한다. 장식 애니메이션 종료가 단독으로 성장 확정을 수행하지 않는다.

#### FR-10.1 전체 화면 방·작은 펫·말캉한 반응 — DEC-27 승인 방향

1. 모바일 메인 콘텐츠 전체를 방으로 사용한다. 방을 관리 대시보드 안의 작은 카드로 넣지 않는다. 상단은 이름/짧은 상태/메뉴, 하단은 먹이·꾸미기·기록을 기본으로 한다. 수치표·디버그·성격 전환·가상 시간은 기본 화면에서 숨긴다. OS 안전 영역은 보존한다.
2. 펫을 작게 하면서 가구를 가장자리로 분산하고 **실제로 걸을 수 있는 바닥 범위도 확대**한다. 빈 배경만 늘리지 않는다. 펫의 크기·히트 영역은 분리해 작은 모습에서도 조작 가능하게 하고 가구·버튼 입력과 충돌하지 않도록 한다.
3. `reserved`는 반쯤 감긴 눈, 작은 일자 입, 절제된 볼/애정 표현을 유지한다. 쓰다듬기 직후 모든 성격을 같은 동그란 웃는 얼굴로 바꾸지 않는다. 짧게 만족한 눈을 감을 수 있으나 기본 인상으로 돌아온다. 시크함은 병·졸림·거부 또는 능력 열세가 아니다.
4. 접촉 때 눌림 → 옆으로 퍼짐 → 작은 반동 → 안정의 흐름을 준다. 발의 바닥 접촉, 얼굴, 배와 귀의 후행 반응을 구분한다. 몸 전체를 지속적으로 확대·축소하는 동작만으로 대체하지 않는다.
5. 걷기 시작/방향 전환/멈춤/식탁 접근/눕기 전환을 연결한다. 자율 탐색·앉기·기지개 사이에 휴식 간격을 두고 환경의 움직임은 미세하게 유지한다. 사용자가 아무것도 누르지 않아도 생동감이 있되 주의를 계속 빼앗지 않는다.
6. 움직임 줄이기에서 장식 배회·탄성·환경 움직임을 제한한다. 필요한 상태·조작 경로는 남기고 경제 결과는 동일하게 유지한다.
7. v3의 ‘약 30% 축소’와 카메라·배율·스프링 계수는 비교용 PROTO 수치다. 최종 규격은 실제 작은 휴대폰에서 표정 가독성·접촉감·성능을 확인해 승인한다. 이번 요청으로 3D 또는 Rive를 최종 제작 방식으로 확정하지 않는다.

검증: `AT-VIS-*`. 시각 수용은 자동 수치 검사와 별도로 사람이 실제 동작을 검토한다. 정지 화면만으로 말캉함·시크함·자연스러운 전환을 승인하지 않는다.


### FR-11 상점 / 꾸미기 `[MVP]`
- 기본 화장실·식탁·생활 가구·장난감으로 생활 환경을 확장한다. 초기 코인 카탈로그는 §9-4로 승인한다. 미확정 현금 코스메틱은 비활성 catalog/interface로 격리한다. 후반 코인의 주요 동기는 새 생활 행동과 취향 표현이며 가구 구입을 직접적인 EXP 보상으로 바꾸지 않는다.
- **핵심 제약**: 효율 아이템은 **코인(활동으로 번 재화)으로만 구매 가능. 현금 직구매 금지**. 현금 결제는 코스메틱에만 허용.
- **수용 기준**: 결제 경로가 아이템 카테고리에 따라 분기(효율=코인 전용).

#### FR-11 상품·경제 경계 — DEC-09 부분 APPROVED

- 원문 ‘활동으로만 획득하는 코인’을 유지한다. **현금→코인, 현금 상품에 효율 아이템 동봉, 유료 코스메틱의 성장 계수** 등 우회 경로도 금지한다.
- 약의 기존 가격 50코인은 유지한다. 체력 아이템의 회복량·가격, 성장 가속의 효과·가격·중첩, 코스메틱 판매 목록은 원문에서 미정이다.
- **이전 미승인 가속안(이번 생활 방향에서 자동 채택하지 않음)**: 다음 성공한 먹이 5회에 추가 ×1.2, 동시에 한 효과만 활성화, 실패·취소 때 횟수 미차감. 이 안을 승인하면 FR-4 기본식에 `itemMultiplier`를 **별도 여섯 번째 계수**로 추가하고 일반 상태에서는 1.0을 사용한다. 원문에 없던 계수를 조용히 끼워 넣지 않는다.
- 위 가속안과 §9-4에 없는 추가 상품은 비활성이며 초기 카탈로그에 포함하지 않는다. 보유 중첩·장착·품절·효과 적용 불가의 반환 상태와 QA 기대값을 승인 후 함께 반영한다.
- 코인 구매·아이템 수량·사용 효과·원장은 하나의 트랜잭션이다. 잔액 부족·중복 요청·실패 시 부분 차감 금지.
- 실제 현금 결제를 MVP에 포함하는지 명시적으로 승인한다. 포함 시 코스메틱 상품 ID, 구매 검증, 중복 지급 방지, 보류·취소·실패·복원·환불 후 소유권 정책을 확정하고 플랫폼 샌드박스에서 검증한다. 정상 구매 콜백만 구현한 상태를 완료로 판정하지 않는다.
- 정책 미확정 화면은 개발 환경에서만 시연하며 실제 결제/지급과 연결하지 않는다. 결제 기능을 빼고 MVP 완료로 부르려면 3장·14장의 범위 변경 승인이 필요하다.

검증: `AT-SHOP-*`.

### FR-12 홈 화면 위젯 `[MVP]` / 선택적 교감 `[EXT-HOME]`

**DEC-29 방향 반영**: iOS·Android 공통으로 ‘작은 방을 들여다보는 창구’를 제공한다. 위젯에 모든 상태 수치를 항상 펼치던 기존 표현을 펫 중심의 요약으로 개정한다.

- 기본 표시: 같은 펫의 모습, 짧은 현재 표시 상태, 스냅샷 시각 및 앱으로 들어가는 경로. 정확한 체력·배고픔·재고·성장 수치는 필요할 때 본앱에서 확인한다. 구체 크기·배치는 OS별 승인 디자인에 따른다.
- 위젯은 정해진 영역의 상태 스냅샷이다. iOS에서 홈 화면 전체 배회 또는 계속 걷는 실시간 펫을 약속하지 않는다. Android에서도 일반 위젯과 라이브 배경화면(FR-22)은 다른 구현이다.
- 조회·타임라인 갱신·위젯 미리보기는 먹이·EXP·코인·수면 회복·동면 해제·성격 재판정을 실행하지 않는다. 앱 진입도 그 자체로 신규 보상을 만들지 않는다.
- 홈에서 짧게 인사하는 기능은 `[EXT-HOME]`으로 분리한다. 지원 OS/API가 확인된 경우만 자원 중립적인 표현으로 구현하고, 미지원에서는 앱 진입으로 대체한다. 직접 급식/구매/재우기 같은 게임 상태 변경은 초기 위젯 범위에 포함하지 않는다.
- 상태 갱신에 제한이 있으므로 즉시 반영을 보장하지 않는다. 마지막 갱신 정보를 접근 가능한 텍스트로 제공하고, 오래된 상태를 실제 현재 건강/기분으로 단정하지 않는다(EXT-09/10).
- 원시 건강 데이터·위치·오디오·이메일/생년월일은 위젯 표시나 일반 진단 로그에 넣지 않는다. 잠금 화면 지원·노출 수준은 별도 승인 없이 추가하지 않는다.
- 워치 컴플리케이션은 기존 ‘가능 시’ 범위를 유지한다. 이번 요청으로 워치 앱이나 Live Activities를 필수 범위에 추가하지 않는다.

#### FR-12 스냅샷·갱신 상세 — DEC-14/30/31

`petId, stateRevision, updatedAtMs, formId, personalityProfileId, displayState`의 read-only allowlist를 사용한다. 경제/건강 원본/계정 필드는 보내지 않는다. 마지막 갱신 시각·앱 진입과 오류 상태를 표시하며 OS의 실제 갱신을 보장하지 않는다. 공유 저장/target wiring은 기술 config로 준비하고 지원 OS/최소버전의 최종 출시 선언은 실기기 검증 후로 남긴다.

새 상태 저장 후 갱신 요청은 가능하지만 요청 성공을 실제 화면 갱신 완료로 기록하지 않는다. 위젯을 여러 개 추가하거나 크기를 바꾸어도 같은 펫의 스냅샷이며 새 펫/가구/재화가 생성되지 않는다. 데이터가 아직 없거나 지원하지 않는 버전이면 ‘앱에서 확인’ 상태를 보여준다.

검증: 기존 `AT-WIDGET-*`와 새 `AT-HOME-*`. snapshot/timestamp/app 안내는 승인되었다. native 갱신/설치의 실제 결과는 별도 기기 검증한다.

### FR-13 방치 처리 `[MVP]`
- 장기 미접속 시 펫은 **"사망"이 아닌 "동면/정지" 상태**로 전환. 복귀 시 재개 가능.
- 동면 중에는 배설물 누적·기운 없음 진행이 **정지**한다(복귀 즉시 기운 없음 상태로 맞닥뜨리지 않게).
- **수용 기준**: 어떤 방치 기간에도 데이터 소실·영구 페널티 없음.

#### FR-13 동면 경계 — 보완 제안 / DEC-07

- `HIBERNATE_AFTER_HOURS=24`를 제안한다. **모바일 본앱**이 전경에서 실제 사용된 마지막 시각 이후 24시간이며, 위젯 조회·푸시 수신·활동 백필은 갱신하지 않는다. 모바일 전경 사용 중에는 동면하지 않는다. PC·홈 배경의 단순 표시/교감은 별도 DEC-30 제안에 따라 이 시간을 갱신하지 않는다.
- 앱이 백그라운드로 나간 시각을 포함해 `lastActiveAt`을 기록한다. 복귀 시 이전 값으로 부재 경과를 먼저 계산한 뒤 최신 접속 시각으로 갱신한다.
- 예: 9월 16일 08시 마지막 사용, 9월 26일 08시 복귀라면 9월 17일 08시까지만 해당 상태의 경과를 반영하고 이후 동면 구간은 멈춘다. 10일치 상태 저하를 먼저 계산하지 않는다.
- 동면 동안 체력·배고픔·배설물 생성·발병·자연 회복·펫 수면의 회복 자격 누적 시간을 모두 정지하는 안을 제안한다. 기존 먹이·코인·EXP·성별·외형 분기·진행 중 요청은 보존한다.
- 동면 중 실제 활동 데이터의 조회·먹이/코인 정산은 FR-3 범위에서 허용한다. EXP는 지급하지 않는다. 수면 혜택은 미접속 날짜마다 쌓아 복귀 때 몰아서 지급하지 않는다.
- 복귀는 남은 타이머와 이전 일반 수면 상태를 복원한다. 이전에 일반 수면이었다면 깨우기 조작은 별도로 수행한다. 동면 정지 시간을 활성 경과에 더하지 않는다.
- 이 규칙은 페널티 목적의 손실을 없애는 설계다. 기기 분실·삭제 전 서버에 전송되지 않은 데이터의 물리적 복구까지 무조건 보장한다는 뜻은 아니다(DEC-10 승인 복구 한계 안내 적용).

검증: `AT-HIB-*`, `AT-TIME-*`.

### FR-16 성격이 보이는 생활·교감 `[MVP]` — DEC-19/22 승인 방향

- 성격은 접근 거리, 반응 지연, 반복 행동, 놀이 방식, 애정 표현에 나타난다. 단순 말풍선 문구만 바꾸는 것으로 충족하지 않는다.
- 외형 `formId`, 비교적 안정적인 `personalityProfile`, 현재 필요/표현 상태, 사물별 취향·습관을 분리한다. 같은 외형에도 서로 다른 성격을 적용할 수 있다.
- 펫은 아기 때부터 작게 성향을 보이고 성장하며 표현이 풍부해진다. 2차까지 성격 표현을 전부 잠그지 않는다.
- 성격에 따라 필수 식사·화장실 사용을 거부시키거나 성장 효율·회복·보상량을 차등하지 않는다. 건강 기록·자동화 사용·접속 빈도로 사용자 MBTI를 추정하거나 펫 성격을 단정하지 않는다.
- 가벼운 쓰다듬기·인사·관찰은 체력/재화/EXP/관계 손실이 없다. 반복 반응의 변주는 가능하나 수치 벌점은 금지한다. 공놀이 등 적극적 활동의 비용은 별도 승인한다.
- 성격을 상점의 고가 가구로만 보여주지 않는다. 빈 방에서도 인사·쓰다듬기·기본 배회로 차이가 드러난다.
- PROTO는 같은 시안 기반 외형에 `expressive`(먼저 다가옴) / `reserved`(천천히 곁에 머묾) 두 fixture만 비교한다. 전환 버튼은 개발 실험용이며 실제 펫 성격 변경 상품이 아니다.
- 독자 16성향은 확장 목표다. 정식 축·판정·확정 시기·변경 가능성·모든 유형의 행동 목록은 OPEN(DEC-08/24). 공식 MBTI 검사나 건강 판정으로 표시하지 않는다.

### FR-17 생활시설·가구 `[MVP]` — DEC-20/23 승인 방향

- 기본 화장실은 시작부터 사용할 수 있다. 식탁과 작은 생활 가구 카탈로그는 활동 코인으로 구매한다. 가격·효과는 승인된 config/ADR에 분리하고 잔액/소유권/설치를 원자 처리한다. 시설 매각·제거·현금 효율 구매는 현재 제공하지 않는다.
- **화장실**: 최초 설치 시 남은 바닥 배설물을 정리하고 이후 발생분은 자동 처리한다. 장면 연출 실패·수면·성격 때문에 자동 처리가 멈추지 않는다. 내구도·모래/휴지·고장·유지비·주기적 청소 없음.
- 기존 기운 없음은 설치 즉시 치료하지 않고 기존 자연 회복 경로로 연결한다. 청결이 계속 유지되면 새 청결 원인 발병이 사라지는 것을 의도된 보상으로 인정한다. 대신 새로운 발병 원인을 추가하지 않는다.
- **식탁**: 설치+별도 자동급식 동의 후 보관함에서 허용 먹이를 사용한다. 식탁용 재고 이동/충전은 필수가 아니다. 설정은 보존하고 언제든 끌 수 있다. 예비 먹이·특수 먹이 정책은 필요할 때 별도 승인한다.
- **생활 가구/장난감**: 쿠션·공 등은 새 행동 후보를 열며 기본적인 애정이나 필수 편의를 유료 장벽으로 만들지 않는다. 가구별 행동 지점과 전용 반응을 `BehaviorCatalog`에 연결한다.
- 기본 생활 기능과 행동을 여는 장난감은 코인 카테고리다. 나중의 유료 스킨은 성능·자동화 효율·성격 점수에서 동등해야 한다.

### FR-18 부재 중 생활 정산 `[MVP]` — DEC-21 방향 승인 / DEC-25 세부 제안

- 설치·자동급식 동의·사용 가능한 기존 먹이·깨어 있음·동면 전 조건을 충족한 시간만 섭취 정산한다. 수면·동면 중 식사와 EXP 지급은 없으며 강제로 깨우지 않는다.
- 상시 OS 백그라운드 실행을 전제하지 않는다. 마지막 정산 지점부터 시간 경계별로 복원하고 일관된 원장으로 한 번만 저장한다.
- **제안 순서**: 이전 저장 상태로 부재 구간을 정산 → 새 활동/수면 기록 수신·승인된 시점 이후 적용 → 현재 명령 처리. 복귀 후 들어온 먹이를 부재 중 과거에 있었다고 소급 소비하지 않는다.
- 수면 배율·config·시설·자동급식 설정의 유효 시각을 저장한다. 과거 식사에는 당시 유효한 계수를 사용하며 늦은 수면 데이터로 과거 EXP를 변경하지 않는다.
- 자동식사·위젯·푸시·동기화는 사람의 접속이 아니므로 `lastActiveAt`을 갱신하지 않는다. 동면 경계가 다른 사건과 겹치면 동면을 먼저 적용한다.
- 정확한 동면 시간은 DEC-07/24, 타이머/예약 우선순위는 DEC-25 승인 대상이다. PROTO는 24시간 이후 정지·게임 분 단위 경계라는 검증용 단순화를 사용한다.

### FR-19 생활 일지·관찰 `[MVP]` — DEC-23 승인 방향

- 확정된 게임 이벤트로 짧은 일지를 만든다. 먹은 수량은 원장과 일치해야 한다. 실제로 실행·완료하지 않은 행동을 관찰 사실처럼 기록하지 않는다.
- 경제 이벤트와 장면 연출은 별개다. 장면 재생·일지 열기·문구 변경은 재화·EXP·성격을 재계산하지 않는다.
- 부재 중에는 정산으로 확정한 식사/자동처리/회복만 표시한다. 사용자의 실제 생활이나 인간 성격에 대한 서사를 발명하지 않는다.
- 기본 일지는 선택적으로 열람하며 보상 수령 의무·미열람 벌점·하루 체크리스트를 만들지 않는다. 운영 보존 기간·동기화 범위는 DEC-11/17 OPEN.

### FR-20 성격·생활 PROTO 검증 게이트 `[PROTO]` — 제작 범위 승인

- 방 1개, 시안 기반 임시 외형 1종, 비교 성격 2종, 식탁/화장실/공/쿠션, 직접급식, 자동급식 opt-in, 무료 터치, 합성 활동, 시간/부재 시뮬레이션, 로컬 저장, 생활 일지를 제공한다.
- 걸음은 실제 측정이 아닌 데모 버튼, 코인/먹이 초기 지급·가격·배고픔 수치는 PROTO 전용이다. 실제 헬스·결제·계정·서버·위젯·외형 진화·16성향 판정은 구현하지 않는다.
- PROTO에서는 게임 상태 변경과 시각 연출을 분리하고 동일 조건의 두 성격/급식 모드에 같은 경제 결과가 나와야 한다.
- 관찰 평가: (a) 설명 없이 성격 차이를 알아보는가, (b) 기억하는 행동이 있는가, (c) 밥/청소가 해결되어도 다시 보고 싶은가. 이번 코드 테스트만으로 사용자 검증을 통과했다고 주장하지 않는다.

### FR-21 PC 동반 펫 `[EXT-PC]` — DEC-28 방향 승인

목표는 휴대폰에서 키운 **같은 아이를 PC에서 곁에 두는 것**이다. 모바일 MVP와 별도 확장으로 관리한다.

| 모드 | 표현·조작 | 초기 경계 |
|---|---|---|
| 작은 방 | 작은 창에서 방·가구·펫을 관찰, 창 이동, 큰 보기로 전환 | 읽기 중심. 공간은 같은 가구 정보의 재구성이며 위치를 모바일과 실시간 일치시킬 의무 없음 |
| 펫만 보기 | 투명한 배경에 작은 펫, 쓰다듬기, 자리 이동, 작은 방으로 복귀 | 데스크톱 배경을 변경하거나 다른 창 내용을 읽지 않음 |

- 처음 제공할 상호작용은 관찰·무료 인사/쓰다듬기·위치 이동·모드 전환·설정·숨김/종료다. 초기 PC에서 먹이 섭취·구매·자동급식 설정 변경·재우기/깨우기·진화 확정을 직접 하지 않는다. 본격 돌봄은 모바일에서 한다.
- 투명 배경은 클릭 통과와 다른 기능이다. 투명 영역이 업무 클릭을 가로채지 않게 구현하되 펫/메뉴의 입력 영역은 보존한다. 지원하지 못하는 환경에서는 일반 작은 방 창으로 대체하고 제한을 안내한다(EXT-07/08).
- 클릭 통과 모드에서도 트레이/메뉴 또는 동등한 접근 경로로 복귀·숨김·종료할 수 있어야 한다. 드래그와 쓰다듬기 제스처를 구분하고 버튼을 창 드래그 영역 안에 갇히게 하지 않는다.
- 항상 위 표시는 선택 기능이며 자동으로 강제하지 않는다. **초기 OFF, 로그인 시 자동 실행 OFF**를 세부 제안으로 둔다(DEC-30). 업무 포커스를 강탈하거나 전체 화면 앱 위에 강제 노출하지 않는다.
- 사용자가 정한 자리·모드·크기는 PC 로컬 표시 설정이다. 여러 모니터/배율 변경 뒤 화면 밖에 남은 펫을 복귀시킬 수 있는 기능을 제공한다. 정확한 범위와 단축키는 DEC-31.
- 모드와 관계없이 `reserved`의 시크한 기본 표정과 말캉한 반응을 유지한다. ‘조용함’을 무반응으로 만들지 않는다. 축소했을 때 표정이 사라지지 않는 크기/가독성을 검증한다.
- PC 실행 시간·입력 횟수·동시에 연 창 수는 활동량으로 계산하지 않는다. PC 로컬 교감은 초기 버전에서 성격 점수·관계 수치·보상 일지의 정식 쓰기 명령으로 사용하지 않는다.
- OS·프레임워크·패키징·서명·배포 경로는 DEC-31 승인 후 구현한다. 브라우저 화면 또는 Figma 프레임을 PC 데스크톱 앱 구현 증거로 사용하지 않는다.

검증: `AT-PC-*`, `AT-CROSS-*`, `AT-VIS-*`.

### FR-22 Android 라이브 배경화면 `[EXT-WALLPAPER]` — 선택적 타당성 검증

- 앱 아이콘 뒤에 방과 펫을 보여주는 방향을 검토한다. 사용자 선택으로 설정하며 자동으로 현재 배경을 바꾸지 않는다. 다른 앱 위에 그리는 오버레이와 구분한다.
- Android 공식 배경 서비스의 생명주기·화면 가시성·터치 지원을 기준으로 검증한다. 런처가 전달하는 입력에 따라 반응 범위를 제한하며 본앱과 같은 자유 터치/드래그를 모든 환경에서 보장하지 않는다(EXT-11).
- 최초 기능은 생활 관찰과 지원 가능한 가벼운 비경제적 반응이다. 먹이주기·구매·성장 확정은 본앱으로 분리한다. 앱 아이콘 탐색/홈 페이지 스와이프를 가로채지 않는다.
- 보이지 않거나 표면이 파괴되면 장식 렌더링을 멈추고 자원을 정리한다. 다시 보일 때 승인된 최신 표시 정보를 읽고, 미리보기와 실제 배경이 동시에 존재해도 별도 게임 엔진을 만들지 않는다.
- 미리보기·배경 재설정·엔진 재생성·화면 켜짐·동시 인스턴스 수로 먹이/코인/EXP/복귀 보상을 발행하지 않는다. 배경 서비스에서 헬스 데이터를 새로 수집하지 않는다.
- 정적 화면·일반 위젯·본앱으로 돌아갈 수 있는 대안을 둔다. 이 대안은 부정적인 펫 상태나 성장 손해를 만들지 않는다.
- 지원 OS/런처/잠금 화면 여부·프레임/배터리 예산과 공개 여부는 DEC-31에서 승인한다. 타당성 검증 실패를 숨기거나 Android 전체 지원으로 표현하지 않는다.

검증: `AT-WALL-*`. 공식 API의 존재가 이 프로젝트의 구현·성능·배포 승인을 뜻하지 않는다.

### FR-23 같은 펫 공유·중복 성장 방지 `[EXT-SHARED]`

**승인 방향 / DEC-28/29**

- 추가 접점마다 새로운 펫을 지급하지 않는다. 계정과 `petId`를 유지하고, 모바일에서 확정한 외형·성격·가구를 승인된 최소 게임 정보로 공유한다. 새 스냅샷 반영은 이미 확정된 결과의 표시이지 신규 EXP 지급이 아니다.
- 초기 PC는 읽기 전용 게임 표시 권한만 갖는다. 같은 기기의 위젯/배경화면도 자체 정산자가 아니다. 표시 접점이 늘어도 한 모바일 식사가 여러 번 소비되지 않아야 한다.
- 원시 수면·GPS·오디오·원본 건강 레코드는 PC에 보내지 않는다. 표시하지 않는 걸음 집계·수면 점수·계정 개인정보까지 편의상 통째로 복제하지 않는다.
- 동기화 끊김·오래된 스냅샷은 시각과 연결 상태로 표시한다. 이를 방치·건강 저하로 해석하지 않는다. 자동 병합으로 펫 정체성이나 이미 확정한 재화를 뒤집지 않는다.
- PC·위젯·배경화면을 켜두는 것만으로 활동 기록, 보상, 성장, 휴식 회복 또는 동면 복귀를 만들지 않는다. 독립적으로 정상 처리된 모바일 자동식사 결과는 이후 스냅샷으로 표시할 수 있다.

**설계 보완 / DEC-30 PROPOSED — 별도 승인 필요**

1. 모바일의 승인된 단일 쓰기 원칙(DEC-10)을 유지한다. 범위 밖 동반 기기의 최소 권한 읽기 토큰·페어링·연결 수는 별도 확장 정책이며 현재 MVP에 추가하지 않는다. 실제 서버 검증은 UI 버튼 제거와 별개다.
2. 읽기 모델에 `accountScope, petId, stateRevision, schemaVersion, generatedAt, sourceCommittedAt, formId, personalityProfileId, displayState, furnitureIds, assetVersion`을 후보로 둔다. 실제 payload·필드 최소화·보존은 DEC-11/17/30에서 승인한다.
3. 오래된 revision·다른 petId·미지원 스키마를 조용히 덮어쓰지 않는다. 지원 불가 아트는 호환 안내/안전한 표시로 대체하고 새 진화형을 추정하지 않는다.
4. PC를 계속 켜두거나 PC에서 가볍게 만져도 모바일 `lastActiveAt`은 갱신하지 않는 안을 제안한다. 동면 정책을 회피하는 화면 유지 보상을 만들지 않는다. 구체적인 동면 시간은 DEC-07의 미정 값을 유지한다.
5. 잠듦·동면이 확정된 스냅샷에서는 먹기/활동 놀이를 재현하지 않고 휴식 상태를 표시한다. 사용자가 PC에서 표시 위치를 옮기는 것은 허용하되 본게임의 깨우기가 아니다.
6. 로그아웃/철회 확인 후 캐시·자격 증명을 정리한다. 이미 오프라인인 PC에 즉시 원격 삭제가 보장된다고 주장하지 않는다. 오프라인 캐시 만료·재인증 정책을 출시 전에 결정한다.
7. 공식 생활 일지로 동기화하지 않는 PC 로컬 연출을 모바일에서 실제 관찰한 사건처럼 기록하지 않는다. 뒤늦게 받은 과거 식사를 길게 재연해 현재 식사라고 표시하지 않는다.

검증: `AT-CROSS-*`. 새 구조는 DEC-10을 대체해 PC에 쓰기를 허용하는 예외가 아니다.

아래 값은 **승인 전 제안**이다. 승인되지 않은 값을 운영 config의 기본값으로 사용하지 않는다. `null`은 0이 아니라 미정이며, 필요한 값이 미정이면 해당 기능의 운영 활성화를 실패 처리한다.

### 9-2. 플레이테스트에서 반드시 확인할 계산

원문 수치로 직접 계산한 **시나리오**이지 의학적 권장량·실제 이용자 데이터가 아니다.

- 최저 수면×낮은 기분×기운 없음×저체력 = `0.7×0.75×0.5×0.5 = 0.13125`. 먹이 15 EXP는 약 1.96875 EXP가 된다. 하한·중복 감소 제한을 둘지는 DEC-13에서 승인한다.
- 16시간 깨어 있음 + 먹이 16개, 놀이 없음의 소모 = `16×5+16×1=96`. 1.0배의 제안 수면 회복은 78.125이므로 단순 수지 약 -17.875다. 체력 아이템 의존이 의도인지 플레이테스트한다.
- 8,000 일반 걸음에서 보관함 손실 없이 16개를 먹고 모든 계수가 1.0이면 240 EXP/일. Lv46까지 `27,750/240=115.625일`이다. 이는 강제 수동 몰아먹이기가 가능했던 가정이며 자동급식 도입 후 실제 기간 예측으로 사용하지 않는다.
- 이전 배고픔 제안 +4/시간·-10/먹이, 16시간 각성은 장기 식사량 약6.4개/일이다. 같은 총식사량 규칙으로 자동/수동을 맞추고, 목표 기간·재고·가격·소화 체력을 함께 조정한다(DEC-24).
- 먹이 상한 도달 빈도, 하루 접속·먹이주기 횟수, 약 없이 회복한 비율, 무기록 사용자와 기록 사용자의 체감 차이를 확인한다. 측정용 분석 이벤트·보존 기간은 DEC-11 승인 없이 실제 사용자에게 추가하지 않는다.

### 10-2. 동기화·복구 계약 — DEC-10 APPROVED / 법적 보존·실서비스 외부 경계

1. 로컬 상태 변경과 outbox 기록은 같은 트랜잭션에 들어간다. 서버 수신 실패가 이미 확정된 로컬 먹이주기를 중복 실행시키지 않는다. 복구·동기화로 기존에 확정된 EXP를 다시 표시하는 것은 신규 EXP 지급이 아니며, 새로운 획득 이벤트를 발행하지 않는다.
2. 서버는 `actionId`를 고유 키로 처리한다. 같은 요청 재전송은 기존 응답을 반환한다. 잔액·EXP를 클라이언트가 보낸 최종 숫자로 무조건 덮어쓰거나 단순 last-write-wins로 합치지 않는다.
3. MVP는 **계정당 쓰기 가능한 활성 모바일 기기 1대**를 사용한다. 다른 기기는 조회만 한다. `deviceEpoch`와 순번으로 작성 권한을 확인하고 활동 보상 커서도 같은 계정에 묶는다. v1.5 초기 PC는 FR-23의 읽기 접점이며 경제 쓰기 권한이 추가되지 않는다. 모바일 간 명시 전환/복구는 ADR-006의 승인 계약을 따르며 실제 서비스 연결은 별도 외부 승인 대상이다.
4. 정상 기기 전환은 기존 기기의 미전송 명령 업로드·서버 확인·쓰기 종료 후 새 기기를 활성화한다. 기존 기기가 오프라인일 때 두 기기를 동시에 쓰기 가능하게 만들지 않는다.
5. 기존 기기를 잃은 경우 서버 확인분까지만 복원하는 명시적 복구 경로를 사용한다. 아직 서버에 전송되지 않은 기록은 복원된다고 약속하지 않는다. 강제 복구에서는 새 epoch를 발급하며, 이후 돌아온 구기기의 미전송 변경은 자동 합산하지 않고 별도 보존·충돌 안내한다. 이미 오프라인인 구기기의 로컬 조작을 원격에서 즉시 멈출 수 있다고 가정하지 않는다. 서버가 유효한 epoch의 명령만 확정하는 것과 오프라인 화면의 상태를 구분한다. 이 제한이 수용되지 않으면 다중 기기·복구 구조를 DEC-10에서 다시 설계해야 한다.
6. 서버는 인증 사용자 소유권, 명령 타입·범위·순서·중복, 지원되는 config/engine 버전을 검사한다. 클라이언트 집계만 쓰는 오프라인 모델이 완전한 어뷰징 방지를 보장하지 않는다는 한계를 기록한다.
7. `synced / pending / conflict / error`와 마지막 서버 확인 시각을 표시한다. 오류를 숨기거나 로컬 기록을 임의 삭제하지 않는다. 실패 이벤트는 재시도 가능한 상태로 보존한다.
8. 승인된 config는 버전별로 보존한다. 과거 명령 재생에는 당시 버전을 사용하고 새 버전으로 보상을 재계산하지 않는다. 스키마 마이그레이션 실패 시 원본 DB를 덮어쓰거나 초기화하지 않는다.
9. 오류/retry/복구 구현은 ADR/config에 기록한다. 횟수 초과로 미확인 action을 삭제하지 않는다. 실제 보존·삭제 기간과 법적 의무는 DEC-11/17 외부 검토 대상이다.

검증: `AT-TXN-*`, `AT-SYNC-*`, `AT-DATA-*`.

## 11. 비기능 요구사항

### FR-NF.1 프라이버시 / 보안 `[MVP]`
- 수면 오디오·원시 헬스 데이터 **원본은 서버 미전송**. 기기 내 분석 후 점수/집계값만 전송.
- 헬스 데이터는 민감정보로 취급, 전송·저장 시 암호화.

#### FR-NF.1 보완 — DEC-11 / DEC-17

서버 필드 허용 목록·로컬 캐시·보존/삭제 정책·계정 삭제·동의 철회·토큰 저장·백업/동기화의 암호화 경계를 명시한다. 원본 데이터 미전송 검증에는 API payload, outbox, 디버그 로그, 분석 SDK, 크래시 첨부, 네이티브 브리지 로그를 포함한다. 점수·걸음 집계도 민감한 사용자 정보일 수 있으므로 ‘원본이 아니므로 무제한 전송 가능’으로 해석하지 않는다.

운영 로그에는 생년월일·원시 수면·오디오·GPS 좌표를 남기지 않는 안을 제안한다. 동의 증빙의 실제 보존 형태는 법률·보안 검토 후 확정한다. 테스트 데이터는 합성 자료를 사용한다.

### FR-NF.2 백그라운드 / 배터리 `[MVP]`
- **수용 기준 수정 제안 DEC-01**: 지원 OS·권한·데이터 공급 범위에서 백그라운드 수집 또는 복귀 후 재조회로 미정산 활동을 보완한다. OS가 기록·접근을 제공하지 않은 구간의 완전 복원을 약속하지 않는다. 지원 조건과 알려진 제한을 문서화한다.
- (마이크 수면 채택 시) 상시 실행에 따른 배터리·플랫폼 정책(iOS 백그라운드 오디오) 사전 검증 필요.

### FR-NF.3 어뷰징 방지 `[MVP]`
- 걸음 조작(흔들기 등)·비정상 급증, 수면 조작(백색소음 등 비현실적 완벽 패턴) 탐지용 최소 이상 감지 로직 포함.

#### FR-NF.3 보완 — DEC-16 / OPEN

기기 리셋·중복·형식 오류는 정합성 검사로 처리한다. 보통의 높은 활동량·잘 기록된 수면만으로 조작이라고 단정하지 않는다. 행동 이상 탐지의 임계값·검토 방식·보상 보류 여부는 미정이다. 미승인 임계값으로 EXP·코인 회수, 계정 제재, 사용자 비난을 구현하지 않는다.

마이크를 채택하지 않은 구성에서는 백색소음 탐지기를 만들지 않는다. 헬스 데이터 진위를 전부 판정한다고 주장하지 않는다. 실제 출시 전 탐지 범위와 오탐 처리·안내 문구를 승인한다.

### FR-NF.4 플랫폼 `[MVP]`
- 모바일 MVP는 iOS / Android 지원. 헬스 연동은 각 플랫폼 공식 API 우선. PC 동반 앱과 Android 배경화면은 3-6의 별도 확장 범위다. OS·렌더러·배포 채택 전 모든 플랫폼에서 같은 기능/성능을 보장하지 않는다.

### FR-NF.5 알림 톤 `[MVP]`
- 푸시/인앱 문구는 **유도형**으로 작성. 비난·죄책감 유발 금지.
  - 🚫 "돌보지 않아 아팠어요" / "3일째 방치되었습니다"
  - ✅ "먹이가 가득 찼어요!" / "구름콘이 기다리고 있어요"

---

#### FR-NF.5 알림 전달 조건 — 보완 제안 / DEC-14

최초 MVP는 인앱 상태 안내를 기본으로 하고, 푸시/로컬 알림은 사용자 허용 후 사용한다. ‘먹이가 가득 찼어요’는 동일 상태에서 반복 발송하지 않고 날짜·조건·알림 종류별 중복 키를 둔다. 야간 시간대·횟수 상한·예약 취소·동면 중 발송 여부는 승인된 알림 정책으로 관리한다. 문구만 만들어 놓고 발송 정책까지 완료했다고 보고하지 않는다.

검증: `AT-COPY-*`.

### FR-NF.6 방해 최소화·접점 전력·표시 개인정보 `[MVP/확장별]`

- **공통 방향**: 휴식 구간이 있는 생동감, 눈매가 읽히는 최소 표시 품질, 상태 설명과 접근 가능한 조작, 움직임 줄이기를 제공한다. 화면을 켜둬야 성장하는 구조로 최적화하지 않는다.
- **PC/배경화면 구현 요구 제안(DEC-30)**: 보이지 않을 때 장식 렌더를 정지하고 보일 때 필요한 상태만 복구한다. 무음 기본, 포커스 강탈 금지, 명시적 숨김/종료 및 일반 창 대체 경로를 검토한다. 정확한 절전 단계/기기별 예산은 DEC-31.
- 펫 자체 입력 영역 밖의 키보드·다른 앱 화면·마우스 기록을 수집해 성격이나 반응을 만드는 기능은 초기 범위 밖이다. 화면 캡처·접근성 감시·전역 키 로깅을 몰래 요구하지 않는다.
- 연결 권한·기기 해제·오프라인 만료·공용 PC 캐시를 개인정보 검토 범위에 포함한다. 제어 가능한 삭제와 제어 불가능한 오프라인 상태를 구분하여 설명한다.
- OS별 실제 장치에서 입력 통과, 드래그/교감 분리, 안전 영역, 숨김/절전, 장시간 사용, 다중 모니터/런처, 가독성을 검증한다. Figma 화면이나 정해진 프레임으로 만든 영상은 실제 성능 측정이 아니다.
- CPU/GPU·메모리·프레임 간격·배터리 측정 목표는 구현 전에 DEC-31로 승인한다. 미정 목표를 임의의 ‘60fps 보장’으로 채우지 않는다.

검증: `AT-PC-*`, `AT-WALL-*`, `AT-CROSS-*`, `AT-VIS-*`.

## 12. 아동 안전 요구사항

> **전제: 아동도 예외 없이 전 기능을 이용할 수 있어야 한다.** 연령별 기능 축소가 아니라, 기능 자체를 구조적으로 안전하게 설계해 전 연령이 동일하게 이용한다.

### FR-CS.1 안전한 소셜 구조 `[P2]`
- 방문·번식 상대는 **친구 목록으로 한정**. 낯선 사람 랜덤 매칭 없음.
- 방문 기능에 **채팅(텍스트/음성) 미탑재** — 낯선 사람과의 대화 위험 요소 자체를 제거.

### FR-CS.2 톤 `[MVP]`
- 방문·번식 연출은 로맨틱 요소 배제, 귀여운 컨셉.
- 기운 없음 상태 연출은 사실적 병증 묘사 배제(FR-9).

### FR-CS.3 법정대리인 동의 `[MVP]`
- **원문 기획 기준 유지**: 만 14세 미만 계정은 가입 시 법정대리인 동의 절차로 분기한다. 국내 서비스 전제로 작성된 기존 요구이며, 본 보완본에서 현재 법률의 적용 범위·예외·동의 방법을 검증하거나 확정한 것은 아니다.
- **⚠️ 실제 적용 전 법률 자문 필요 / DEC-11 OPEN** — 정책 미확정 시 합성 데이터로 화면 흐름과 인터페이스를 검증한다. 필요한 실제 동의 확인 없이 실사용 가입·민감 데이터 처리에 연결하지 않는다. 전 연령 동등 이용이라는 제품 목표를 임의의 연령 차단으로 바꾸지 않되, 준비되지 않은 가입 경로는 출시하지 않는다.
- 관할 지역, 동의 확인 방법, 수집 최소화, 연령 재판정, 동의 철회, 보관·삭제, 아동 결제·스토어 정책을 담당자가 검토하고 승인한다. 단순 checkbox 또는 에이전트 자가 판단을 법적 요건 충족 근거로 사용하지 않는다.

### FR-CS.4 신고·차단 `[P2]`
- 전 연령 공통 제공.

## 14. MVP 완료 정의 (Definition of Done)

아래 개정 체크리스트와 14-1의 검증 게이트를 모두 충족해야 MVP 완료로 간주한다. 체크리스트에 보완 제안이 걸려 있으면 승인된 SRS 문구를 기준으로 검사한다. 미정·미실행·범위 밖은 통과가 아니다.

- [ ] 가입·연령 확인·펫 명명(콘 접미사) 온보딩
- [ ] 걸음 트래킹 → **먹이·코인** 적립, 보관함 상한 동작. 폴백 성공·측정 불가 수용 범위는 DEC-01 승인안으로 검증
- [ ] **직접 급식·식탁 자동급식** → 공통 식사 조건·비용·EXP, 부재 중 제한 정산 및 중복 방지
- [ ] 기본 화장실 설치 후 수동 청소 불필요, 유지비/고장/소모품 없음
- [ ] 성격별 일관된 반응·무료 가벼운 교감·취향/현재 상태 분리
- [ ] 가구에 따른 생활 행동과 기록 기반 일지, 자동화 사용에 관계 손해 없음
- [ ] 레벨업·스테이지 진화·성별 랜덤 결정·개인 외형 분기
- [ ] 수면 점수 → **성장 배율**·체력 회복 반영(모든 EXP에 적용, 하한 보장, 무기록일 중립)
- [ ] 체력: 시간·승인된 적극적 놀이·소화로만 감소 / **걷기·가벼운 쓰다듬기는 감소 없음** / 저체력 자체로 행동 차단 없음
- [ ] 청결(배설물) 누적·치우기·기분 연동
- [ ] 기운 없음 발생(청결 방치 단일 조건) 및 **약 없이도 회복 가능**
- [ ] 펫 배회·표정 변화·터치 반응 (플레이스홀더 아트 허용)

- [ ] FR-10.1 전체 화면 방·넓은 이동 범위·작은 펫의 가독성·시크한 얼굴·말캉한 반응을 실제 화면/동작으로 검토. 최종 아트 승인과 PROTO 통과는 구분
- [ ] 상점(코스메틱=현금 가능 / 효율·약=코인 전용)
- [ ] iOS/Android 홈 위젯의 펫 중심 상태 스냅샷·갱신 시각·앱 진입·자원 중립성을 검증. 갱신 상세는 DEC-14/31 승인안 사용, 추가 인사/배경화면은 별도 확장
- [ ] 방치 시 동면 처리(동면 중 부정 상태 진행 정지)
- [ ] 밸런스 수치가 단일 config로 분리됨
- [ ] 헬스 원본 데이터 서버 미전송 원칙 준수
- [ ] 알림·문구에 비난조 표현 없음


### 14-1. 추가 검증 게이트 — 보완 제안

- [ ] PROPOSED/OPEN 중 해당 출시 범위에 필요한 DEC가 승인되어 SRS·config·테스트에 일치하게 반영됨
- [ ] 중복 활동·보관함 상한·분수 전환·과거 데이터 수정·자정 경계 테스트
- [ ] 먹이주기 전/중/후 앱 종료, 재시도, 트랜잭션 실패 시 먹이·EXP 정합성 테스트
- [ ] 순수 엔진의 시각·난수 주입, 구간 분할 불변성, 배고픔·수면·동면·발병·회복 복합 테스트
- [ ] 수면 점수 산식의 승인된 입력/출력 예시와 실제 플랫폼 기록 연동 테스트 (fixture 통과만으로 대체 금지)
- [ ] iOS/Android 권한 거부·철회·미지원·재부팅·강제 종료·지연 기록 실기기 테스트와 지원 한계 명시
- [ ] 오프라인 변경·중복 재전송·다중 기기 정책·서버 확인분 복구·마이그레이션 실패 테스트
- [ ] 실제 결제 포함 시 구매 검증·실패·중복·복원·환불 시나리오 테스트
- [ ] 동의·데이터 정책 승인, 원본 미전송 점검, 계정/기기 간 접근 통제 검증
- [ ] `acceptance-tests.md`에 실제 실행 환경·명령·증거·결과 기록. 미실행 테스트를 통과로 표기하지 않음
- [ ] 치명적 원칙 위반과 출시 차단 결함이 없으며 최종 머지·출시 판단은 사람이 수행

### 14-2. 단계별 QA 판정

요구사항별 판정은 `충족 / 미충족 / 결정 대기 / 해당 단계 범위 밖 / 확인 불가`를 사용한다. 단계 통과는 해당 범위의 충족을 뜻하며 전체 MVP 완료와 다르다. 합성 입력 단위 테스트 통과가 네이티브 실기기·결제·법적 동의 검증을 대신하지 않는다.

### 14-3. 플랫폼 확장 완료 게이트 — 모바일 MVP와 별도

| 범위 | 완료 판정에 필요한 근거 |
|---|---|
| PC `[EXT-PC]` | 지원 OS/스택 승인, 실제 설치·실행, 작은 방/펫만 모드, 입력 통과·복귀·숨김·무료 교감·표정, 성능 검증, 읽기 전용 강제 |
| 읽기 모델 `[EXT-SHARED]` | 연결/권한/철회 승인, 같은 petId·revision 처리, 원시 건강 정보 배제, 오래된 정보·오프라인·스키마 오류·중복 성장 방지 테스트 |
| 추가 위젯 `[EXT-HOME]` | OS/크기별 지원 입력·대체 경로, 자원 중립, 갱신 제한·접근성·소비 전력 검증 |
| Android `[EXT-WALLPAPER]` | 채택 승인, 대상 런처/기기에서 실제 설정·표면/가시성 생명주기·아이콘 조작·중복 인스턴스·전력/삭제 복원 테스트 |

PC나 배경화면이 미구현이라는 이유만으로 기존 모바일 MVP의 범위를 몰래 변경하지 않는다. 반대로 모바일·Figma·웹 시안 완료를 위 확장 완료로 표시하지 않는다. 세부 지원 정책이 미정이면 해당 범위는 **결정 대기**이며 테스트 작성은 실행 통과가 아니다.

## 부록 A. 자료 근거 및 외부 확인

### 원문 근거

사용자가 첨부한 `arucon-SRS.md` v1.2의 0~14장과 `arucon-agent-prompts.md`를 기준으로 재작성했다. 원문의 기능 ID·분류와 관련 없는 기존 값은 보존했다. 전경 전용 급식·쓰다듬기 비용 등 변경 대상은 본문에서 교체하고 DEC ID로 추적한다. 이 보완본의 새 수치·정책은 외부 자료에서 나온 ‘정답’이 아니라 명시적으로 제시한 설계 제안이다.

### 외부 기술 근거 (v1.3에 기록된 2026-09-16 확인 이력; v1.4에서 재검증하지 않음)

- **EXT-01 — Apple, Authorizing access to health data.** 읽기 허용 여부 비공개 및 빈 읽기 결과 처리 근거. https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data
- **EXT-02 — Android Developers, Use Sensor Manager to measure steps from a mobile device.** 별도 활동 권한·걸음 센서 부재 가능성 근거. https://developer.android.com/health-and-fitness/fitness/basic-app/read-step-count-data
- **EXT-03 — Android Developers, Read raw data.** 누적 데이터 aggregate 권고 및 백그라운드 읽기 추가 권한 근거. https://developer.android.com/health-and-fitness/health-connect/read-data

법률·상표·의학적 수면 점수·특정 SDK 조합의 실제 빌드 가능성은 이번 문서 작성에서 검증하지 않았다. 따라서 해당 항목을 승인 완료나 적법·정확하다고 표시하지 않는다.


### v1.4 승인 출처
사용자의 이번 대화: 성격이 드러나는 게임 방향, 화장실/식탁 제안에 이어 마지막 의견을 “개발요건에 반영”하고 “프로토타입” 제작 요청. 승인 해석 범위는 decisions.md의 DEC-19~23에 개별 기록했다. 이 문서는 실제 사용자 플레이테스트·법률 검토·의학 검증 결과가 아니다.


### v1.5 승인 출처와 검증 범위

- 사용자 시각 피드백: 공간을 더 넓게 사용, 캐릭터 축소, 모찌 같은 말캉함, 생동감 강화, 조용한 아이의 시크한 표정 복원. 해당 방향을 DEC-27로 추적한다.
- PC 바탕화면·모바일 기본화면 가능성 논의 뒤 사용자가 “위 요건도 요건정의서에 반영” 요청. DEC-28/29는 제시된 기능 역할과 단계 구분만 승인한 것으로 기록한다. 수치·스택·서버 구현 전체 승인은 아니다.
- 신규 플랫폼 기술 근거 EXT-07~12는 `platform-sources.md`에서 공식 문서 확인 내용과 제품 설계를 구분했다. 과거 EXT-01~06의 나머지 항목은 이번 작업에서 재검증하지 않았다.
- v1.4 원문 구성·기능 ID·소셜/번식 단계 및 이번 변경과 무관한 밸런스 값은 보존했다. v3 코드와 과거 QA 결과는 변경·재실행하지 않았다.
- Figma 생성/업로드 성공 여부는 `../figma/FIGMA-STATUS.md`의 이번 도구 결과로만 판단한다. 요구 문서/로컬 SVG 작성은 원격 반영 완료가 아니다.
