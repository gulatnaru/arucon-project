# 아루콘 — 성격이 보이는 생활 설계

버전 v1.5 / 작성일 2026-09-17  
근거: 이번 대화에서 승인한 방향, SRS FR-4/7/16~20, DEC-19~23. 구체적인 운영 성향 계산·아트·수치는 DEC-08/24에서 결정한다.

## 1. 제품의 중심

> 건강한 행동으로 먹이와 생활환경을 마련하고, 그 안에서 자기 성격대로 살아가는 아루콘을 알아간다.

관리 버튼의 횟수를 늘리는 것이 목표가 아니다. 화장실은 청소를 졸업시키고 식탁은 매번 급식해야 하는 의무를 줄인다. 남은 시간에는 관찰·인사·놀이·꾸미기를 제공한다. 자동화 이후 다시 접속하고 싶지 않다면 편의를 비싸게 만들지 말고 행동의 매력을 개선한다.

핵심 평가 질문은 “유형 이름을 알겠는가?”가 아니라 “우리 아이는 원래 이렇게 행동한다고 말할 수 있는가?”다. 기존 웹 시제품은 그 질문을 시험하는 도구이며 결과를 이미 입증한 제품이 아니다. PC/홈 화면 확장은 같은 질문을 새 접점에서 검증하는 후속 범위다.

## 2. 구분해야 할 네 층

| 층 | 예시 | 바뀌는 방식 | 금지하는 연결 |
|---|---|---|---|
| 외형 | 작은 뿔, 귀 방향, 말랑한 몸 | 승인한 성장/진화 경계 | 특정 외모를 특정 성격으로 강제 |
| 성격 | 먼저 접근 / 천천히 가까워짐 | 비교적 안정적. 실제 형성 방식 미정 | 걸음량·수면시간으로 사람의 MBTI 판정 |
| 현재 상태 | 배고픔, 수면, 기분, 기운 없음 | 도메인 이벤트와 시간 | 잠깐 시무룩한 것을 영구 성격으로 저장 |
| 취향·습관 | 자주 쉬는 자리, 관심 가는 장난감 | 사물별 경험, 규칙 미정 | 고가 가구 없이는 애정을 표현하지 않음 |

실제 구현의 성향 점수·기간·확정/변경 규칙은 아직 없다. 프로토타입의 성격 선택은 테스트 fixture 전환이며 육성 중의 성격 변경권이나 사용자 MBTI 입력 기능이 아니다. 프로토타입은 사물별 취향 학습도 구현하지 않는다.

## 3. 먼저 검증할 성격 두 가지

외형은 같은 임시 아루콘을 사용한다. 양쪽 모두 애정과 호기심이 있으며 표현 방식만 다르다. 능력, 먹이 필요량, EXP, 화장실 효과는 동일하다.

| 상황 | 먼저 다가오는 아이 — expressive | 천천히 곁에 오는 아이 — reserved |
|---|---|---|
| 인사 | 앞으로 통통 접근 → 반가운 표정 → 몸을 기댐 | 잠깐 관찰 → 천천히 접근 → 옆에 머묾 |
| 쓰다듬기 | 가까이 오기 → 몸 눌림 → 한 번 더 기대기 | 무심히 보기 → 몸 기울이기 → 슬쩍 붙기 |
| 공 | 공 쪽으로 튀기 → 공을 굴리기 → 따라오기 | 살피기 → 천천히 접근 → 발끝으로 건드리기 |
| 쿠션 | 바로 올라가기 → 폭 눌리기 → 편안한 얼굴 | 멀리서 보기 → 가까이 와보기 → 작게 몸 말기 |
| 식사 | 빠르게 다가가기 → 먹기 → 반가운 반응 | 잠깐 보기 → 빠른 접근 → 먹기 → 작은 만족 |
| 새 가구 | 먼저 다가가 탐색 | 거리를 두고 본 뒤 탐색 |

### 행동의 데이터 계약

`BehaviorScript`는 `steps[{pose,x,y,ms,bubble}]`와 선택적 완료 문구를 가진다. 이 중 `x/y/ms/pose`를 실제로 바꾸어야 한다. 설명문과 말풍선만 바꾸는 구현은 불충분하다.

운영 설계 제안은 `Situation + PersonalityProfile + Needs + AvailableObjects + VariantCursor → BehaviorPlan`이다. 난수나 시각은 입력으로 받으며 결과를 테스트할 수 있어야 한다. 자원 효과는 `BehaviorPlan`에서 직접 실행하지 않는다.

현재 코드의 `behaviors.js`는 성격/상황별 수작업 스크립트다. 학습 모델, 생성형 대화, 사람 성격 추론을 사용하지 않는다. 말풍선은 펫의 연출이고 실제 사용자의 감정에 대한 판단이 아니다.

## 4. 생활시설의 계약

### 화장실

첫 설치는 코인 구매와 소유권 확정의 일부로 기존 바닥 배설물을 정리한다. 이후 시간성/식사성 발생분은 자동 처리한다. 경로 찾기·연출·성격 때문에 자동 처리의 성공 여부가 달라지지 않는다.

기운 없음이 이미 있다면 자연 회복 타이머를 시작/유지하되 즉시 치료하지 않는다. 약 없이 회복할 수 있는 원칙을 유지한다. 소모품·고장·유지비·변기 청소는 추가하지 않는다. 동면 중 정지하던 타이머를 화장실이 우회하지도 않는다.

### 식탁

설치와 자동급식 동의를 분리한다. 기본 OFF. ON이면 배고픔·재고·각성·비동면 조건에서 보관함의 허용 먹이를 먹는다. 매번 별도 식탁 재고를 채우는 절차는 없다. 첫 데모에는 먹이 종류가 하나라 ON이 해당 먹이 사용 허용을 뜻한다. 실제 특수 먹이가 추가되면 종류별 허용 정책을 별도로 승인한다.

직접 급식과 공통 소비 함수를 쓴다. 직접 급식이 더 많은 EXP, 적은 소모, 유리한 성격/애정 보상을 주어서는 안 된다. 사람의 손을 따라오는 반응이 직접 급식의 가치다. 배부를 때 연속 수동 급식만 허용하는 우회도 만들지 않는다.

### 가구와 장난감

공과 쿠션은 생활 행동 후보를 추가한다. 가구 구매 자체는 EXP를 주지 않는다. 기본 인사·애정 반응은 빈 방에서도 가능해야 한다. 행동을 여는 기본 품목은 활동 코인으로 마련한다. 향후 현금 스킨은 같은 기능을 표현하는 외형일 뿐 성능 우위가 아니다.

배치·판매·철거·여러 개 소유·경로 찾기 규칙은 아직 OPEN이다. 시제품은 고정 슬롯당 한 번만 설치하고 매각·철거는 없다. 이 단순화를 운영 정책 승인으로 해석하지 않는다.

## 5. 아트 및 성장의 경계

공통 아기형은 짧은 귀·작은 뿔·단순한 덩어리로 시작하며 표시명은 **아루콘**이다. 1차 4계열의 승인 대명사는 **말루(낮고 넓은 실루엣), 모노(세로형·비대칭 귀), 피코(두 귀가 위로 선 실루엣), 몽글(둥근 귀·말린 꼬리)**이다(DEC-32). 이 이름들은 외형 계열명이며 성격을 고정하지 않는다. 특히 과거 가칭 `시크형`은 `모노`로 바꿔 성격과 혼동하지 않는다. 비교 시트의 귀 형태만 반복해 공통형과 말루가 같은 실루엣이 되지 않게 한다.

2차는 1차의 특징을 이어받아 성체화하고, 별도의 성격이 더 풍부하게 드러나는 방향이다. 4외형×16성격=64조합을 생각할 수 있지만, 64종의 개별 완성 아트를 즉시 제작하는 범위는 아니다. 지금은 하나의 외형과 두 행동 프로필이 목표다.

현재 HTML의 SVG는 모찌 같은 몸·한쪽 올린 귀·둥근 뿔을 표현한 **임시 개발 아트**다. 승인된 캐릭터 시트의 완성 원화, 네 방향 리깅, 1차 4종 혹은 최종 캐릭터 납품물이 아니다. `formId` 및 렌더러를 교체해도 성장 함수를 바꾸지 않는 구조를 지향한다.

## 6. 연출과 경제 상태의 분리

프로토타입은 식사 명령 시 엔진이 즉시 확정하고 저장한 뒤 화면에 식사 장면을 보여준다. 장면이 중단되면 이미 확정한 EXP를 취소하거나 다시 주지 않는다. `다시 보기`는 저장이나 일지를 늘리지 않는다.

운영 앱에서 먹이 예약을 두는 방식은 DEC-25가 미정이다. 앱 종료 전 예약만 되었으면 취소/재개할 수 있는지, 자동 식사와 마지막 재고를 어떻게 경쟁시키는지 결정해야 한다. 자동화가 요구되었다는 이유로 트랜잭션 설계를 생략하지 않는다.

동작 줄이기 환경에서는 짧은 정지 포즈 전환으로 바꾸지만 경제 결과는 동일하다. 잠들기·성격 전환·새 행동·창 숨기기 등으로 중단된 교감은 완료 관찰 일지로 남기지 않는다.

## 7. 생활 일지

식사·구매·자동 청결은 도메인이 확정한 사건으로 기록한다. 애정·놀이 반응은 화면 시퀀스가 끝난 경우만 관찰 기록으로 남긴다. 부재 구간은 식사/자동처리/회복처럼 계산된 사건만 기록한다. 보지 못한 귀여운 행동을 실제 관찰했다고 꾸미지 않는다.

실제 반응을 사용자에게 설명하는 짧은 문구를 사용한다. "외로웠어요", "돌보지 않아서", "관계가 나빠졌어요" 같은 접속 압박을 만들지 않는다. 일지를 읽는 것에 보상 수령·출석·성향 점수를 연결하지 않는다.

## 8. 다음 사용자 검증의 진행안 — 아직 미실행

첫 라운드에서는 성격 설명을 가리고 같은 외형에 두 프로필을 각각 보여준다. 인사·쓰다듬기·공놀이를 같은 순서로 실행한다. "누가 더 좋나"뿐 아니라 "무엇이 달랐나", "다음에는 어떤 반응을 할 것 같나"를 묻는다.

두 번째 라운드에서는 화장실과 식탁을 설치하고 자동급식을 켠 상태로 본다. 관리할 일이 없어도 다시 보고 싶은지, 새 가구를 마련할 이유가 느껴지는지, 수동 급식에 효율 손해가 있다고 오해하는지 확인한다.

관찰 항목: 성격 인지 이유, 기억에 남은 장면, 반복 반응의 지루함, UI 이해, 자동화에 대한 안도/심심함, 작고 시크한 외형의 매력. 인터뷰 인원·대상·정량 합격 기준은 별도 합의한다. 코드 자동 테스트 통과로 이 사람 대상 검증을 대신하지 않는다.


## 9. v3 시각 피드백과 플랫폼 확장

FR-10.1/DEC-27을 시각 기준으로 추가한다. 넓은 실제 이동 범위와 작은 펫을 유지하되 표정·접촉 영역까지 무작정 축소하지 않는다. `reserved`의 기본은 반쯤 감긴 눈·작은 일자 입·절제된 애정이다. 쓰다듬기 장면에서도 모든 프로필에 같은 웃는 얼굴을 적용하지 않는다.

PC에서는 사용자가 일하는 동안 조용히 곁에 머물고, 본인의 영역에 마우스가 들어왔을 때만 제한적으로 반응한다. 다른 앱 화면·전역 키 입력을 관찰하는 기능은 아니다. 눈맞춤 → 머뭇거림 → 작은 기울임처럼 기본 성격을 전달한다. 항상 뛰어다니거나 크게 출렁이는 모션으로 생동감을 대신하지 않는다.

PC·위젯·배경화면의 표현은 본게임 수치와 분리한다. 잠든 스냅샷에는 휴식 표정, 오래된 정보에는 시각/확인 경로를 제공한다. ‘표시용 반응’이 실제 성격 성장·식사·건강 진단·보상 일지가 되지 않는다. 플랫폼별 상세는 [다중 접점 설계](cross-device-design.md) 및 SRS FR-12/21~23을 따른다.
