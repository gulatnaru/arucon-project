## 실행 명령

묶음 루트 기준:

```sh
python validation/check_workflow.py --baseline /mnt/data/_arucon_baselines/arucon-v1.5 --prototype /mnt/data/_arucon_baselines/arucon-room-v3
python -m unittest discover -s validation -p 'test_workflow_validator.py' -v
```

위 `/mnt/data/_arucon_baselines/...`는 이번 검사 환경의 읽기 전용 기준 복사본 경로다. 사용자는 자기 기준 경로로 지정하거나 두 선택 인수를 생략한다. 기본 실행은 묶음 자체의 38개 계약 검사이며 두 인수가 있으면 기준 원본·제품·AT·실행 명령 파일의 4개 대조가 추가된다. Python/PyYAML 전제는 requirements.txt에 있다. 이 검사기는 게임·Codex·Figma를 호출하지 않는다.

## 보존과 정리

SRS의 **제품 장 1부터 문서 끝까지**를 v1.5와 바이트 단위 대조했다. 제품 내용·원래 0~14장 명칭·밸런스·DEC 승인 상태를 유지했다. 변경은 metadata와 0-3 개발 운영 절이다. 기존 AT 214개 행은 입력/기대값까지 그대로다.

v1.5 기준 묶음 전체 파일의 해시를 검사해 원본이 변경되지 않았음을 확인했다. 별도 첨부 SRS도 기준 ZIP 내용과 일치했다. 제공 변경은 새 `arucon-v1.6` 디렉터리에만 작성했다.

루트 AGENTS는 **45줄 / 4,879 UTF-8 바이트**다. 루트+docs 지침 합계는 기존 11,649바이트에서 5,747바이트로 정리했다. 이는 파일 크기 비교이지 토큰·비용 절감 측정이 아니다. 문서 폴더에 들어가지 않는 작업에서는 해당 보충 AGENTS의 자동 로딩 여부가 실행 도구 규칙에 따른다.

세 TOML의 필수 필드·역할 이름·read-only/workspace-write 구분과 세 스킬의 frontmatter·YAML·짧은 설명·Figma explicit-only 설정을 검사했다. 모델 ID는 고정하지 않았다. 로컬 문서 링크·기존 단계 ID·외부 v3 명령 전제 파일의 존재를 확인했다.

## 회귀 테스트가 검사한 것

정상 묶음 통과, 제품 본문 무단 수정 감지, AT 행 수정 감지, 검토자 쓰기 확대 감지, Figma 자동 호출 활성화 감지, 네트워크 허용 변경 감지, 깨진 로컬 링크 감지를 임시 복사본에서 시험했다. 이는 **설정 계약을 검사하는 코드**의 테스트이며 실제 운영 권한을 강제하는 보안 장치가 아니다.

## 한계

실제 사용자 전역 AGENTS, 조직 정책, Codex 버전, 현재 모델 목록·비용, 실제 스킬 발동률과 에이전트 간 협업은 확인하지 않았다. 향후 SDK 문법 변경·환경 차이를 이 정적 검사로 모두 검출할 수 없다. 서브에이전트에게 쓰기 도구가 실제 노출되지 않는지는 실행 호스트에서 별도 확인한다.

기존 게임 단위/브라우저 검사와 Figma 실패 기록은 `references/` 및 기존 status 문서의 과거 자료다. 그 결과를 이번 새 기능 구현·원격 반영의 성공으로 재사용하지 않는다. 게임 규칙·UI·모션 코드를 수정하지 않았으므로 여기서 전체 게임 테스트를 반복하지 않았다.
