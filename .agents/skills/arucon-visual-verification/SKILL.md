# 시각·성격 표현 검증

## 완료 조건
같은 viewport와 식별 가능한 코드 상태에서 실제 변경 전후 캡처를 확보한다. 모션 변경은 관련 동작의 전·중·후 영상을 확보한다. 반쯤 감긴 눈·작은 일자 입의 reserved와 expressive의 차이, 넓은 이동 영역, 작은 UI, 말캉함의 안정, 동작 줄이기를 변경 범위에 맞게 확인한다.

기능 테스트 성공, 시각 검토, 사용자 아트 승인을 구분한다. 캡처·영상이 없거나 볼 수 없으면 시각 검증 확인 불가다. 설정값 존재만으로 자연스러움을 통과시키지 않는다.

## 기본 절차
1. SRS FR-10.1/16과 이번 피드백·현재 원화/실행판을 확인한다. 스타일을 새로 선택하는 작업으로 확대하지 않는다.
2. `docs/validation-policy.md`, `validation/commands.json`에서 필요한 화면/모션 검사를 고른다. 실제 실행과 합성 데이터만 사용한다.
3. 레이아웃은 잘림·가림·히트 영역, 모션은 바닥 접촉·접근/회전·귀 지연·눌림/복원을 관찰한다. 바뀐 구간만 충분히 비교한다.
4. 필요한 자료 생성은 쓰기가 허용된 실행자가 담당하고 읽기 검토자는 증거를 대조한다. 총괄에게 파일·구간·문제·미확인을 반환한다.

## 보호 경계
미리 만든 홍보 영상/정지 시안을 코드 실행 증거로 대체하지 않는다. 출력 영상 fps를 실기기 FPS로 보고하지 않는다. 먹이·코인·EXP·건강 규칙과 회사 계정은 변경하지 않는다. 사용자 승인을 대신하지 않는다.
